# MCHive 界面设计系统规范 v1.0

> 面向「长文档阅读」场景的设计规范。延续现有的 Liquid Glass（通透液态玻璃）视觉语言，
> 重点解决阅读体验的量化缺陷。
>
> 状态：**规范草案（待评审）** · 编写：UI Designer · 依据：仓库真实代码与实测数据

---

## 0. 这份规范解决什么

MCHive 是资料站，读者来这里是为了**把一篇 8000+ 字的教程读完、照着做完**。
所以「界面好看」是次要目标，「读得下去、找得到、不串行」才是核心指标。

规范建立在一次真实审计之上，不是凭空写的。审计结论（数据可复现）：

| 发现 | 实测值 | 判定 |
|---|---|---|
| 浅色 `text-muted` 用于 13px 正文 | **2.81:1** | ✗ 违反 WCAG AA（需 4.5:1） |
| 浅色 `accent` 用作链接/TOC 激活文字 | **2.36:1** | ✗ 违反 WCAG AA |
| 浅色 `success` / `warning` 用作文字 | **3.51:1 / 2.40:1** | ✗ 违反 WCAG AA |
| 浅色 `danger` 用作文字 | 4.50:1 | ⚠ 压线，零余量 |
| 正文字号在全站散落 13 / 14 / 15px | 20+ 处硬编码 | 缺乏阶梯，认知不一致 |
| 桌面正文 14px、移动正文 15px | 反向 | ✗ 桌面应不小于移动 |
| 正文行宽上限 820px @14px | 每行约 58 汉字 | ✗ 超出舒适区（28–38 汉字） |
| 目录仅高亮当前位置，无进度 | — | 长文缺乏「还剩多少」预期 |
| 单篇最长教程 13,744 字 / 平均 8,665 字 | 26 篇教程 | 长文场景确凿，阅读优化收益高 |

> 复现命令：`node .workbuddy/verify/contrast-audit.mjs`（原始配色）、
> `node .workbuddy/verify/check-design-system.mjs`（交付物一致性 + 修正后对比度）

## 1. 设计原则

### 1.1 阅读优先（Reading First）
正文的每一个数值——字号、行高、行宽、段距、对比度——都由「中文长文可读性」反推，
不由「视觉美观」正推。装饰元素（玻璃拟态、渐变、光晕）**永远让位于文字可读性**。

### 1.2 系统性而非补丁式（Systematic, not Patched）
所有颜色、字号、间距、圆角、动效时长**必须来自 token**。
禁止在组件样式里硬编码色值或字号——历史事故已证明这会导致浅色模式对比度崩溃
（`pre.code-block` 曾硬编码 `#d1fae5`，浅色下对比度仅 1.13:1）。

### 1.3 三主题同步（Tri-theme Parity）
每个 token 必须在**三处**同步定义，缺一即为缺陷：

1. `:root`（浅色，默认）
2. `[data-theme='dark']`（深色）
3. `@media (prefers-color-scheme: dark) { :root[data-theme='system'] }`（跟随系统的深色）

### 1.4 无障碍是底座（A11y as Foundation）
正文对比度 ≥ 4.5:1、大字号 ≥ 3:1、可交互元素触达区 ≥ 44px、键盘可达、
尊重 `prefers-reduced-motion`。这些在 token 层就保证，不靠事后补救。

### 1.5 诚实表达状态（Honest Feedback）
读者永远知道：我在哪（面包屑）、这文章多长（阅读进度）、下一步去哪（上下篇）。
不留「不知道自己读到哪儿了」的状态。

## 2. 设计 Token

完整可执行实现见 [`tokens.css`](./tokens.css)，预览见 [`preview.html`](./preview.html)。

### 2.1 颜色

#### 语义色（修复后）

| Token | 浅色 | 深色 | 用途 | 浅色对比度 |
|---|---|---|---|---|
| `--text-primary` | `#1a2332` | `#f0f2f5` | 标题、强调 | 14.71:1 ✓ |
| `--text-secondary` | `#4a5568` | `#a8b3c4` | 正文 | 7.01:1 ✓ |
| `--text-muted` | **`#667085`** ← 修正 | `#7d8b9e` ← 微调 | 辅助说明 | **4.64:1 ✓** |
| `--accent-strong` | `#047857` | `#4ade80` | 正文内链接 | 5.11:1 ✓ |
| `--accent` | `#10b981` | `#6ee7b7` | 装饰/图标（**不用于正文文字**） | 2.36:1 仅装饰 |

**关键修正**：

- `--text-muted` 浅色由 `#8896a6`（2.81:1）改为 `#667085`（**4.64:1**），
  这样 13px 辅助文字也合规。深色改为 `#7d8b9e`（**5.57:1**），保证卡片底上同样达标。
  （注：`#6b7280` 虽也达标但对卡片底仅 4.83:1、余量偏小，故选 `#667085` 留出安全空间。）
- `--accent` 定位收窄为**装饰色**（图标、指示条、进度条、边框高亮）。
  任何**文字**若要绿色，一律用 `--accent-strong`（浅 5.11:1 / 深 11.43:1 双达标）。

#### 状态色

| Token | 浅色 | 深色 | 用途 | 浅色对底 |
|---|---|---|---|---|
| `--success` | `#047857` | `#34d399` | 成功提示 | 5.11:1 ✓ |
| `--warning` | `#b45309` | `#fbbf24` | 警告提示 | 4.68:1 ✓ |
| `--danger` | `#b91c1c` | `#f87171` | 危险/破坏性操作 | 6.03:1 ✓ |
| `--info` | `#2563eb` | `#60a5fa` | 中性信息 | 4.82:1 ✓ |

> 状态色用于**文字**时同样需要 ≥4.5:1。上表深浅两列均已核对达标
> （浅色 warning 由 `#d97706` 2.4:1 → `#b45309` 4.68:1；
> success 由 `#10b981` 2.36:1 → `#047857` 5.11:1；
> danger 由 `#dc2626` 4.50:1 压线 → `#b91c1c` 6.03:1 留余量）。

### 2.2 排版阶梯

统一为 **1.25 模数比**（Major Third），且**桌面不小于移动**：

| Token | 字号 / 行高 | 用途 |
|---|---|---|
| `--fs-caption` | 12px / 1.6 | 元信息、标签、面包屑 |
| `--fs-small` | 13px / 1.65 | 辅助说明、卡片描述 |
| `--fs-body` | **15px / 1.75** | 正文（桌面与移动一致） |
| `--fs-body-lg` | 16px / 1.8 | 长文正文（≥3000 字教程） |
| `--fs-h4` | 17px / 1.45 | 四级标题 |
| `--fs-h3` | 20px / 1.4 | 三级标题 |
| `--fs-h2` | 25px / 1.35 | 二级标题 |
| `--fs-h1` | 31px / 1.25 | 一级标题 |

**变更要点**：正文由 14px 提到 **15px**，行高由 1.85 收到 **1.75**。
14px/1.85 的问题是「字小却行距松」，阅读节奏散；15px/1.75 在同样行宽下
既放大字号又收紧行距，密度更稳。

字重仅用四档：`400`（正文）、`500`（界面）、`600`（强调）、`700`（标题）。

### 2.3 间距系统（8 点栅格）

基础单位为 **4px**，主序列为 8 的倍数：

`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96`

阅读场景的语义化间距：

| Token | 值 | 用途 |
|---|---|---|
| `--space-paragraph` | 16px | 段落之间 |
| `--space-heading-before` | 40px | 标题上方留白（2 倍段距，形成分组） |
| `--space-heading-after` | 12px | 标题下方留白（0.75 倍段距，与下文紧跟） |
| `--space-block` | 24px | 代码块/表格/引用上下留白 |

**标题-段落「前松后紧」** 是中文长文分节的关键：让标题明显归属其下方内容。

### 2.4 圆角 / 阴影 / 动效

| Token | 值 | 说明 |
|---|---|---|
| `--radius-sm` | 10px | 按钮、输入框、代码块 |
| `--radius` | 14px | 卡片、面板 |
| `--radius-lg` | 20px | 对话框、大型容器 |
| `--radius-full` | 9999px | 胶囊标签 |

动效时长三档：`--dur-fast: 150ms`（悬停/焦点）、`--dur-base: 250ms`（展开/切换）、
`--dur-slow: 400ms`（页面转场、主题切换 560ms 除外）。
缓动：`--ease-standard`（通用）、`--ease-spring`（回弹，用于入场）。

## 3. 阅读体验专项（本次核心）

### 3.1 行宽（Measure）

中文阅读的舒适行宽是 **28–38 个汉字**。换算到 15px 字号：

```
理想行宽 = 38 汉字 × 15px ≈ 570px（上限）
推荐区间 = 30–35 汉字 → 450–525px
```

**结论：正文容器宽度上限由 820px 收紧到 42rem（≈ 672px @16px 根字号），
在 15px 下约 44 汉字/行**——比单纯的 570px 略宽，是为**含中英混排、代码标识符**
的技术文档留的余量（英文单词不能被过度挤压）。这是「中文纯文本」与「中英技术文档」
的折中，也是本次规范明确的取舍依据。

| 场景 | 正文宽度上限 |
|---|---|
| 教程正文（`GuideDetail`） | `min(100%, 42rem)` |
| 插件文档正文（`PluginDetail`） | `min(100%, 46rem)`（表格/配置项较多，略宽） |
| 首页/列表页描述性文字 | `min(100%, 38rem)` |

### 3.2 字号与行高的联动

| 正文长度 | 字号 | 行高 | 理由 |
|---|---|---|---|
| < 3000 字（多数插件文档） | 15px | 1.75 | 标准密度 |
| ≥ 3000 字（教程） | 16px | 1.8 | 长文放宽，降低疲劳 |

实现方式：在正文容器加 `data-reading-length="long"`，或用 `:has()` 按内容量判断。
不建议用 JS 测量后切换（会闪烁）——由页面类型决定即可（`GuideDetail` 一律 long）。

### 3.3 段落节奏

现状 `margin: .85em 0`（约 12px）+ 行高 1.85 的问题是**段距小于行距的视觉重量**，
段落边界不清晰。规范：

```css
.markdown-body p { margin: 0 0 var(--space-paragraph); }      /* 16px，单向 */
.markdown-body > * + h2 { margin-top: var(--space-heading-before); }
.markdown-body h2 { margin-bottom: var(--space-heading-after); }
```

用**单向 margin**（只留 bottom）避免相邻 margin 折叠带来的不可预测间距。

### 3.4 目录与阅读进度

现状：右侧 TOC 只高亮当前标题。规范新增**阅读进度条**：

- 位置：正文与 TOC 之间，或 TOC 卡片顶部一条 2px 细线
- 语义：`已读高度 / 正文总高度`，用 `--accent` 填充（装饰色，非文字，2.36:1 无妨）
- 辅助：TOC 每一项左侧的状态点由「当前」扩展为「当前 / 已读 / 未读」三态
  - 已读：`--text-muted` 圆点（视觉后退）
  - 当前：`--accent` 竖条 + `--accent-strong` 文字
  - 未读：空心圆点

这样读者能一眼看到「读到 3/8 节，还剩 5 节」，长文焦虑显著降低。

### 3.5 代码块与表格

| 元素 | 规格 |
|---|---|
| 代码块字号 | 13px（正文 15px 的 0.87 倍，monospace 视觉偏大需略缩） |
| 代码块行高 | 1.7 |
| 代码块内边距 | 16px |
| 代码块最大宽度 | 不撑破容器，超宽横向滚动，且滚动条常显（避免「以为没内容」） |
| 表格 | 首列不换行、其余列可换行；表头 sticky（长表格滚动时保持列语义） |
| 行内码 | 14px（0.93 倍），padding 2px 6px，用 `--accent-strong` 着色 |

### 3.6 阅读辅助元素

- **锚点链接**：标题 hover 时右侧浮出 `#` 图标，点击复制该节链接（现状缺失）
- **回到顶部**：正文滚动超过 2 屏后右下角浮出，`--glass-bg` + 模糊，40px 圆形
- **阅读时间预估**：文章头部显示「约 N 分钟」（按 350 字/分钟中文速度），
  给读者明确的心理预期。13,744 字 → 「约 40 分钟」比「很长」更友好
- **上一篇/下一篇**：沿用现有 `guide-sequence`，规格统一（见 4.4）

## 4. 组件规格

### 4.1 按钮

| 变体 | 背景 | 文字 | 边框 | 用途 |
|---|---|---|---|---|
| Primary | `linear-gradient(135deg, accent, accent-hover)` | `--button-text` | 同色 | 主操作 |
| Secondary | `--glass-bg` | `--text-secondary` | `--glass-border` | 次操作 |
| Ghost | transparent | `--text-secondary` | none | 弱操作 |

尺寸：`sm` 32px 高 / `md` 40px 高 / `lg` 48px 高。
**移动端触达区最小 44×44px**（可用透明 padding 扩展，不改视觉尺寸）。
状态：default / hover（上移 1px）/ active（缩放 0.97）/ disabled（不透明度 0.5）/
focus-visible（2px `--accent` outline，offset 2px）。

### 4.2 链接

- 正文内链接：`--accent-strong`，`text-decoration: underline` + `text-underline-offset: 3px`
  （**必须保留下划线**——仅靠颜色区分链接对色觉障碍用户不可用）
- 悬停：`--accent-hover`，下划线加粗
- 导航链接：无下划线，靠背景/指示条区分

### 4.3 卡片（玻璃容器）

```css
.glass-card {
  background: var(--glass-bg);
  backdrop-filter: blur(var(--blur-amount)) saturate(180%);
  border: 1px solid var(--glass-border);
  border-radius: var(--radius);
  box-shadow: var(--shadow), inset 0 1px 0 var(--glass-highlight);
}
```

**性能约束**：`backdrop-filter` 是昂贵的合成操作。同屏同时存在的玻璃卡片
**不超过 8 个**（首页分类卡 + 列表项容易超）。超出时列表项改用纯色
`--surface`，只在顶层容器保留玻璃效果。
另外 `@supports not (backdrop-filter: blur(1px))` 需有纯色降级。

### 4.4 导航序列卡（上/下篇）

| 属性 | 规格 |
|---|---|
| 布局 | 双列网格；移动端单列 |
| 最小高度 | 68px |
| 内容 | 上：小字「上一步」+ 粗体标题；下：右对齐 |
| 边界 | 首篇无「上一篇」、末篇无「下一篇」时占位保持网格对称 |

### 4.5 标签 / 徽章

胶囊形（`--radius-full`），12px 字号，`padding: 3px 10px`。
颜色语义：分类标签用 `--accent-dim` 底 + `--accent-strong` 字（双主题达标）；
状态徽章（如「已汉化」）用对应状态色的 `-dim` 底 + 深色字。

### 4.6 提示框（Callout）

长文里必要的提示/警告块：

| 类型 | 左边框 | 背景 | 图标 |
|---|---|---|---|
| 提示 info | `--info` | `--info` 6% | 💡 |
| 警告 warning | `--warning` | `--warning` 6% | ⚠️ |
| 危险 danger | `--danger` | `--danger` 6% | ⛔ |

统一 `border-left: 3px solid`，`border-radius: 0 radius-sm radius-sm 0`，
正文色用 `--text-secondary`（不用状态色当正文色，保证对比度）。

## 5. 无障碍基线

| 项目 | 标准 | 当前状态 |
|---|---|---|
| 正文对比度 | ≥ 4.5:1 | 修正后达标（见 §2.1） |
| 大字号对比度 | ≥ 3:1 | ✓ |
| 键盘导航 | 全功能可达 | 需补：TOC 项、卡片点击用 `<a>`/`<button>` 而非 div |
| 焦点可见 | 2px outline + 2px offset | ✓ 已实现 |
| 触达区 | ≥ 44×44px（移动） | 需补：移动端 TOC、标签 |
| 减少动效 | 尊重 `prefers-reduced-motion` | ✓ 已实现 |
| 文本缩放 200% | 不破版 | 需验：固定 px 容器在 200% 下溢出 |
| 语义化 | 正确标签层级、landmark | 需补：文章应用 `<article>` + 标题层级不跳级 |

**键盘可达性问题（实测发现）**：`GuideDetail` 的 `related-item`、
`Sidebar` 的 `plugin-item` 用 `<div @click>` 实现，**无法 Tab 聚焦**。
应改为 `<RouterLink>` 或加 `tabindex="0" role="button" @keydown.enter`。

## 6. 响应式断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| Mobile | < 640px | 单列；侧栏收起；TOC 折到正文上方（现状已有） |
| Tablet | 640–1023px | 两列（侧栏 + 正文），TOC 上移 |
| Desktop | 1024–1279px | 三列（侧栏 + 正文 + TOC） |
| Wide | ≥ 1280px | 三列 + 更宽留白，正文宽度**封顶**（不随屏幕无限增长） |

**关键规则**：正文宽度**永远封顶**。宽屏的价值是留白与更大侧栏，
不是更长的行。这是阅读类站点最常见的错误。

## 7. 落地优先级

按「读者可感知收益 / 改动成本」排序：

| 优先级 | 项目 | 收益 |
|---|---|---|
| **P0** | 修复 `--text-muted`、`--accent` 对比度 | 合规，全部辅助文字可读 |
| **P0** | 正文行宽封顶 42rem + 字号 15/16px | 直接减少串行 |
| **P1** | 段落节奏（单向 margin + 标题前松后紧） | 分节清晰 |
| **P1** | 阅读进度 + 三态 TOC | 长文焦虑下降 |
| **P2** | 锚点链接、阅读时间预估、回到顶部 | 导航便利 |
| **P2** | div→button 键盘可达性 | 无障碍合规 |
