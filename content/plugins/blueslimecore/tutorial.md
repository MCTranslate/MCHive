## BlueSlimeCore 安装教程

### 1. 先说结论：你大概率不需要装它

**这一节放在最前面，因为它决定了这页对你有没有意义。**

BlueSlimeCore **不是功能插件，是库**。装了它，玩家的游戏体验**完全没有任何变化**。

| | 你自己装它 | 你因为别的插件装它 |
|---|---|---|
| 玩家能感知到东西吗 | ❌ 一点都没有 | ❌ 也没有（但那是别的插件的功能） |
| 解决问题了吗 | ❌ 没有 | ✅ 那个依赖它的插件能正常加载了 |

**如果没有人要求你装它，就别装。** 多一个插件就多一份加载时间、多一份出错可能，而收益是零。

**你该装它的唯一情况：某个你非要用的插件声明依赖它，而它没装就加载失败。**

### 2. 它到底是什么

它是一个**通用工具库**，作者是 SirBlobman，仓库说明里写得很直接——「一个任何人都可以用來增强自己插件的自定义插件库」。

它把每个插件都要重写一遍的东西抽出来，做成 API：

| 它提供什么 | 具体内容 |
|-----------|---------|
| **跨版本兼容** | 同一套代码在 MC 1.8 到 26.x 上跑，屏蔽 NMS 差异 |
| **语言管理** | 多语言系统，支持**按玩家分别设置语言**、MiniMessage、PlaceholderAPI |
| **菜单 API** | 构建带按钮/分页的 GUI 菜单，物品格式可配 |
| **配置管理** | 多文件的保存与加载 |
| **命令系统** | 带玩家检查和子命令的命令框架 |
| **物品构建** | 快速造物品、皮革甲、药水、玩家头颅 |
| **Factions 适配** | 一套 API 兼容多个不同的 Factions 插件 |
| **版本处理器** | 生成实体、改最大生命值、检查吸收效果、发冷却包、查 TPS 等 |
| **杂项工具** | 位置、NBT、经验、十六进制颜色、版本判断 |

**注意最后两类不是 API，是直接给服主用的命令。** 见第 5 节。

### 3. 版本与安装

- 仓库：<https://github.com/SirBlobman/BlueSlimeCore>
- SpigotMC：Resource ID `83189`
- SpigotMC / Hangar 均有发布
- 协议：GPL-3.0
- 平台：**Spigot / Paper / Folia**（自定义 fork 可能能跑，但未测试）

**声明支持 MC 1.8 - 26.2。**

作者在仓库里明确列了一张版本表，并且标注了哪些是测试过的、哪些不是：

| 状态 | 含义 |
|------|------|
| 官方标注 ✅ | 测试过，提供支持 |
| 官方标注 ❌ | 代码里包含但**未测试，且计划在未来移除** |

**这个「计划移除」值得留意。** 跨版本兼容代码是有维护成本的——老版本的实现越来越难留。**如果你的服在很老的版本上，未来的 BlueSlimeCore 更新可能不再覆盖它。**

**Java 版本要求有过反复**：历史版本曾要求 Java 21，之后又改回可以低到 Java 8。**装之前确认你那个版本的 Java 要求**，别照着旧教程装。

安装就是拖进 `plugins/` 重启，没有硬依赖。可选依赖包括各种 Fences 系插件和 PlaceholderAPI。

### 4. 谁会需要它

**SirBlobman 自己的一堆插件都依赖它**，此外还有一些第三方插件把它当前置。

**判断你的服需不需要它：**

1. 某个插件装完不加载，控制台说缺依赖 → 看它说缺什么
2. 直接搜其他插件的 `plugin.yml`，找 `depend` / `softdepend` 里有没有 `BlueSlimeCore`
3. 控制台启动日志里哪些插件报了依赖它

**没有这三类信号，就别装。**

### 5. 它确实有几个能直接用的命令

虽然是库，但它暴露了几个给服主用的命令（**可用性以你的版本为准**）：

| 命令 | 说明 |
|------|------|
| `/item-to-nbt` | 查看物品的 NBT 数据标签 |
| `/item-to-base64` | 把物品转成 Base64 字符串 |
| `/debug-event` | 查找哪些插件在监听某个事件 |

**这三个命令在做故障排查时真的有用。**

`/debug-event` 尤其值得知道：玩家反馈「某个动作没反应」时，这个命令能告诉你**到底有没有插件在监听它**——能省掉大量「一个个禁用试试」的时间。

`/item-to-nbt` 适合排查物品属性问题（附魔、自定义 NBT）。

> ⚠️ **命令列表以你版本的 `/bsc help` 输出为准。** 版本间有增删。

### 6. 值得知道的两个设计

**按玩家设置语言**

大多数插件的语言是全局的——服务器配置成中文，所有人看中文。BlueSlimeCore 的语言 API 支持**按玩家分别设置**，并且集成 MiniMessage 和 PlaceholderAPI。

**这意味着什么**：如果你的服有国际玩家，用依赖它的插件可以给不同语言的人显示不同语言的提示，而不用装多套插件。**这在多语言社区服里是实打实的价值。**

**Factions 适配**

MC 服务器的 Factions 插件有好几个互不兼容的实现（各种 Factions / FactionsX / LegacyFensions）。BlueSlimeCore 提供一套 API 去适配它们。

**如果你用的是其中的某一种**：依赖它的插件可能就能少一层兼容问题。**如果你一个都不用**：这功能和你无关。

### 7. 常见坑

**被当成功能插件装了，没人用**

见第 1 节。**这是最常见的情况**——搜索时看到「有用的库插件」就装了。装完除了占一点加载时间，什么都没有。

**不装它导致依赖插件加载失败**

控制台会明确报缺少 `BlueSlimeCore`。**这时候从依赖它的那个插件的官方页面下载对应版本**，别随便找一个版本。

**Java 版本不对**

历史上有过「必须 Java 21」的版本。**装之前看一眼发布页的说明。**

**装了个旧版本，依赖它的新版插件起不来**

库插件有严格的版本对应关系。**插件要求哪个版本就装哪个版本**，别用「反正有个 BlueSlimeCore」的想法凑合。

**老 MC 版本未来可能不被支持**

见第 3 节——作者已经标注了未测试且计划移除的版本。**如果你依赖很老的版本，锁版本别乱升。**

### 8. 什么时候可以删掉它

**只有一种情况：你把依赖它的插件全卸了。**

它自己**不提供任何玩家功能**，所以删掉它不会损失任何东西。但——**如果还有插件声明依赖它，删了会导致连锁加载失败**，而报错往往只说「缺少依赖」，不告诉你是 BlueSlimeCore。

**删之前按第 4 节的方法确认一遍有没有人在用。**

### 9. 关于汉化

**本站未核实 BlueSlimeCore 的官方中文语言文件机制。** 若要汉化需自行确认。

需要注意的是：**它本身自带一套语言管理 API**（见第 6 节），但那是给**依赖它的插件**用的接口，不是给服主直接改的文件。

引导式排查方法：

1. 进 `plugins/BlueSlimeCore/`（或它实际生成的目录名），找语言相关文件
2. 搜配置里有没有 `language`、`lang`、`locale`、`messages` 关键词
3. **注意区分对象** —— 依赖它的插件的提示文本是各自的语言文件管的，**改 BlueSlimeCore 自己的语言文件不一定能改到那些提示**

**实用建议：玩家能看到的提示来自依赖它的那些插件。** 想汉化那些提示，应该去对应插件里改，别在这里绕。

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候该关心它

| 你的情况 | 该做什么 |
|---------|---------|
| 只是想让服更好玩 | **不用管它** |
| 某个插件报缺依赖 | 装它，然后看那个插件的要求 |
| 服里有国际玩家 | 值得关注——它的按玩家语言机制是这类库里少见的 |
| 你自己写插件 | 可以考虑用它的 API，能省掉跨版本适配的活 |
| 服在很老的 MC 上 | 注意它未来可能放弃那些版本 |
