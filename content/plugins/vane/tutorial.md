## Vane 安装教程

### 1. 先说清它是什么

**Vane 不是一个「单功能插件」，是一个模块化的原版增强合集。**

作者的定位是「**沉浸且不破坏原版 lore 的原版增强**」——注意这后半句，它的设计准则是**不做违背 Minecraft 世界观的东西**。它不给你加魔法、不加神棍系统，只加那些「原版暗示了但没实现」的东西。

**模块划分**（从仓库结构能看出）：

| 模块 | 大致内容 |
|------|---------|
| `vane-core` | 核心：物品保护、命令隐藏、可配置性 |
| `vane-regions` | **区域系统**（区域权限、区域创建） |
| `vane-enchantments` | **附魔**（翅膀、钩爪、不破坏、收割者、打雷……） |
| `vane-trifles` | **小物件/工具**（背包、药水、剪刀、锄、指南针、经验瓶、末影箱……） |
| `vane-portals` | 传送门相关内容 |
| `vane-enchantments` | 附魔 |
| `vane-bedtime` | 睡眠/床相关机制 |
| `vane-admin` | 管理功能 |
| `vane-velocity` | Velocity 代理端支持 |

> ⚠️ **具体每个模块包含哪些功能、以什么形式提供，以你版本的官方文档为准。** Vane 有自己的文档站（`oddlama.github.io/vane`），模块和功能会随版本增删。**本页不列完整功能清单**——抄一份必然过时的清单不如指路。

### 2. 它和「给服务器加玩法」是两件事

**先想清楚你要的是哪种：**

| 你想要的 | Vane 适不适合 |
|---------|-------------|
| **原版机制的完善**（更多附魔、更好用的工具、区域保护） | ✅ 正是它做的 |
| **新玩法/新系统**（职业、技能、剧情、技能树） | ❌ **它不做这个**。找 AuraSkills / Quests / Jobs 这类 |
| **性能优化** | ❌ 它是功能插件，**不是优化插件**。找 PaperTweaks 那类 |
| **领地保护** | ⚠️ 它有 `vane-regions`，但**不能替代 WorldGuard**（见下） |

> **判断标准：你想让原版「更好用」，还是想加「原版没有的东西」？** Vane 站在前者。

### 3. ⚠️ 它不是 WorldGuard 的替代品

Vane 有一个 `vane-regions` 模块提供区域功能，**很容易让人以为可以用它代替 WorldGuard**。

**建议不要这样用。** WorldGuard 是这一块的专门工具：

| | Vane regions | WorldGuard |
|---|-------------|------------|
| 成熟度 | 模块化增强的一部分 | **专门的保护工具，多年迭代** |
| 保护类型 | 区域权限 | 完整的保护体系（建筑/交互/破坏/爆炸/PVP…） |
| 兼容性 | 独立 | 被无数插件依赖 |

**如果你的服需要严肃的领地保护 → 用 WorldGuard。** Vane 的区域功能按它自己的定位来用（更轻量的区域概念）。

### 4. 附魔模块：这是 Vane 最有特色也最需要谨慎的部分

`vane-enchantments` 提供了一批自定义附魔。从仓库文档能看到的包括：

| 附魔 | 大致作用 |
|------|---------|
| **翅膀（wings）** | 飞行类|
| ** grappling hook（钩爪）** | 移动类 |
| **不破坏（unbreakable）** | 工具耐久 |
| **收割者/割草（rake/leafchopper）** | 收割作物 |
| **播种（seeding）** | 批量播种 |
| **灵魂绑定（soulbound）** | 死亡不掉落 |
| **古老之书（ancient tome系列）** | 附魔相关 |
| **打雷（lightning）/ 地狱冲刺（hell bent）** | 特效/移动 |

> ⚠️ **这类附魔是「改变玩法平衡」的东西。** 「翅膀」这种附魔一旦能刷到，** PvP 和生存难度就变了**。

**要仔细想的：**

| 问题 | 为什么重要 |
|------|-----------|
| **能不能刷到** | 能刷到翅膀 = 破坏游戏平衡 |
| **和什么稀有度/获取方式绑定** | 太容易得到就崩平衡 |
| **PvP 服能不能用** | 翅膀/钩爪类附魔在 PvP 里强度很高 |
| **和附魔冲突系统的兼容** | 你服里如果有其他附魔插件 |

> **一句话：Vane 的附魔「好玩」，但「平衡」要你自己把关。** 它的设计优先沉浸和原版感，不是优先竞技平衡。

### 5. 安装

1. 从官方渠道下载（**oddlama/vane**，Modrinth: `vane`）
2. 丢进 `plugins/`
3. 启动，生成配置

**有 Velocity 支持**（仓库有 `vane-velocity` 模块）——如果你跑代理，可以考虑。

> ⚠️ **模块可能是可单独开关的。** 装了之后**先别全开**，去配置里/命令里确认哪些模块默认启用、能不能按需关。**具体模块开关方式以你版本的文档为准。**

### 6. 汉化：自带中文

**Vane 自带简繁中文。** 仓库里各模块都有：

```
lang-zh-cn.yml← 简体中文
lang-zh-tw.yml    ← 繁体中文
```

**每个模块独立带一套**（vane-core、vane-regions、vane-trifles、vane-enchantments 等各自有lang 文件）。

一共有 7 种语言（含中文两种）。**跟随玩家客户端语言自动切换。**

详见 [汉化机制](#/plugin/vane) 页。

### 7. 性能：模块多，开销就多

**Vane 的开销跟着你启用的模块走。**

| 因素 | 说明 |
|------|------|
| **启用模块数量** | 开得越多，日常事件处理越多 |
| **区域模块** | 区域判定会在玩家交互时执行 |
| **附魔模块** | 附魔效果触发时的逻辑 |
| **小物件模块** | 物品使用事件处理 |

> **实践建议：**
> - **别把能开的都开满** —— 挑你真正想要的
> - **一次开一批，观察 TPS**（尤其玩家密集时段）
> - **如果 TPS 掉了，先怀疑你开得太多**，而不是别的插件

它是**功能插件不是优化插件**，别指望它帮服务器变快。

### 8. 常见坑

**和WorldGuard 冲突/重复**

⚠️ **区域功能重叠了。** 见上面第 3 点。**同时用两套区域保护要非常小心**——保护规则可能互相打架（一个放行一个拦截）。

**和附魔插件冲突**

如果服里还有别的附魔插件（自己写的附魔插件、附墨水的加强版等），**两套附魔系统会互相影响**。**同一个附魔名可能冲突。**

**和 Geyser/基岩玩家**

客户端不同，能用的东西不同。**具体表现以实测为准** —— Vane 的一些机制有客户端依赖。

**平衡被自定义附魔打破**

见上面附魔那节。**翅膀类附魔刷到就崩。**

**模块不知道哪些开了**

去配置和命令里确认。**以你版本的文档为准。**

### 9. 什么时候别装

- **想要新玩法/系统** —— 它不做这个，找别的
- **想要领地保护** —— **用 WorldGuard**，别拿它凑
- **竞技/PvP 服** —— 自定义附魔（翅膀等）会严重破坏平衡
- **追求极简原版** —— 它的整个存在意义就是改原版
- **已经装了很多增强类插件** —— 功能可能重叠

### 10. 关于汉化的补充

各模块语言文件在仓库里是 `lang-xx.yml` 的形式，**每个模块一份**。

需要改文案时：

1. 进 `plugins/Vane/`（**具体目录结构以你版本为准**）
2. 找各模块的语言覆盖目录
3. 复制 `lang-zh-cn.yml` 改
4. 重启

**不要直接改 jar。**
