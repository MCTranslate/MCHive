# GSit 汉化机制

> 以下路径来自官方仓库文件树核实。GSit 的多语言支持是同类插件里比较用心的。

## 一、结论：自带简繁中文，开箱即用

GSit 的语言文件在仓库里共 **19 个**，中文占 2 个：

```
zh_cn.yml    ← 简体中文
zh_tw.yml    ← 繁体中文
```

**命名风格是下划线**（`zh_cn` 而不是 `zh-CN`）。这点在你自己放覆盖文件时容易踩——**命名必须和官方一致**，写成 `zh-CN.yml` 不会被加载。

语言文件是 YAML 格式（和配置文件同一种风格），位置在插件数据目录下（`plugins/GSit/` 内，具体子目录以实际生成的目录为准）。

## 二、怎么切换

**默认跟随玩家客户端语言。** 简体中文客户端进服自动生效，不需要改任何配置。

这点比很多插件省事——有些插件要在 config 里手动指定语言码，结果不同玩家的客户端语言就统一了，导致混编团队反而更难用。

如果你的服想强制统一语言，去配置文件里找语言/locale 相关的配置项。**具体配置键名请以你手上版本的 config 注释为准**——GSit 的配置结构随版本变过，写死的键名不可靠。

## 三、想改文案

1. 进 `plugins/GSit/`，找到语言文件所在目录
2. 复制一份 `zh_cn.yml` 出来，改里面的文本
3. 重启服务器

**不要直接改 jar 里的文件。** 升级就白改了。

GSit 的语言文件里除了提示文本，**命令帮助文本也在里面**。所以改这份文件能一次性改掉玩家看到的 `/gsit` 帮助输出——这是很实用的一点，服主不用再在公告里贴命令列表。

## 四、三个容易踩的坑

**改了没生效**

GSit 的语言文件在启动时加载。改完**必须完整重启**，`/gsit reload` 是否覆盖语言文件取决于版本——**不确定就重启**，重启永远是对的。

**命名写成 `zh-CN.yml` 或 `zh_cn.yml.bak`**

必须**严格**是 `zh_cn.yml`。大小写、下划线、扩展名都要对。多一个字符就静默失效——插件找不到就用默认英文，**不报错**。

很多人排查半天发现是自己文件名多了个 `final`。

**简繁体选错**

`zh_cn` 是简体，`zh_tw` 是繁体（**注意不是 `zh_HK`**）。给大陆玩家用 `zh_cn`。

## 五、什么不会被汉化

语言文件只管**界面提示文本和命令帮助**。这些仍然是英文：

- **物品栏里的姿势图标名** —— 如果游戏里显示的是原版可翻译组件，跟随客户端语言
- **资源包里的模型/纹理内容** —— 那是美术资源，不走语言文件
- **你自己在配置里写的告示、菜单标题** —— 在配置文件里写，可以直接写中文

## 六、验证有没有生效

装完之后自己确认一遍，比看文档靠谱：

```
进游戏（客户端语言设成简体中文）
  → /sit
  → 看聊天栏和命令返回是不是中文
  → 敲 /gsit 打开帮助，看是不是中文
```

两条都中文 = 生效了。任一条是英文，去检查文件名。
