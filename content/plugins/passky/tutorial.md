## Passky 安装教程

### 1. 先确认你到底需不需要它

**这一节放在最前面，因为它决定了后面所有事值不值得。**

```
online-mode=true（正版验证）
  → 玩家 UUID 由 Mojang 分配，别人拿不走你的身份
  → 不需要任何登录插件

online-mode=false（离线模式）
  → 玩家 UUID 按名字生成
  → 别人只要用你的 ID 进服，就是你
  → 需要登录插件
```

**离线服不装登录插件，等于把存档拱手让人。** 但登录插件是玩家体验的敌人——它给每个玩家增加一次摩擦。**没有两全的方案，只有选一个代价。**

> 如果你有正版玩家（Geyser / Floodgate 进来的基岩玩家），判断要单独算：基岩玩家走的是 Floodgate 那套流程，**和 Java 玩家的登录机制不是一回事**。

### 2. Passky 和 AuthMe 是什么关系

**Passky 定位是 AuthMe 的替代品——两者是二选一的关系，不能同时装。**

站内收录的 AuthMe 系是 [AuthMeReReloaded](#/plugin/authmerereloaded)，一个第三方 fork（版本号带 `-FORK` 后缀，上游支持上限 MC 1.21.3）。

| | **Passky** | **AuthMeReReloaded** |
|---|---|---|
| 定位 | 登录认证 | 登录认证 |
| 声明 MC 区间 | **1.8 - 26.2** | 1.8 - 1.21.3 |
| 上游/来源 | **本站未核实到明确的官方上游仓库** | 已知是 AuthMe Reloaded 的第三方 fork |
| 成熟度参照 | 较新，声明区间到 26.2 | fork，跟随但落后于上游 |
| 社区沉淀 | 相对少 | 十几年的老插件，教程和踩坑资料极多 |
| 和对方的关系 | **二选一** | **二选一** |

**为什么强调「二选一」**

两个登录插件装一起的后果不是「功能叠加」，是**互相打架**：

| 症状 | 原因 |
|------|------|
| 玩家登录状态混乱 | 两套会话逻辑都在管 |
| 玩家卡在登录界面出不来 | 一个认了密码，另一个不认 |
| 数据库写入冲突 | 两边都在写同一份账号数据 |
| 传送/经济插件行为异常 | 「已登录」的判定和你的预期不一样 |

**这不是能靠配置绕过去的问题，是设计上就不该共存。** 换插件 = 先卸载旧的，确认数据处理完，再装新的。

### 3. 选哪个：说点实在的

**没有「Passky 更好」或「AuthMe 更好」的结论，只有适不适合你现在的服。**

选 Passky 的理由：服在 **MC 1.21.4 或更高**（AuthMeReReloaded 声明上限 1.21.3，不覆盖）；你要一个**声明区间到 26.2** 的方案；你愿意接受**更少的社区踩坑资料**（遇到问题得自己看文档/问作者）。

继续用 AuthMe 系的理由：服在 **1.21.3 及以下**且现有配置已经跑通——**没坏就别换**；团队已熟悉它的配置和坑；遇到问题时**能找到资料**（这对服主是实打实的价值）。

> **本站未核实 Passky 的功能细节、配置项、命令列表和数据库兼容性。** 本页不给它的配置项编造键名，命令表也只写登录类插件的通用动作。**装之前自己看它的官方页面**（见第 4 节）。

### 4. 下载

**⚠️ 本站未定位到 Passky 的官方仓库。** 这意味着你更需要自己去确认下载源，而不是照着本页的链接点。

确认渠道：

1. **Modrinth / Hangar 搜插件名** —— 看作者名、下载量、更新时间
2. **看它是不是在某个已知的插件生态里被列为依赖**（比如某些插件的 `depend` / `softdepend` 里写了它）
3. **看 MC 1.8 - 26.2 这个区间声明是否在官方页面上** —— 如果你只在第三方转载页看到这个区间，把它当未验证信息

> **不明的来源不要装。** 登录插件是要处理玩家密码的——密码会进数据库、会进哈希算法、会进日志。装一个来源不明的登录插件，**等于把你的服交给陌生人。**

### 5. 装之前必须做的决定

**这一步比装插件本身重要。**

| 决定 | 说明 |
|------|------|
| **要不要装** | 装了就回不去了。玩家会觉得「多了一步」 |
| **注册上限** | 同一 IP 能注册几个账号。**不限制 = 小号泛滥** |
| **超时踢出** | 不在时限内登录就踢。设太短会误伤输错密码的玩家 |
| **忘了密码怎么办** | 服主必须有管理手段（这是必须有的，不是可选项） |
| **未登录时禁哪些命令** | 传送、经济、领地相关的都要禁。漏一个就等于开了个口子——比如漏了 `/pay`，别人能在登录前转账 |
| **和别的插件的兼容** | 有些插件要求玩家已登录才能用 |

**上线前自己演练一遍控制台命令。** 服主忘了密码没人能进服，是登录插件最经典的事故。

### 6. 安装

1. 从确认过的官方渠道下载 jar
2. 放进 `plugins/`
3. 重启服务器
4. 生成 `plugins/<插件名>/` 目录（含配置和数据库文件）

**没有前置依赖**（这是登录类插件的常态）。

### 7. 常用命令

登录类插件的通用动作（**具体命令名和参数以你版本的帮助输出为准**）：

| 动作 | 说明 |
|------|------|
| 登录 / 注册 | 输入密码 / 设置密码（部分实现需确认） |
| 改密码 | 需要旧密码 |
| 登出 | 退出登录状态 |
| 邮箱设置 | 用于找回（部分实现） |

**管理端**（权限控制，具体节点名以 `plugin.yml` 为准）：查看登录状态、强制改密、解锁账号、踢出未登录玩家。

> ⚠️ Passky 的实际命令列表**本站未核实**，上表是这类插件的通用动作，不是它的完整清单。装完先进游戏敲帮助命令看实际有什么。

### 8. 常见坑

**装完玩家卡在登录界面出不来**

按可能性排：**① 两个登录插件共存**（见第 2 节，最常见）→ ② 数据库读写异常（看控制台堆栈）→ ③ 某个依赖插件在登录流程里报错了。

**玩家反复输错密码被踢**

超时设太短的直接后果。改长一点，或者配「输 N 次后锁一段时间」而不是直接踢。

**注册小号泛滥**

不限同一 IP 注册数量 = 一个人注册一百个号。**注册限制是必需的，不是可选的。**

**和 Geyser / Floodgate 的配合没测试**

基岩玩家走另一条认证路径。**装了 Geyser 的服必须单独测基岩玩家的流程**，别假设和 Java 玩家一样。

**装完之后某些插件报错**

有些插件要求玩家已完成登录。表现是「登录后才能用 /xxx」。**这要在登录插件里把该插件的未登录拦截加上，或在别的插件里改白名单。**

**服主自己忘了密码，没人能进服**

**先确认控制台有强制改密/解锁的手段，并且现在就试一遍。** 别等出事才第一次用。

**什么时候别用它**

- **正版服（online-mode=true）** —— UUID 由 Mojang 管，不需要。装了纯属给玩家添麻烦
- **只是 1-2 个朋友连机** —— 用正版账号就行
- **已经装了 AuthMe 系** —— 二选一，见第 2 节

### 9. 关于汉化

**本站未核实 Passky 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/Passky/`（或它实际生成的目录名），找语言相关文件——常见形态是 `lang/` 目录、`messages_xx.yml`、`locale/` 目录
2. 搜配置文件里有没有 `language`、`lang`、`locale`、`messages` 关键词
3. **别只搜主配置文件** —— 有些实现把语言设置写在单独的 `config.yml` 里，或者用 `language: zh_CN` 这种单行指定

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
