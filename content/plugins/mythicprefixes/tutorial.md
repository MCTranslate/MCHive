## MythicPrefixes 安装教程

### 1. 它是什么（先看这段，否则你会装错）

MythicPrefixes 是一个**称号/标签（tag）管理框架**。它解决的问题只有一个：**谁在什么条件下能佩戴哪些称号**。

它做这些事：

| 能力 | 说明 |
|------|------|
| 多称号并行 | 一个玩家可同时戴多个称号，聊天显示一个、计分板显示另一个 |
| 权限驱动 | 有权限节点就能戴，不占用数据库存储，靠权限判定 |
| 自定义显示占位符 | 生成 PAPI 变量，显示内容可配数量上限、隐藏列表、输出格式 |
| 装备触发 | 戴上/摘下称号时执行动作：发消息、actionbar、标题、音效、执行命令、传送、粒子、生成实体 |
| 周期动作 | 佩戴期间按周期重复执行动作（注意这里的性能开销） |
| BUFF 联动 | 接 libreforge、AuraSkills、MythicMobs、MythicLib 的属性加成 |
| HEX / 渐变色 | 16 位颜色、渐变，支持 MiniMessage 与旧式颜色码 |

### 2. 它刻意不做的事（这是它的设计，不是缺陷）

这一点非常关键，直接决定了你要不要选它：

```
❌ 不做称号商店         → 想要商店请自己接 QuickShop / DeluxeMenu
❌ 不存玩家称号数据     → 判定走权限节点，不做「个人已拥有列表」
❌ 不做称号卡物品       → 想要可发放的道具请用 ItemsAdder 之类的
❌ 不改聊天格式/Tab/计分板 → 只提供 PAPI 变量，渲染交给别的插件
```

作者的定位很明确：**这插件是给懂权限系统的服主用的模块**，不是小白开箱即用方案。

> 说人话：你要是想要「一个称号商店 + GUI + 聊天显示 + 计分板显示」全家桶，这个插件**单独用不了**，你还得再装两三个插件把剩下的一半补上。这种情况下你该找的是打包型插件。

### 3. 前置与平台

| 项目 | 说明 |
|------|------|
| 平台 | Folia / Paper / Purpur / Spigot |
| 硬依赖 | 无（核心功能自足） |
| 软依赖 | libreforge、AuraSkills、MythicMobs、MythicLib（属性/效果联动） |
| 渲染侧 | PlaceholderAPI + 你的聊天/计分板插件 |

装之前确认这三件事：

1. 你的服有权限插件（[LuckPerms](#/plugin/luckperms) 之类）——**没这个插件整套逻辑跑不起来**
2. 你的服有 PAPI——称号文本要靠变量输出到聊天/计分板
3. 你知道自己想要什么显示在哪个位置

### 4. 安装

1. 下载 jar 丢进 `plugins/`
2. 重启，生成 `plugins/MythicPrefixes/` 目录
3. 确认聊天插件 / 计分板插件已经装好并能输出 PAPI 变量

> 版本号提醒：2.1.x 之后的更新日志里出现过多次与 PacketEvents 是否安装相关的报错修复。**如果你服里装了 PacketEvents，留意启动日志里 MythicPrefixes 那几行**，别把无关的报错当成它的锅。

### 5. 命令

命令这块本站不列具体子命令——不同版本增删过命令，硬写容易误导。**最可靠的做法是进游戏敲主命令看内置 help**：

```
/mp help        （主命令名以插件实际提供的为准）
```

命令不是这个插件的重点。它的重点是配置文件。

### 6. 配置结构：2.1.4 的重点变化

2.1.4 的更新说明里明确写了**配置文件支持递归读取**——你把配置放进子文件夹里也能正常加载。

这解决的是一个真实痛点：称号多了以后 `prefixes/` 目录会变成一堆平铺的 YAML 文件，多到根本没法翻。2.1.4 之后你可以自己分目录：

```
plugins/MythicPrefixes/
├── 基础/       # 新手可用的一批
├── 稀有/       # BOSS 掉落限定
└── 活动/       # 赛季限定称号
```

另外 2.1.4 也修了 Tab 补全：选项列表会自动过滤掉不匹配当前输入的项，补全不再刷屏。

> 具体目录名、文件结构、字段名**以你版本实际生成的目录为准**。本站没有核实到 2.1.4 的完整字段清单，不提供逐键对照，避免给错。

### 7. 一条称号大概长什么样

不写具体键名，只说结构逻辑（这是插件的设计通例，字段名以实际文件为准）：

```
标识（唯一 id）
 ├─ 显示文本        ← 这里填中文标题，支持 HEX / 渐变
 ├─ 所需权限        ← 玩家有权限才发得到
 ├─ 条件            ← 世界、地区、占位符判定、ANY / NOT 组合
 └─ 动作
     ├─ 戴上时：发消息 + 标题 + 音效
     ├─ 摘下时：移除 BUFF
     └─ 周期动作：每 N tick 执行
```

三处逻辑要自己想清楚：

**① 条件怎么组合。** 条件系统支持权限、世界、地区、占位符判定，还有 ANY 模式和 NOT 逻辑。称号发放的复杂度全在这。设计的时候先画条件树再写配置，别边想边写。

**② 动作的副作用。** 「周期动作」是按 tick 重复执行的。给一个玩家戴 5 个称号、每个称号都配了 3 秒周期的粒子——在线 50 人就是每 tick 750 次粒子调用。**称号带周期动作之前先算一遍这个数**。真要做周期效果，优先用 3.x 分支的做法或者别的状态显示插件。

**③ 商店怎么接。** 插件不给商店。想做「用金币买称号」，流程是：商店插件卖一个物品 → 物品右键执行 `/lp user <玩家> parent add <称号权限>` → 玩家自动获得称号。**称号的「购买」本质是发权限**，这个设计带来的好处是：不需要给称号单独建存储，退款就是撤权限。

### 8. 常见坑

**称号显示了但颜色不对 / 变成 `&#xxxxxx` 字面量**

你的聊天插件把颜色码吃掉了。InteractiveChat 官方文档特别提到：它的颜色转义是靠**改写数据包**实现的，**如果另一个插件也在改数据包，就会互相打架**。这是装了多层聊天插件的典型症状。解法是只让一个插件负责颜色。

**玩家背包/计分板表现和聊天不一致**

正常，因为这个插件只发变量，渲染由三个不同插件分别负责。要一致就得在三个地方用同一套格式化配置，别指望插件帮你统一。

**BUFF 摘不下来**

「周期动作」和「摘下时动作」是两套机制。周期动作发的 BUFF 不一定会走摘下清理。称号 buff 这块建议参考 [MythicMobs](#/plugin/mythicmobs) 的属性系统，两边一起调。

**reload 后玩家称号状态错乱**

2.x 系列对 reload 做过多次重写（2.1.0 甚至强制改成 PlayerJoinEvent 触发缓存加载）。热重载后让玩家重进一次服务器验证，别在生产服靠 reload 改称号配置。

**权限给错了，称号发不出去**

先自检这条链路：权限插件里玩家真的有那个节点吗？→ 条件里的其他判定也过了吗？→ 你配的动作里有没有把称号又立刻摘掉？第三种最隐蔽，很多「佩戴后立刻消失」都是动作配置互相打架。

### 9. 汉化

> **本站未核实到该插件的官方中文语言文件机制，若要汉化需自行确认。**

不过这个插件的汉化需求本来就不大——**称号文本是你自己填的**，直接把「显示文本」写成中文就是汉化：

| 要改的文本 | 在哪 |
|-----------|------|
| 称号显示文本 | 称号配置里的显示文本项 |
| 称号 Lore / 描述 | 称号配置里的描述项 |
| GUI 按钮名称 | GUI 配置文件 |
| 佩戴/摘下的提示消息 | 动作配置里的消息类动作 |
| 菜单标题 | GUI 配置 |

> ⚠️ **以实际文件为准。** 打开配置目录搜 `messages` / `lang` / `locale` 之类段落看看还有没有别的可改文本，本站不提供逐键对照的汉化文件。

配色上提醒一句：中文称号普遍比英文长，配 HEX 渐变时颜色跨度别拉太大，不然中间几个字会糊成一片。
