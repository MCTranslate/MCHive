## VaultUnlocked 安装教程

### 1. 先搞清它和 Vault 的关系

**VaultUnlocked 是 Vault 的 fork（分支）——不是「类似插件」，是 fork。**

这决定了很多事，先说清楚：

| 关系项 | 说明 |
|--------|------|
| **代码来源** | 从 Vault fork 出来 |
| **定位** | **drop-in replacement（直接替换）** —— 官方描述就是「现代的 drop-in Vault fork」 |
| **兼容性目标** | **让依赖 Vault API 的插件照常工作** |
| **加了什么** | **Folia 支持** + **增强的 API** |
| **为什么 fork** | **为了能提 PR** —— 见下 |

### 2. 为什么要 fork Vault：这是理解它的关键

**Vault 本身的故事是个典型的「生态瓶颈」案例：**

Vault 定义了一套标准接口（权限、经济、聊天），让「任何经济插件」和「任何要读余额的插件」能互通。**这个设计影响了整个 Bukkit 生态——现在几乎所有经济/权限类插件都支持 Vault。**

**问题出在维护上：**

- Vault 的核心功能**基本够用**，不需要大改
- 但 **Folia 来了**、新版 API 来了，Vault 不跟进
- 想给 Vault 加个 Folia 支持？**提 PR 没人合并**
- 于是依赖 Vault 的插件遇到 Folia 就尴尬

**「为提 PR 而生」就是这个意思**：既然上游不合并 PR，那就 fork 一份自己改。VaultUnlocked 的核心动机是**让改动能落地**——加Folia 支持、增强 API。

> **所以它的定位不是「更好的 Vault」，而是「能继续维护的 Vault」。** 理解这点，你就知道它什么时候该用。

### 3. 什么时候用 VaultUnlocked

| 场景 | 建议 |
|------|------|
| **你跑 Folia** | ✅ **这是最明确的理由** —— 原版 Vault 不支持 Folia |
| **依赖 Vault 的插件在 Folia 上报错** | ✅ 换它能解决 |
| **需要 Vault API 的新功能** | ✅ 它加了增强 API |
| **普通 Paper 服，用 Vault 用得好好的** | ❌ **没必要换** —— 原版 Vault 还能用 |
| **新服从零开始** | ⚠️ 可以考虑，但原版 Vault 也行|

> **实话说：如果你的服是普通 Paper，Vault 没出什么问题，那就不用换。** fork 的价值在「上游不维护」这个特定问题上——**你得真的撞上那个问题才需要它。**

### 4. 替换 Vault：操作很简单

**因为是 drop-in replacement，替换流程很直接：**

1. **删掉原Vault 的 jar**（从 `plugins/` 移走，**不是禁用**）
2. 装VaultUnlocked
3. 启动

**它用同样的 API，所以依赖 Vault 的插件（EssentialsX、ChestShop、Jobs 等）不需要改任何配置。**

> ⚠️ **但要注意插件兼容性的一个现实**：绝大多数插件只声明「依赖 Vault API」，不关心你装的是原版还是 fork。**理论上直接换就行。** 不过既然是替换核心 API，**建议先在测试服跑一遍**，确认你服上那些经济/权限插件都正常。

**不建议两个都装**——会冲突。

### 5. ⚠️ 降级回原版 Vault：可能没那么简单

**这是需要注意的一个方向。**

VaultUnlocked 如果加了新 API，**用上这些新 API 的插件在换回原版 Vault 后会挂**。所以：

- **先确认你服上哪些插件依赖 Vault**，以及它们用的是**原始 API 还是新 API**
- 如果只用原始 API（大多数情况），**回退没问题**
- 如果有插件用了它的增强 API，**回退会报错**

> **实践上，大部分服用的是原始 API**，所以这条更多是「心里有数」。

### 6. Folia 相关

**这是 VaultUnlocked 最有价值的地方。**

如果你跑 Folia：

| 组件 | 原版 Vault | VaultUnlocked |
|------|-----------|--------------|
| Folia 兼容性 | ❌ 不支持 | ✅ **支持** |
| 依赖它的插件 | 可能在 Folia 上出错 | 正常工作 |

> ⚠️ **先确认你的 Folia 上真的有这个问题。** 不是所有依赖 Vault 的插件都会在 Folia 上出问题——**取决于它们怎么用 Vault**。如果你的服在 Folia 上跑得好好的 Vault 生态，那就不需要动。

### 7. 增强 API

VaultUnlocked 在原版 API 基础上加了增强 API。

**对普通服主来说这条基本用不上**——它是给**插件开发者**用的。**如果你不是写插件，这部分可以忽略。**

提及它的意义：**这是它持续维护的证据**——有东西在往前推。

### 8. 常见坑

**换过去之后某个插件报错**

- 确认**只装了一个** Vault（删干净原版）
- 确认**没有**其他插件自带了 Vault（比如某些插件会把 Vault 打包进去）
- 看日志是哪个插件报的错，它可能用了增强 API 而你装的是原版（反过来的情况）

**装了两个 Vault**

❌ **冲突。** 只留一个。

**原版 Vault 我还能继续用吗**

**能**，只要你没撞上 Folia/新 API 这些它不跟进的问题。

**不确定该用哪个**

**问自己一句：我的 Vault 现在有实际问题吗？** 没有就别换。**fork 不是默认升级项。**

### 9. 什么时候别用

- **普通 Paper 服，Vault 一切正常** —— ✅ 不需要动
- **只是「听说这个更新」** —— fork 不该因为「更新」而换，**因为有实际问题才换**
- **服上大量插件用了增强 API**（虽然罕见）—— 那你已经锁定了

### 10. 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

**但对这个插件来说这基本不重要**——VaultUnlocked 是个**中间件/API 层插件**：

| 特点 | 说明 |
|------|------|
| **玩家可见文本极少** | 它不提供玩法界面 |
| **主要是 API** | 给别的插件调用|
| **消息多为错误/日志** | 面向管理员，不是玩家 |

**需要汉化的东西可能只有错误提示。** 经济、权限这些**玩家看到的是别的插件的文案**（EssentialsX、ChestShop 等各自的语言文件）。

如果确实要改：

1. 进 `plugins/VaultUnlocked/` 看有没有语言文件
2. 仓库 `TheNewEconomy/VaultUnlockedAPI` 搜 `lang` / `message`
3. **具体机制以你版本为准**

> **别为它折腾汉化** —— 它的输出面太小了。**想把经济/权限提示汉化，该去改那些真正显示文案的插件。**
