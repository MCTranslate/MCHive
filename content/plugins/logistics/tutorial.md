## ⚠️ 先说清楚：这不是 Paper 插件

**这一条必须先讲，否则你会在错误的渠道找很久。**

我们核实了 Logistics 的官方仓库（**Indemnity83/logistics**）和 Modrinth 记录：

| 项目 | 实际情况 |
|------|---------|
| **形态** | **Minecraft 模组**（mod） |
| **加载器** | **Fabric / NeoForge**（multiloader） |
| **有没有 Paper/Spigot/Bukkit 版** | ❌ **没有** |
| **协议** | MIT |

**所以：**

- ❌ **不能**放进 Paper/Spigot/BungeeCord 的 `plugins/`
- ✅ **只能**装在 **Fabric 或 NeoForge** 的模组服务器上
- ✅ **客户端也要装**（它是真正的 mod，server side 标注为 required）

> ⚠️ **如果你的服是 Paper 系，这个插件和你无关。** 请直接跳过，去看 [PaperTweaks](#/plugin/papertweaks) 或其他 Paper 插件。

### 关于「Nova 附属」的说法

**本站未核实到 Logistics 是 Nova 的附属插件。**

我们查了它的仓库（文件树、gradle 配置、README），**没有发现对 Nova 的依赖**。它的官方定位是：

> 「一个受 BuildCraft 和 Logistics Pipes 启发的 **multiloader 模组**，把真实的物品管道系统带回现代 Minecraft。」

**它自己就是一个独立的模组项目**，不是别人的附属。**如果你是因为「Nova 附属」这个说法找过来的，这个说法和它实际的情况对不上——请以它的官方仓库为准。**

### 1. 它在做什么

**把你熟悉的经典 Minecraft 自动化搬回现代版本。**

管道里能看到东西在**真实移动**（不是瞬间传送），这是它最有特色的地方。

主要内容：

| 系统 | 内容 |
|------|------|
| **管道（Pipes）** | 物品运输、抽取、过滤，完整网络（提供者、请求者、供应商） |
| **请求/自动合成** | 物品网络 + 自动合成系统 |
| **流体（Fluids）** | **独立于物品网络**的流体管道/罐/泵系统 |
| **动力（Power）** | RF 引擎（红石、斯特林、创造）、动力线缆 |
| **自动化机器** | 粉碎机（macerator）、窑（kiln）、**激光采石场**（laser quarry）、精炼厂、序列Fabricator |

**「激光采石场」是这类模组的经典玩法**——自动化采石，不用手动挖。

### 2. ⚠️ 早期开发阶段

**官方 README 自己写明：**

> **⚠️ Early Development** — Logistics is in active development. 核心系统能用，但预期有毛刺、缺失功能和偶发 bug。

**这是作者自己的话。** 具体意味着：

| 风险 | 说明 |
|------|------|
| **毛刺和 bug** | 明确承认可能有 |
| **功能缺失** | 计划中的功能可能没做完 |
| **存档兼容** | ⚠️ **这是最要紧的**——见下 |

> ⚠️ **存档兼容警告（官方明确写了）**：
> 预发布阶段，**存档向前兼容只回溯一个主版本**（版本号的第二位）。升级时要用**每个大版本的最新发布版依次加载世界**，不能直接跳到最新。
>
> **实操上就是**：从旧版升到最新版，要 1.19 → 1.20 → 1.21 → 26.x 一路升上来，**每一步都要先进游戏开一下世界**。直接跳会坏存档。
>
> **升级前务必备份世界。** 这不是客套话。

### 3. 什么时候用

**它只适合一种情况：你想玩经典自动化模组。**

| 你想要的 | 适合吗 |
|---------|--------|
| **玩 BuildCraft/Logistics Pipes 那种自动化** | ✅ 正是它 |
| **想自动化采石/冶炼** | ✅ |
| **在 Paper 服上要管道** | ❌ **它不是 Paper 插件** |
| **只想简化一点原版红石** | ❌ 太重了 |
| **服务器稳定的生产环境** | ⚠️ **早期开发阶段，存档兼容有坑** |

> **判断标准**：你怀念经典 MC 自动化模组，**并且你的服本来就是模组服**。两条都满足才值得。

### 4. 安装

**前置：**

| 要求 | 说明 |
|------|------|
| **服务端加载器** | Fabric 或 NeoForge |
| **客户端加载器** | 同一个（玩家也要装） |
| **Java** | 较新版本，**装前确认** |
| **Paper/Spigot** | ❌ **不适用** |

**步骤：**

1. 下载对应你加载器和 MC 版本的 jar（Modrinth: `logistics`）
2. 客户端和服务端都放进 `mods/`
3. 重启

> ⚠️ **Modrinth 上的版本号形如 `0.8.10+mc1.21.11.fabric` / `0.8.10+mc1.21.11.neoforge`** ——注意**同一个版本号有不同加载器的构建**，**别下错**。

### 5. 这是个「全量模组」，不是小插件

**要调整预期**：

- 你是在**装一个模组生态**，不是加一个插件
- **需要玩家也装**——不装的玩家进不来（这是模组服的常态）
- 会有**自己的方块、物品、机器、管道**
- 和其他模组的**兼容性问题**是日常——**这是模组服固有的成本**

**如果你的服现在是纯 Paper，加这个意味着转型。** 不是不行，但要意识到这是**换赛道**，不是「加个插件」。

### 6. 常见坑

**装到 Paper 服上没反应**

它不是 Paper 插件。**Paper 上装不了。**

**存档坏了**

⚠️ **最严重的问题就是它。** 升级时**必须按大版本逐步升**（官方要求），**每步开一次世界**。**直接跳最新版可能坏存档。** 升级前备份。

**和 Nova 什么关系**

**本站未核实到有依赖关系。** 它是独立项目，见前面说明。

**某个机器/管道不工作**

**早期开发阶段，作者自己承认有 bug 和缺失功能。** 遇到问题查它的 issue 区。

**客户端和服务端版本不一致**

模组服的基本要求，两边必须同版本。

### 7. 什么时候别碰

- **Paper/Spigot 服** —— 直接不适用
- **不想让玩家装模组** —— 模组服的成本不只是你装一次
- **追求稳定的生产服** —— 早期开发 + 存档兼容有坑
- **只是想自动化一点** —— 完整模组生态太重了
- **存档没有备份习惯** —— 鉴于上面的存档兼容警告，**没备份习惯别碰**

### 8. 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

我们核实了它的仓库，语言文件在 `common/src/main/resources/assets/logistics/lang/` 下，**目前只有 `en_us.json`**，**没有找到中文**。

**实际情况：**

- 这个模组的界面文本（机器名、物品名、提示）目前**是英文**
- **而且它连完整的本地化机制都还在建设** ——早期开发阶段，语言文件可能随时变

**要汉化的话：**

1. 进 `mods` 所在的服务端目录找 Logistics 的资源
2. 语言文件在 `assets/logistics/lang/` 结构下
3. **要加中文需要**：`zh_cn.json`（命名按 Minecraft 模组惯例是下划线小写，但**请以它现有文件的命名方式为准**）
4. 仓库 `Indemnity83/logistics` 有 wiki（`indemnity83.github.io/logistics`），文档可能比仓库新

> **注意**：即使加了中文语言文件，**物品/方块的显示名在游戏里可能被翻译成中文或保留英文**（取决于物品是否有翻译键）。**模组的汉化没有插件汉化那么直接** —— 物品名要走 Minecraft 的翻译机制。
