## NoBuildPlus 安装教程

### 1. 它是什么（名字起得很随便，功能不是）

NoBuildPlus（中文名「别建+」）干的事一句话说完：**把「这个世界不许干什么」做成一堆开关，然后内置一个 GUI 让你点。**

它的定位是**世界管理员工具**，不是领地插件。核心操作是：

```
选一个世界 → 打开菜单 → 一堆开关挨个点 → 生效
```

| 特性 | 说明 |
|------|------|
| 内置 GUI 菜单 | 不用手改 YAML，菜单里点 |
| 模板系统 | 一个模板 = 一套规则，应用到多个世界 |
| 规则数量多 | 建造、破坏、交互、容器、实体伤害、TNT、火焰、岩浆、传送、合成、饥饿、回血……几十项 |
| 每世界独立权限 | 每个世界可以配自己的「无视权限节点」 |
| 拒绝提示 | 拒绝消息可自定义，支持 actionbar 显示、可以配音效 |
| HEX 颜色 | 1.6.40 起支持 |
| 自动补全 | 1.7.20 里 `/nbp flag [世界] [flag]` 缺参数时会提示当前布尔值 |

平台：**Bukkit / Folia / Paper / Purpur / Spigot**，MC 从 1.8 一路到 26.x。

### 2. 什么该用它，什么不该

这条线很重要，划错了你会装错插件：

| 需求 | 用哪个 |
|------|--------|
| **整个世界**禁止建造和破坏 | ✅ NoBuildPlus |
| **一块区域**禁止建造、允许成员建造 | ❌ 用 [WorldGuard](#/plugin/worldguard) |
| **玩家自己圈地**、有产权有面积限制 | ❌ 用 [WorldGuard](#/plugin/worldguard) 或 [Towny](#/plugin/towny) |
| 需要税收、居民、国战 | ❌ 用 [Towny](#/plugin/towny) |
| 出生点、大厅、剧情地图要纯净 | ✅ NoBuildPlus |

一句话：**NoBuildPlus 管「世界级开关」，WorldGuard 管「区域级权限」，Towny 管「城镇级玩法」。**

它最典型的用法是：**大厅/出生点世界全套禁止，野外世界全套允许，然后在大厅范围内再用 WorldGuard 加一条 build deny 兜底。** 这种组合比单用任何一个都干净。

### 3. 安装

1. 下载 jar 丢进 `plugins/`
2. 重启，生成 `plugins/NoBuildPlus/` 目录
3. 打开菜单开始配

可选联动：

| 插件 | 联动作用 |
|------|---------|
| [Residence](#/plugin/worldguard) | 可选，兼容 |
| Dominion | 可选，作者提到过 API 兼容（1.5.1 起要求 v3+） |
| BlockRegen | 可选 |
| ItemsAdder | 可选 |

**注意版本兼容的小版本要求**：作者在更新日志里写明，如果你装了 Dominion，需要 **v3 及以上**。这类联动插件的版本要求以官方更新日志为准，别硬装。

### 4. 菜单用法（推荐路径）

1. 进去执行 `/nbp` 打开菜单
2. 菜单里选世界
3. 挨个开关配置规则
4. 完成

菜单页数会跟着规则数量增长（1.4.6 之后菜单页数自动适配），所以规则多的时候翻页正常。

从 1.7.0 起，模板的编辑和管理也在菜单里，**不用再回 YAML 手改模板了**。

### 5. 命令

| 命令 | 作用 |
|------|------|
| `/nbp` | 打开主菜单 |
| `/nbp flag [世界] [flag]` | 设置某世界某规则的布尔值；参数不全时会提示当前值 |

> 具体的子命令划分在版本间变过（世界添加/删除、模板相关命令等）。**`/nbp` 打开菜单点点看比背命令快**，而且菜单版正是这个插件的设计意图。

`/nbp flag` 那个「缺参数提示当前值」的行为是 1.7.20 加的，改配置时很好用——它告诉你现在到底是开还是关，不用去翻 YAML。

### 7. 关键决策：模板 vs 逐世界配

模板系统（1.7.0 引入并在菜单里可编辑）是这个插件最实用的功能。

**什么时候用模板**：

```
大厅模板：全部禁止建造/破坏/交互，但保留战斗
地图模板：全禁，禁 TNT，禁火焰
野外模板：全允许
生存模板：允许建造，禁止 TNT 和火焰
```

**什么时候逐世界配**：世界少（1-3 个）且规则差异大时，模板反而是多余的一层抽象。

**新建世界的坑**：1.7.10 改了行为——**新启用的世界会跟随 `default.yml` 模板的设置**。这个改动方向是对的（以前新世界不跟模板很坑），但要知道：**你现在改 `default.yml` 只影响以后新建的世界，已有的世界不会被追溯。** 老世界要手动应用一次模板。

### 8. 权限：每世界独立无视节点

每个世界可以配自己的「无视权限节点」。设计思路是：

```
nobuildplus.world.<世界名>.build.allow  → 在 <世界名> 里可以建造
```

好处是你能做出「大厅里所有人都不能建，但 staff 在大厅能建」这种效果，而不用动 LuckPerms 的全局组。

**更稳的做法**：直接用 LuckPerms 按世界给权限，而不是用插件自带的节点。理由是 LuckPerms 的权限管理有上下文（world/group 限定），你以后调权限只有一个地方要动。两套权限系统并存是运维噩梦。

分配权限 → [权限系统设计](#/guide/permissions-design)。

### 9. 拒绝提示怎么配

拒绝消息的行为（1.4.9 起）：

- 拒绝消息可以显示在 **actionbar**（见 config.yml）
- 拒绝消息**可以配音效**

这两点很实用：actionbar 提示不刷屏，配合音效玩家立刻知道自己被拒了，比只在聊天框里冒一行字体验好很多。

> ⚠️ 具体配置键名**以你的 `config.yml` 为准**。作者多次更新中调整过消息显示方式，1.4.9 之前和之后的键名/行为不同。

### 10. 汉化

> **本站未核实到该插件的官方中文语言文件机制，若要汉化需自行确认。**

不过这个插件的汉化有个**明确的有利条件**：它有 GUI 菜单，菜单标题、按钮名称、flag 的显示名这些文本是可以在语言文件里改的。

需要汉化的地方：

| 改什么 | 大致位置 |
|--------|---------|
| 拒绝提示消息 | `config.yml` 里的消息段落 |
| GUI 菜单标题 / 按钮名 | 语言文件 |
| flag 的显示名称 | 语言文件 |
| 模板名称与描述 | 模板配置 |

**一个不能忽略的事实**：1.6.40 起，插件**第一次加载时会自动把 `config.yml` 里的语言设成系统语言**。也就是说中文系统环境下首次生成的配置可能已经是中文了。但：

> ⚠️ **这只影响「自动生成的默认值」，不代表所有文本都有中文翻译。** 打开语言文件逐条看，缺的地方自己补。**以实际文件为准**，本站不提供逐键对照的汉化文件。

### 11. 常见坑

**老版本服务器启动就报错**

作者在更新日志里专门提过这个问题，并且明确建议：**服务端 MC 版本低于 1.15.2 的，用 1.4.8 版本**。原因是 1.4.8 之后的版本会修掉低版本 GUI 相关报错。低版本服别硬上最新版。

**控制台刷屏**

历史上多个版本有过控制台刷消息的 bug（`fire-spawn`、`wind-charge`、1.7.10 修了一个安全漏洞导致的刷屏）。**遇到刷屏先看版本号**，往上更新通常就解决了。

**flag 不生效**

三个方向查：

1. flag 名拼错了（作者新增 flag 时会提到需要删除 `flags.yml` 让它重新生成，**新增 flag 版本一定要考虑重建这个文件**）
2. 玩家有对应的「无视权限」
3. **另一个保护插件也在管这块**——这是最常见的。WorldGuard 的 build deny 和 NoBuildPlus 的禁建造同时生效时，日志里不会互相提示，你只会觉得「flag 明明开了还是能建」。**两个保护插件不要叠在同一个世界上。**

**新世界规则不对**

1.7.10 之后新世界跟 `default.yml`。如果 `default.yml` 本身没配好，所有新世界都错。检查 `default.yml`。

**TNT 禁了但凋灵还能炸**

`wither-destroy` 只管凋灵造成的破坏，不管凋灵造成的伤害。两个是分开的 flag。1.7.1 修过相关问题，往新版升。

**`/nbp flag` 提示看不懂当前状态**

1.7.20 的新特性：参数不全时直接告诉你当前布尔值。养成用这个命令查状态的习惯，比开 GUI 快。
