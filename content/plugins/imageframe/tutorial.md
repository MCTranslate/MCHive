## ImageFrame 安装教程

### 1. 它解决什么问题

想在服务器里展示一张图——公告图、玩家作品、服务器 logo、店铺广告——原版做不到。物品展示框只能放物品和方块模型。

ImageFrame 的做法：**用一整面地图墙拼出图像**。

原理是把一张图切成若干个方块，每块渲染成一张 `minecraft:map`，再把展示框按正确朝向摆成平面。玩家从正面看过去，就是一张完整的图。

**这不是"加载图片"式的 GUI 屏**——它是真的**方块和物品**。所以：

| 特点 | 后果 |
|------|------|
| 玩家可以打掉它 | 需要保护（领地保护 / 权限方块） |
| 地图有数量上限 | 大图很吃物品栏和磁盘 |
| 只能从固定方向看 | 是墙上的画，不是全息投影 |
| 存档跟着世界走 | 服务器关了还在 |

### 2. 版本要求

**支持 MC 1.16 - 26.3**，需要 Spigot / Paper 系。

**1.16 是下限。** 更老的版本地图分辨率和 API 有差异，插件直接跑不了。

### 3. 它不依赖外部资源（这点是优势）

很多同类方案要玩家自己搞图床、或者依赖一个外部渲染服务。**ImageFrame 是在服务端本地生成并应用的**——图片由你提供（本地文件），生成过程在服务器上完成。

实际影响：

- **不需要第三方服务**，不存在别人的服挂了导致你挂
- **图片自己保管**，服务器关了不影响
- 代价是**得在服务器上放图片源文件**，且**换图要重新生成**

### 4. 安装

1. 下载 jar 放进 `plugins/`，重启服务器
2. 生成 `plugins/ImageFrame/`
3. 准备图片源文件
4. 用命令生成画框

### 5. 生成画框

命令形式大致是「指定图片来源、尺寸、朝向」。**具体参数写法以你版本的 `/imageframe` 帮助输出为准**——这类命令参数通常不少（图片来源、宽高、方向、光照），本页不逐条默写免得写错。

**流程一般是：**

```
1. 站在你想放画的位置
2. 看向要贴图的那个面
3. 执行生成命令，指定图片和尺寸
4. 插件在那个面上铺地图方块
5. 自己补上展示框（部分版本会自动放）
```

> ⚠️ 方向这一项最容易搞错。**站错位置或看错方向，画框会贴到墙上、地下、或者你背后。** 生成完不对就拆了重来，比挪一大片方块省事。

### 6. 分辨率与规模

**地图分辨率决定图片清晰度，但成本是平方级增长。**

| 尺寸 | 地图数量级 | 观感 |
|------|----------|------|
| 小 | 几块到一二十块 | 远看清楚，近看马赛克 |
| 中 | 几十块 | 正常观影距离够用 |
| 大 | 上百块 | 清晰，但吃资源、吃存档 |

**尺寸不是越大越好。** 一张 32×32 的图就是**上千个地图物品**——

- 背包塞不下（要用 `/give` 分批给）
- 世界存档明显变大
- 区块加载时会给客户端带来卡顿

**实际建议：先做小尺寸试效果，确认位置对了再做大图。**

### 7. 保护（必做）

画框是**真方块真物品**。不保护的话：

-  Grief 玩家拆了你的公告图
- 熊孩子把地图捡走塞进箱子
- 有人把展示框拆了，地图掉落，等于**你的图片资源被人搬走**

**至少要做：**

| 做法 | 适用 |
|------|------|
| 领地保护（WorldGuard） | 你已经在用领地保护 → 把画框区域划进去 |
| 权限方块（ GriefPrevention / 地标插件） | 简单公告图用这个最省事 |
| 区块保护类插件 | 服务器级别的兜底 |
| 限制方块交互权限 | 对应版本的交互权限节点（以插件实际为准） |

**只靠「不设保护」是赌运气。** 画框的物品是可以被捡走的。

### 8. 常见坑

**图贴到墙里 / 方向错了**
生成时的站位和朝向搞错。**拆掉重来**，比用 WorldEdit 挪快。

**图很模糊**
- 分辨率不够（地图数量太少）
- 玩家离得太近看——**地图贴图的本质就是马赛克，近看必然糊**
- 光照不对：展示框在暗处，图会偏暗。**放灯或者用光照等级参数**

**生成时卡死 / 卡顿**
大图一次性生成会集中计算。**在没人在线的时候生成大图。**

**地图物品数量超背包上限**
大图会超。分批用 `/give` 拿，或者在生成时就规划好尺寸。

**重启后图不见了**
- 展示框里的地图被其他插件清理（比如某些清理插件会删空展示框）
- 世界保存异常
- **检查有没有「清理闲置物品 / 清理展示框」的插件在跑**

**玩家拆了展示框，地图掉了**
见第 7 节。这不是 bug。

**和其他图片/展示类插件冲突**
市面上有若干同类插件（部分需要客户端模组）。**同时装会出现图错乱、方块互相覆盖。** 同时只留一个。

### 9. 关于汉化

**本站未核实到 ImageFrame 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/ImageFrame/`，看有没有 `lang/`、`messages` 之类的目录或文件
2. 用编辑器搜配置文件里有没有 `message`、`language`、`locale` 段落
3. 图片本身的文字**不走插件汉化**——图上的中文得你在做图时自己写进图片源文件里
4. 如果只有很少的提示消息，**直接用其他插件的消息接管/自定义功能**可能比汉化它更省事

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **想展示动态内容（滚动字幕、实时排行）** —— 它是静态图，做不了动态
- **想放超大图** —— 成本太高，不如做一个网页地图然后放个链接牌子
- **服务器很小、玩家会乱拆** —— 保护没做好就是给玩家送素材
- **纯生存服** —— 建筑装饰需求本来就不强

### 11. 更好的替代思路

先想清楚你到底要什么：

| 想要的效果 | 更合适的方案 |
|-----------|------------|
| 公告图 / 赛季海报 | ✅ ImageFrame 挺好用 |
| 实时更新的排行榜 | 记分板 / Tab 插件，或 hologram 类插件 |
| 全景大图展示 | 网页地图 + 一个牌子放链接 |
| 动态展示（倒计时、活动） | hologram / 展示框 + 切换命令 |
| 服务器 Logo | **一个牌子就够了**，别为了 logo 贴一百张地图 |

**ImageFrame 解决的是「静态图片上墙」。** 需求越接近「静态图片」，它越合适。
