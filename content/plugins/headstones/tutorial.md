## ⚠️ 先读这一段：Headstones 是有代价的

这个插件解决的是一个真实问题，但它同时**制造了两个新问题**。装之前先想清楚你能不能接受。

| | 说明 |
|---|---|
| ✅ **它解决的** | 死后掉落散落一地，**被别人捡走**。尤其混合服务器（有人 PvE 有人 PvP），你辛辛苦苦攒的装备被路过的人顺走 |
| ⚠️ **它带来的 1** | **PvP 变复杂** —— 想拿回自己的东西，得先去找到头石并打碎它。「杀了就能抢」这个直白规则没了 |
| ⚠️ **它带来的 2** | **刷物空间** —— 头石是个容器，容器的开取逻辑边界多，容易被做出重复结算的漏洞 |

**这不是「无脑装上就赚」的插件。** 硬核抢夺类 PvP 服装它，等于自废武功；纯 PvE 装它，收益也不大。

官方仓库：<https://github.com/alex3025/Headstones>

### 1. 它到底改变了什么

```
原版：玩家死亡
  → 物品变成掉落物实体，散落在死亡点
  → 谁路过谁捡走
  → 掉在岩浆里 / 掉进虚空 / 被活塞推走 = 永久损失
```

```
Headstones：玩家死亡
  → 物品被收进一个「头石」方块，放在死亡点
  → 只有玩家本人能打开
  → 别人要拿，得先打碎这个方块
```

**注意最后那一步。** 「只有本人能开」不等于「绝对安全」：

| 情况 | 结果 |
|------|------|
| 别人打碎头石 | 物品掉出来 → **能被捡走** |
| 别人打碎后**没来得及捡** | 又散落一地，回到原版状态 |
| 头石被活塞推出掉进虚空 | 物品可能一起没了 |

**所以准确的说法是：它把「捡漏」变成了「有门槛的捡漏」。** 不是「死亡不掉落」。

### 2. 什么时候真的需要它

| 场景 | 需不需要 |
|------|---------|
| 混合服，死亡掉落价值高，装备被顺走过 | ✅ **这就是它存在的理由** |
| 玩家掉进虚空/岩浆就永久损失装备，怨气大 | ✅ 有帮助 |
| 硬核 PvP，「杀你就要能抢你东西」是核心规则 | ❌ **直接破坏核心玩法** |
| 纯 PvE 服，玩家之间几乎不接触 | ⚠️ 收益一般 |
| 死亡本身不痛（玩家等级低、装备不值钱） | ⚠️ 收益不大 |

### 3. 安装

1. 从 <https://github.com/alex3025/Headstones> 或 Modrinth 下载
2. 丢进 `plugins/`
3. 启动，看控制台确认加载成功
4. **读一遍生成的配置文件** —— 这个插件的选项比多数同类插件多，值得看完

> ⚠️ 支持区间是 **MC 1.18 - 1.21.3**。较新的 MC 版本请先确认 jar 的实际支持范围，**别假设它会自动跟进**。

### 4. 头石是「谁都能打」的方块

**这一点是设计核心，也是最大的坑。**

因为头石本身是个方块，**任何玩家都能打碎它**。所以它的安全性来自这个机制：

```
只有你能打开  →  但
任何人都能打碎 →  打碎后物品散落 →  谁抢到是谁的
```

**这意味着两件事：**

1. **如果头石在敌人地盘，你要冒险去打碎它** —— 这是 PvP 博弈的新层
2. **你自己也得去打碎自己的头石才能拿回东西** —— 有一种设计是让头石自动在你靠近时打开，那种更友好；另一种是必须手动打碎。**装完先测自己能不能顺利拿回装备**，不同版本行为可能不同。

### 5. ⚠️ 刷物风险：真实存在的漏洞面

**这个插件给作弊者留了空间，而且比一般插件明显。** 原因链条是清楚的：

```
头石 = 容器
容器 = 有开/取/关三个独立状态
容器 = 插件要处理的事件类型变多
事件类型变多 = 边界情况变多
边界情况变多 = 重复结算/复制出错的可能变多
```

**常见的攻击面**（不是指「某个具体漏洞」，而是这类插件的结构性弱点）：

| 攻击方向 | 原理 | 表现 |
|---------|------|------|
| **重复结算** | 同一个头石被触发多次开取 | 一份装备变两份 |
| **时序竞态** | 快速开→取→关、或断线重连 | 物品被结算两次 |
| **跨世界 / 维度移动** | 带着未结算的头石跨维度 | 物品状态不同步，重复入账 |
| **区块卸载** | 站在区块边界开取 | 容器状态错乱 |

**这不是说它一定有漏洞，而是说这类插件的架构天然容易被做。** 处理办法：

- **核心保护插件照装不误** —— 至少保证管理员能回滚
- **上监控** —— CoreProtect 之类，记录方块的放置与容器交互（见 [CoreProtect](#/plugin/coreprotect)）
- **有经济系统的服，开箱/取物相关的异常行为要能被审计**
- **发现异常立刻回档** —— CoreProtect 的回滚在这里是保命的

> 如果你的服**没有**任何回滚手段（没装 CoreProtect 之类），我建议**先装回滚插件再装这个**。顺序反了出事你只能手动清。

### 6. 和其他死亡相关插件的冲突

| 插件 | 一起装会怎样 |
|------|-------------|
| [AxGraves](#/plugin/axgraves) | **都做同一件事（把掉落封进方块），别同时装** |
| [CoreProtect](#/plugin/coreprotect) | ✅ 配合得好，是它的补救措施 |
| EssentialsX | 一般不冲突 |

**死亡处理类插件是「一个玩家只能有一个」的类型。** 两个都想装的话，先确认它们是否声明了互相的软依赖，以及实际行为是不是被后者覆盖。

### 7. 关于汉化

**本站未核实到 Headstones 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/Headstones/`（或类似目录名），**搜文件名**找 `lang`、`locale`、`messages`、`zh`
2. 打开配置，**搜关键词** `message`、`locale`、`lang`、`text`、`display`
3. 分清文本类型：

| 文本 | 可能走哪 |
|------|---------|
| 「你获得了自己的物品」这类提示 | 可能在语言文件里 |
| **头石方块的名字** | **很可能走 Minecraft 本体语言**（"Headstone" 是个物品名）—— 改这个可能要靠物品改名而不是改插件 |
| 头石上可交互的告示牌文字 | 可能读玩家名或自定义文本，**不一定是语言文件** |

> 「头石的名字显示成英文」这类问题**十有八九不是这个插件的锅**——方块/物品的显示名走的是 Minecraft 自己的语言表。先分清这一点，能省掉很多无用功。

4. 全都搜不到语言文件 → 消息很可能硬编码在 jar 里

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 8. 什么时候别用它

- **硬核 PvP / 抢夺装备是核心玩法** —— 别装，它直接改写这个规则
- **同时装了两个死亡处理插件** —— 先解决冲突
- **服上没有回滚手段** —— 先装 CoreProtect
- **想给玩家「死亡即惩罚」的紧张感** —— 它把紧张感削掉了，这可能是你要的，也可能不是
