## BetterMessages 安装教程

### 1. 它改的是什么

原版消息就三行，白字、无格式、不能关：

```
Player123 joined the game
Player123 left the game
Player123 switched from world_nether to world_world
```

BetterMessages 把这三类事件接管过来，核心是**同一件事可以配很多条，按条件挑一条发**：

| 能力 | 说明 |
|------|------|
| 多条候选 | 同一事件配一组消息，随机抽一条 |
| 首次/里程碑 | 只在第 1、5、10 次之类触发（`priority` + 次数判断） |
| 观众分组 | 一条消息可以指定发给：全服 / 只有离世者 / 只有加入者 / 特定权限组 |
| 前缀后缀 | 消息里带 EssentialsX 前后缀 |
| 多行 | 一条消息可以拆成多行发 |
| 颜色 | Bukkit 颜色码 + Hex |
| 占位符 | `{player}` `{from}` `{to}` |
| 屏蔽 | 任何一条都能整个关掉，包括原版那行灰字 |

> **注意它和 EssentialsX 的关系**：BetterMessages 的自我定位是「EssentialsX 自定义 join 消息的替代品」。两者功能重叠，**同时开会出现消息重复发送**——EssentialsX 发一遍，BetterMessages 再发一遍。选一个。

### 2. ⚠️ 版本区间数据说明（重要）

本站记录的区间是 **MC 1.8 - 3.3**，但这个上限 **`3.3` 明显不是 Minecraft 版本**——它混入了插件自身的发布版本号（Modrinth 上确实有 `3.3.0` / `3.3.1` / `3.3.2` 这几个发布）。

真实的 MC 支持上限落在 **1.20.x 一档**（3.3.x 时期发布）。也就是说：

- 你看到的「支持到 3.3」不代表支持到 MC 3.3
- **这个区间来自注册表元数据，可能不准确，以官方页面为准**

装之前去 Modrinth / SpigotMC 看一眼实际的版本列表，别照着「3.3」去理解。

### 3. ⚠️ 已知限制：代理端只在 BungeeCord 有效

BetterMessages 分服务端版和代理版。**代理版的历史实现只覆盖 BungeeCord / Waterfall**，这是它的已知短板：

| 部署 | 服务端 jar | 代理 jar | 跨服切换提示 |
|------|-----------|---------|------------|
| 纯 Spigot / Paper | ✅ | — | 不适用 |
| BungeeCord / Waterfall 群组 | ✅ | ✅ | ✅ |
| Velocity 群组 | ✅ | ⚠️ 见下 | ⚠️ |

> 3.3.0 的更新日志里提到了 Velocity 相关支持，但同一份日志也写着「还没有正式文档，有问题去 Discord」。**Velocity 下的行为请自行实测验证**，不要假设它和 BungeeCord 下表现一致。

**如果你就是 Velocity 群组**：跨服切换提示这块大概率不工作，或者行为诡异。这不是你能配置修好的，是插件侧的限制。

### 4. 安装

服务端端和代理端是**两个不同的 jar**，别混装：

```
服务端：BetterMessages-<版本>.jar        → plugins/
Bungee：BetterMessagesBungeecord-<版本>.jar → plugins/
```

丢进 `plugins/`，重启。生成配置目录后按注释改。

> 群组服**两边都要装**：代理端负责跨服切换，服务端端负责本服内的加入/离开/世界切换。只装一边会有一半事件没消息。

### 5. 内置占位符

只有三个，别指望更多：

| 占位符 | 含义 | 适用事件 |
|--------|------|---------|
| `{player}` | 事件主角，带前缀后缀 | 全部 |
| `{from}` | 离开的世界名 | 仅世界切换 |
| `{to}` | 进入的世界名 | 仅世界切换 |

外部占位符（PlaceholderAPI）是否可用，取决于版本和平台，**没有核实到官方明确说明**。要用 PAPI 的话自己装上试，别默认它能工作。

### 6. 世界切换提示的一个坑

玩家在群组服里从生存服切到小游戏服，**生存服的人也会看到这条切换提示**。3.3.x 把服务器切换消息改成发给所有服务器，为的是让大厅服的人也能看到「某人去小游戏了」。

如果你觉得吵，**得靠观众分组过滤**，没有「只发给目标服玩家」这种开关。这是设计取舍，不是 bug。

### 7. 常见问题

**消息重复两遍**
EssentialsX 和 BetterMessages 同时生效。二选一，或者关掉 EssentialsX 的自定义 join/leave 消息。

**原版灰字还在**
BetterMessages 有个「静默加入/退出时不显示原版消息」的修复项。如果灰字还在，检查你的配置里是不是显式开了原版消息，或者是不是装了别的插件在发。

**世界切换没反应**
检查两件事：是不是多世界世界名对不上；`{from}` / `{to}` 只在**世界切换事件**里有效，放在加入消息里不会替换。

**改完配置不生效**
用重载命令而不是重启。有专门的重载支持，也可以配 BetterReload 插件联动。

**消息计数不准**
更新日志里明确写过「消息计数功能可能有问题」。别拿它做精确逻辑。

### 8. 什么时候别用它

- **只想要一条固定的加入提示** → 服务器properties 或 EssentialsX 够了
- **Velocity 群组且依赖跨服提示** → 它不满足你
- **要深度可配的广播系统** → 这不是广播插件，能力边界在 join/leave/世界切换这几件事上

### 9. 关于汉化

**没有核实到 BetterMessages 的官方中文语言文件机制。**

不提供下载，也不写猜测的语言文件路径——给一个插件不读的文件，读者照做后不生效，比不给更糟。

引导式排查步骤：

1. 下载 jar，用解压工具看 `resources/` 下有没有 `lang/`、`locale/`、`messages_*.yml` 之类目录
2. 装上后进服敲一次加入/离开，看控制台和 `plugins/` 下新生成的目录
3. 去看 Modrinth 项目页的 Changelog 和评论区，作者提到过消息相关改动
4. 消息内容本身写在配置里——**这部分一定能改中文**，只是键名和层级要以你手上那份配置文件注释为准
