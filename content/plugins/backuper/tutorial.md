## ⚠️ 先说风险：备份能把你的硬盘撑爆

**这一节放在最前面，因为这是 Backuper 类插件最主要的翻车方式。**

```
世界大小 8 GB
每小时备份一次，保留最近 24 份 → 8 × 24 = 192 GB  ⚠️ 硬盘没这么大
每天备份一次，保留最近 30 份   → 8 × 30 = 240 GB  ⚠️ 还是爆
```

**更危险的是：备份通常存在和世界同一台机器上。**

- **磁盘不够时，备份会先把磁盘写满，然后世界文件写不进去**
- 表现是服务器卡死、存档损坏、世界数据丢失
- **「我一直在备份」在这种情况下反而加速了数据丢失**

**配置前必须做的事：**

| 检查 | 为什么 |
|------|-------|
| 算一遍 `世界大小 × 保留份数` | 这是最直接的爆盘原因 |
| 确认备份输出目录在**独立磁盘**或**远程存储** | 和世界同盘 = 备份帮倒忙 |
| 确认有清理旧备份的机制 | 手动删会忘 |
| **先手动跑一次，测真实占用** | 估的和实际差很多，尤其是压缩/包含数据库时 |

**本页的底线：没算过空间，不要开定时自动备份。** 先手动跑几次，测出真实体积，再定策略。

## Backuper 安装教程

### 1. 它的真实价值：远程备份

**「有备份」和「有远程备份」是两件完全不同的事。**

看这张表就明白了：

| 事故类型 | 本地备份（同一台机器） | 远程备份（FTP / 云盘） |
|---------|---------------------|---------------------|
| 玩家误删建筑 / 管理员手滑 | ✅ 能恢复 | ✅ 能恢复 |
| 某个插件把世界改坏 | ✅ 能恢复 | ✅ 能恢复 |
| **服务器磁盘坏掉** | ❌ **备份一起没了** | ✅ **还在** |
| **机房起火 / 数据中心故障** | ❌ **一起没了** | ✅ **还在** |
| **误删整个服务器目录** | ❌ 一起没了 | ✅ 还在 |
| **勒索软件 / 服务器被入侵** | ❌ 备份可能被一起加密 | ✅ 远程副本可能安全 |
| 服务商跑路 | ❌ 一起没了 | ✅ 还在 |

**所以：只备份到同一台机器的同一块盘，值不了这个插件的钱。** 真正的价值在 FTP 和 Google Drive 那两条路。

**代价也在这里：** 远程存储要么花钱（云盘），要么占你的带宽和时间（传大文件到 FTP）。**每次备份一个 8 GB 的世界传上去，几十兆的上行带宽要跑很久。**

### 2. 支持的备份目标

| 目标 | 适合 | 注意 |
|------|------|------|
| **FTP** | 有自己的 NAS / 家用服务器 / 另一台 VPS | 带宽成本自己承担 |
| **Google Drive** | 不想自己搞存储、备份量不大 | 有 API 配额限制；大世界要分片 |

**FTP 方案的现实提醒：**

- **传大文件很慢。** 8 GB 的世界 + 20 Mbps 上行 ≈ **一小时以上**
- 备份任务跑太久会一直占着连接和资源
- **不要在游戏高峰时段跑**——玩家会感觉卡（尤其是打包世界时）
- FTP 密码**明文存在配置文件里**，配置文件权限要收紧

**Google Drive 方案的现实提醒：** 免费空间有限，超了要付费；**API 有配额**，传太多会触发限制；超大世界需要规划分片。

### 3. 版本与依赖

**支持 MC 1.13 - 26.3。**

- 无硬依赖
- 可选：数据库相关插件（如果你的服用外部数据库，**数据库要单独备份**，见第 5 节）

### 4. 备份什么

| 内容 | 该不该备份 | 理由 |
|------|-----------|------|
| 世界目录 | ✅ **必须** | 存档本体 |
| `plugins/` 下的配置 | ✅ **应该** | 配置丢了要重配半天 |
| 权限数据（LuckPerms 等） | ✅ **应该** | 权限组没了等于重开服 |
| 经济 / 领地数据 | ✅ **应该** | 玩家余额、领地没了会出事 |
| 玩家数据 | ⚠️ 看情况 | 数据量大，且**数据库通常已经包含** |
| **日志 / 缓存 / 崩溃报告 / 临时文件** | ❌ **别备份** | 纯浪费空间，能重新生成 |

**❌ 那行是「爆盘」的主要贡献者。** 日志和缓存加起来可能比世界还大，而且**完全没有备份价值**。

> **排除列表是必须配的**，不是可选优化。不排除日志和缓存，你的备份体积可能翻倍甚至更多。

### 5. ⚠️ 数据库：备份的盲区

**这一条是很多人漏掉的，也是最致命的。**

如果你的服务器用了**外部数据库**（MySQL / MariaDB / PostgreSQL）存权限、经济、领地数据——

**备份 world 目录救不了这些数据。**

```
世界文件被恢复 → 玩家回到上次的位置和背包
                → 但权限、经济、领地全是数据库里的当前状态
                → 数据对不上，玩家投诉「我明明有 10 万金币怎么变 0 了」
```

**如果用外部数据库，数据库必须有独立的备份机制。** 不是 Backuper 的活，是 MySQL 自己的备份（mysqldump、定时任务、或云数据库的自动快照）。

**如果数据库是 SQLite 文件**（直接放在插件目录里），备份 `plugins/` 就等于备份了数据库——但**要小心备份时数据库正在写入**，快照可能不一致。**最稳的做法是备份前短暂停服。**

### 6. 安装与配置流程

```
1. 下载 jar，放进 plugins/，重启
2. 生成 plugins/Backuper/ 目录
3. 配置备份目标（FTP 或 Google Drive 的连接信息）
4. 配置备份内容与排除列表
5. 【手动跑一次备份，测真实体积和耗时】  ← 别跳过
6. 据实调整保留份数
7. 再考虑开定时
```

**第 5 步是本页最想强调的。** 手动跑一次，你会得到两个关键数据：

- **实际占用了多少空间**（估的值基本不准）
- **实际跑了多久**（决定能不能在高峰期跑）

**拿这两个数字去定保留策略，别靠猜。**

> 配置项的**具体键名以你手上版本的配置文件注释为准**。本页不列具体键名——这类插件的配置结构随版本变过，写错的键名你配了等于没配。

### 7. 定时策略

| 要点 | 说明 |
|------|------|
| **避开高峰** | 备份会占 IO 和带宽，别在玩家在线高峰跑 |
| **避开自动保存** | Minecraft 会定期保存世界，撞上会互相拖慢 |
| **保留份数别贪多** | 3-5 份通常够。10 份以上是空间灾难 |
| **上一轮跑完才开下一轮** | 别让两个备份任务叠着跑 |

**一个务实的组合：** 每天凌晨低峰跑一次完整备份，保留最近 3-5 份。日常小误操作用 CoreProtect 之类的方块记录兜，**别指望全量备份能覆盖「误删三块石头」这种粒度**。

### 8. ⚠️ 没有验证过的备份等于没有备份

**这是最重要的一条，也是最容易被跳过的一条。**

备份成功的日志 ≠ 备份可用。**你必须确认它能恢复。**

**上线前做一次完整的恢复演练：**

```
1. 找一个测试环境（或者本地临时开一台服）
2. 把备份下载下来
3. 完整恢复
4. 进游戏确认：地形对不对、玩家数据在不在、权限经济在不在
5. 记录恢复耗时（这决定真出事时你能等多久）
```

**演练里最常见的失败：**

| 现象 | 原因 |
|------|------|
| 地形恢复但玩家位置错乱 | 备份是几个小时的旧数据，正常的 |
| 权限/经济全没了 | **数据库没备份**（见第 5 节） |
| 插件配置全丢 | 备份排除列表把 `plugins/` 排除错了 |
| 文件解不开 / 传输中断 | 备份时服务器被关了，**没做一致性处理** |
| 恢复了但服务器起不来 | 版本不对、配置文件跨版本不兼容 |

**没有演练过的备份，只是让你心理上安心的字节。**

### 9. 常见坑

**磁盘满了，服务器卡死甚至世界损坏**
见开头。**先算空间，再开定时。** 备份是往磁盘里塞东西，配置不当它会害你。

**备份跑完之后服务器卡了好一阵**
正常现象——打包和传输都吃 IO。**但如果卡到影响玩家，说明时段选错了。**

**备份传到一半断了 / 任务叠着跑**
FTP 上行带宽不够，或定时间隔短于单次耗时。**设一个「上一轮跑完才开下一轮」的机制。**

**数据库数据不在备份里**
见第 5 节。**用外部数据库就要单独备份数据库。**

**把 logs 一起打包了**
见第 4 节。**排除列表必须配。**

**FTP 密码泄露 / 配置文件被传到公开地方**
**密码是明文的。** 配置文件不要 commit 到公开仓库，不要贴到论坛。**这台 FTP 账号只给一个写目录权限。**

**服务器被入侵，备份也一起没了**
同盘备份就是这个下场。**这是必须用远程备份的核心理由。**

### 10. 配套：CoreProtect 要一起用

| | Backuper | CoreProtect |
|---|---|---|
| 粒度 | 全量（整个世界） | 细粒度（谁动了哪块） |
| 响应速度 | 慢（要解包整个备份） | **快（当场回滚）** |
| 适合 | 灾难恢复 | 日常误操作 |

**实践上：日常用 CoreProtect 解决「谁拆了我的墙」，Backuper 解决「服务器没了」。** 只装一个都不够。
