## PlayerTitle 安装教程

### 1. 它是什么

PlayerTitle 是**完整闭环**的称号插件：管理员建称号 → 玩家在商店买 → 玩家在仓库切换当前佩戴的称号 → 称号可以带属性 BUFF 和专属粒子。

和 [MythicPrefixes](#/plugin/mythicprefixes) 那类「只发牌、渲染自理」的框架型插件相反，PlayerTitle 是**打包型**：商店、仓库、管理 GUI、称号卡都自带。

| 能力 | 说明 |
|------|------|
| 三处显示 | 聊天栏、Tab 列表、玩家头顶，**三个开关独立控制** |
| 称号商店 | 内置 GUI，可按类型分类展示不同商店页面 |
| 称号仓库 | 玩家持有多称号时自由切换当前佩戴的 |
| 管理 GUI | 增删改称号不用手改文件 |
| 称号卡 | 固定称号卡 + 随机称号卡，使用后获得对应天数的限时称号 |
| 称号 BUFF | 可绑多种属性来源：AttributePlus、SX-Attribute、原版药水、MMOItems 属性、怪物休战 |
| 粒子特效 | 每个称号可配专属粒子，佩戴时环绕显示 |
| 稀有度 | 支持 RGB 渐变、16 位颜色 |

### 2. 适合谁 / 不适合谁

| 适合 | 不适合 |
|------|--------|
| 想要「玩家能自选称号」的中长期 RPG 服 | 只想给少数人挂个固定头衔（用权限插件 + 显示插件更快） |
| 打算做赛季限定称号、活动称号体系 | 追求极致轻量（带商店+仓库+GUI，比裸框架重） |
| 中文服，需要大量中文称号文本 | 纯生服（大量玩家在城镇里切称号是有风险的，见下文） |

**说一个真实的坑**：头顶称号 + 粒子是**所有人可见**的。在人多的主城，一个玩家挂着全屏粒子称号进出，等于持续给所有客户端渲染压力。这种称号最好做成「只在特定区域显示」，或者干脆不给普通玩家可自由切换的粒子称号。

### 3. 前置条件

**全部是可选的**，不装也能跑，装了解锁对应功能：

| 插件 | 作用 |
|------|------|
| PlaceholderAPI | 变量（其他插件读称号信息靠它） |
| Vault + 经济插件 | 用金币买称号。Vault 后端要接 EssentialsX / CMI 之类 |
| PlayerPoints 3.0.0+ | 用点券买称号 |
| PlayerCurrency 1.0.3+ | 多货币支持 |

存储：支持 **MySQL** 和**本地 SQLite**。

> 多服（群组服）必须用 MySQL。SQLite 是单文件本地存储，跨服读不到，称号数据会分裂。这个没得商量。

### 4. 安装

1. 确认装了 [LuckPerms](#/plugin/luckperms)（称号管理权限靠它）
2. 下载 jar 丢进 `plugins/`
3. 重启，生成 `plugins/PlayerTitle/`
4. 想要「玩家在自己手机上编辑称号文本」这类需求 → 看 [Geyser 基岩玩家](#/guide/geyser-bedrock)

### 5. 快速上手

推荐路径是**先用命令建一个称号试试手感**，别一上来就钻配置文件：

```
/title            # 主命令，各版本子命令略有差异
```

> 具体的子命令语法在版本间有增删（获取指定称号卡、随机称号卡、强制切换等都是不同版本加的）。**进游戏敲主命令看内置 help 最准**，本站不列具体参数，避免你照抄报错。

面板路径：

| 界面 | 谁用 |
|------|------|
| 称号管理 GUI | 管理员，浏览器里增删改 |
| 称号商店 GUI | 玩家，按类型分页 |
| 称号仓库 GUI | 玩家，切换当前佩戴 |

### 6. 关键配置思路

不写具体键名，写你要做决定的地方（键名以实际 config 为准）：

**① 三处显示开关**

这是最该先想清楚的。三个开关分别是「聊天栏」「Tab 列表」「玩家头顶」，它们各有代价：

| 位置 | 好处 | 代价 |
|------|------|------|
| 聊天栏 | 所有人看得到，氛围感最强 | Tab 刷屏时很乱 |
| Tab 列表 | 干净整齐 | 玩家不一定注意到 |
| 头顶 | 沉浸感最好 | 别人屏幕小一点就看不见；最吃渲染性能 |

**建议**：Tab 列表常开，头顶只给少数高级称号开，聊天栏开但限制称号文字长度。

**② 称号获取方式**

四种并存，互不冲突：

| 方式 | 实现路径 |
|------|---------|
| 商店购买 | 商店 GUI → Vault / PlayerPoints / 物品 / 称号币 / 权限 五种支付通道 |
| 活动获取 | 发放称号卡物品 |
| 限时称号 | 称号卡使用后按天数生效，到期失效 |
| 管理员直接给 | 命令发放 |

**注意商店的「多支付通道」不共存**。选 Vault 就得先有经济，选物品就得设计好定价物品。这是要开服前定的，不是上线后能随便切。

**③ 称号 BUFF 选哪个类型**

5 种 BUFF 来源，选错的代价是性能或兼容性：

- **原版药水效果** — 最省事，无需额外插件，但能给的属性最少
- **AttributePlus / SX-Attribute** — 适合已经在用属性系统的服
- **MMOItems 属性** — 已经在跑 MMOItems 体系的服选这个
- **怪物休战** — 反过来降低怪物仇恨，防熊型称号

一个称号绑 1 个或多个 BUFF。**别贪多**——BUFF 越多，属性系统的每次重算成本越高。属性计算走 [性能调优](#/guide/performance-tuning) 那篇算一下。

**④ 数据安全**

支持自动全量备份到 `backUp` 文件夹。**开服第一天就去 config 里把备份打开**。称号数据丢了是玩家投诉级的事故。

### 7. 汉化

> **本站未核实到该插件的官方中文语言文件机制，若要汉化需自行确认。**

需要改的中文文本基本都在这几个地方：

| 位置 | 改什么 |
|------|--------|
| 称号名称 | 建称号时自己填，直接写中文 |
| 称号描述 / Lore | 同上 |
| 商店分类标题 | 商店 GUI 配置 |
| 菜单标题 | GUI 配置 |
| 购买/获取成功提示 | 消息配置段落 |

**它的汉化友好度其实很高**：消息文本和 lore 的自定义度官方称接近 100%，而且从 4.12.0 起支持 MiniMessage——**这意味着你可以用 MiniMessage 标签写颜色，而不是只能在 `&` 颜色码里挑**。渐变中文称号靠这个做。

打开配置目录搜 `messages` / `lang` / `locale` 之类段落确认还有没有别的文本，**以实际文件为准**。

### 8. 常见坑

**玩家称号全没了**

SQLite + 多服，或者数据库连接断了。去查 `backUp` 目录恢复。**这就是为什么第 6 节让你第一天就开备份。**

**Tab 列表被称号撑爆，一堆人挤在一起**

Tab 称号关掉，或者限制称号长度。这一条在人多的时候特别明显。

**改名之后找不到称号**

4.0.0 起数据按 **UUID** 存储，所以改名不会丢称号——这是好事，但意味着你**不能靠「删玩家数据」来重置别人的称号**，得用管理命令。

**删称号连带把 BUFF 留在身上**

删除称号会关联删除购买记录和称号 BUFF，这是设计如此。但如果某个 BUFF 是别的插件通过其他途径给的，清理会漏。反过来，「删称号 BUFF」只移除该称号关联的 buff——手动戴的同名效果可能被一起清掉。删之前让玩家重进一次。

**商店里看不到已购买的称号**

商店有「已购买隐藏」优化，**别人买过的你也能看到**（只是不能买）。想要完全隐藏得改配置。

**升版本后玩家数据不兼容**

数据格式在几个大版本间动过（4.0.0 的 UUID 改造是最大的一次）。跨这些大版本升级前**必须导出数据备份**，别赌。
