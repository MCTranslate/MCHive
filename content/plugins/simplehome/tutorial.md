## SimpleHome 安装教程

### 1. 它做什么

```
/sethome      在你当前站的地方设一个「家」
/home         传送到你的家
/sethome 基地  设一个叫「基地」的家
/home 基地     传送到那个叫「基地」的家
```

**这个功能的价值不在于「传送」本身，在于「家的概念」。**

有了家，玩家才会：

- 有「我要回基地整理东西」的目标
- 把仓库、农场、繁殖区**放在一个固定的地方**（因为要回来）
- 愿意跑远探索（因为回得来）
- 在服务器里形成「几个据点」的格局

**没有 home 机制的服，玩家的行为模式是「到处乱跑，什么都不固定」。** 这是生存服「没味道」的一个常见原因。

### 2. ⚠️ 首要问题：几乎肯定已经有 `/home` 了

**这一节是本页最需要先看的。**

`/home` 是 Minecraft 服务器里**最经典的命令之一**，几乎所有「基础插件」都自带它：

| 来源 | 是否自带 home |
|------|------------|
| EssentialsX | ✅ 自带 `/home`、`/sethome` |
| HuskSync 等同步插件 | 常常自带 |
| 各种一键整合包 | 常常自带 |
| 某些「基础功能」插件包 | 常常自带 |

**装两个的结果几乎必然是冲突：**

| 症状 | 原因 |
|------|------|
| `/home` 提示未知命令 | 另一个插件抢占了命令 |
| `/home` 传了但 `/sethome` 没记录 | 两套逻辑各存一份数据 |
| **家会「丢失」** | 换个命令就传不到同一个家了 —— **最迷惑的一种** |
| 提示消息重复 | 两个插件都在播报 |

**那个「家会丢失」是最坑的。** 玩家用 `/sethome` 设了家，然后 `/home` 传不过去（因为是另一个插件的数据），或者反过来。**玩家会以为插件坏了，其实是两套数据。**

**所以：装之前先确认。** 在游戏里敲 `/home` 试一下，有反应就说明已经有插件了。

### 3. 版本要求

**支持 MC 1.21 - 26.3。**

- **1.21 是下限**，比 SimpleTPA 的 1.21.4 稍宽一点
- 需要 Spigot / Paper 系

**1.20.x 及以下不覆盖。**

### 4. 它「简单」的代价

和 SimpleTPA 一样，Simple 系列的取舍是「只做一件事，不做多余的配置」。

| 它不做的事 | 你要另找的 |
|-----------|---------|
| 传送冷却 | 冷却类插件 |
| 传送费用 | 经济插件 + 相关配置 |
| 玩家最大家数量 | —— **看它的配置能力** |
| 跨世界家 | 多数实现基础版本就支持，**以你的配置为准** |
| **站在家上被传送时的位置安全** | —— |

**「最大家数量」这一项值得想清楚。** 无限制的话，有心的玩家会设几十个家（每个坐标一个），本质上是把 `/tp` 换了个皮。**这个限制是很多服主会配的。**

### 5. 安装

1. 下载 jar 放进 `plugins/`，重启
2. 生成 `plugins/SimpleHome/`
3. 权限分配
4. 确认世界权限规则

### 6. 常用命令

| 命令 | 说明 |
|------|------|
| `/sethome` | 在当前位置设家（默认家） |
| `/home` | 传送到默认家 |
| `/sethome <名字>` | 命名家 |
| `/home <名字>` | 传送到指定家 |
| `/delhome [名字]` | 删除家（部分实现有） |
| `/homes` | 列出自己的家（部分实现有） |
| `/setrespawn` | 把当前位置设为重生点（**部分实现有这个功能**） |

> ⚠️ **具体命令和参数以你版本的帮助输出为准。** 极简插件的命令列表可能只有其中一半。

**`/delhome` 和 `/homes` 这两个要看它有没有。** 有的话对玩家体验影响不小（尤其是家设多了要能管理），没有的话玩家只能删了重设。

**如果它带 `/setrespawn` 功能，那它就不只是「家」而是「出生点管理」了。** 这种情况下它和 SimpleTPA、Minecraft 原版床的定位会有重叠，**装之前要想清楚哪个是「权威源」**。

### 7. 权限：家这件事必须认真配

**home 的权限是这类插件里最需要精细控制的。**

| 问题 | 后果 |
|------|------|
| 所有人都能设家 | 有人在家旁边的方块里设家，卡住地图 |
| 玩家能设无限个家 | `/home` 变成 `/tp` |
| **能传进别人的家** | **这是最严重的问题** |
| 可以在不属于自己的世界里设家 | 在别人的世界里建据点 |

**最后一条要重点说。** 家园点加上多世界服，会出现这种情况：

```
玩家在别人的世界里 /sethome
  → 在那里有了家
  → 天天过去干扰别人
  → 或者在那个世界的关键位置建了个家卡住路
```

**所以除了「能不能用 /home」这个权限，还要有「能在哪些世界用」的权限。** 跨世界权限是这类插件最容易漏配的项。

**以你版本的权限节点和配置注释为准**，本页不列具体节点名——**写错的节点名等于没配**。

### 8. 常见坑

**`/home` 提示未知命令**
1. 插件没加载（看控制台有没有报错）
2. **被其他插件抢占了命令**（见第 2 节）

**家和别的插件的数据不互通**
「用 A 设的家，用 B 传不过去」。**两套数据、两套逻辑。** 必须清掉一个。

**玩家在家附近的方块里被卡住 / 被压死**
- `/sethome` 设在了危险位置（岩浆、仙人掌、方块内部、半砖里）
- **设家时的位置本身不安全** —— 玩家站在半砖上设家，传送回来就卡住了

**这个问题是这类插件的固有短板。** 原版床有「安全位置检查」，home 类插件多数没有或者简化了。**如果服务器有随机传送/回城机制，home 也有这个问题。**

**玩家把家设在别人的领地里 / 敌对区域**
权限 + 领地保护要一起管。**home 只管「我能传去我的家」，不管「那里安不安全」。**

**世界删除/重置后，家指向空坐标**
- 世界被删了但 home 数据还在 → 传送出错或无效
- 地图/下界/末地被重置 → 玩家回不去家

**需要处理：世界重置时清掉对应的 home 记录。** 这一步很多服会忘。

**和 EssentialX 的 home 冲突**
见第 2 节。**这是最高概率的冲突场景。**

### 9. 关于汉化

**本站未核实到 SimpleHome 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/SimpleHome/`，看有没有语言文件目录
2. 搜配置文件里有没有 `message`、`language`、`locale` 段落
3. **注意区分**：
   - 插件发出的消息（设家成功、传送失败、没权限）—— 服务端发出
   - **家列表的显示**（如果能列出家的名字和坐标）—— 可能也是消息文件管
4. **需要汉化的内容通常很少** —— 就是「已设置家」「已传送」「没有家」这几行

**务实的判断：** 极简插件的中文支持不是刚需。玩家看到「No home set」三秒就懂了。**除非你非常在意社区观感，否则可以先放着。**

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **已经有 home 功能** —— 见第 2 节，冲突概率极高
- **MC 1.20.x 及以下** —— 声明区间从 1.21 起
- **服务器已经在用 EssentialsX** —— **先确认 EssentialsX 的 home 够不够用**，够就别加
- **纯小服（几个朋友）** —— 直接用坐标和 `/tp` 就行
- **玩家希望自己管理多个家（跨设备同步）** —— 极简插件通常不支持数据跨服同步

### 11. Home 系统对服务器氛围的实际影响

**这一节不是讲配置，是讲「为什么值得装」。**

有 home 和没 home 的服，玩家的行为模式是不一样的：

| 维度 | 有 home | 没有 home |
|------|--------|----------|
| 基地感 | 「我要回我的家」→ 有归属感 | 「我在到处跑」 |
| 仓库/工厂位置 | 会固定下来，形成据点 | 到处都是箱子 |
| 探索意愿 | 敢走远（回得来） | 不敢走远 |
| 社交 | 会互相串门（用 TPA） | 各玩各的 |
| 服的「历史感」 | 有故事发生的地方 | 地图是空的 |

**这些差异在小服上是能感觉到的。** 不是玄学——「固定几个据点」这件事本身就会催生社区活动。

**反过来说：如果你想要的是「大家都聚在一起玩」的氛围，home 系统反而可能让玩家散开。** 这取决于你的服是什么类型。

**所以「要不要 home」这个问题，答案取决于你想让玩家在哪儿待着。**
