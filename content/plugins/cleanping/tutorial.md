## CleanPing 安装教程

### 1. ⚠️ 先看这个版本区间：它大概率不准

本页 `version` 字段写的是 **`CleanPing（MC 1.8 - 3.4）`**。**这里有两个问题：**

**第一，`3.4` 不是 MC 版本。** MC 版本号带 `1.` 开头（`1.8`、`1.20.4`、`1.21.4`）。`3.4` 明显是**加载器/代理端的版本号**——CleanPing 同时支持 Velocity，而 Velocity 的版本号正是 3.x 那一套。**第二，声明的区间跨度过大**，`1.8 - 3.4` 在时间上说不通。

**所以这个区间是注册表元数据把不同平台的信息混在了一起。** 准确的 MC 支持范围请以官方页面为准（SpigotMC 资源页 / 仓库 <https://github.com/frafol/CleanPing>）。**官方 README 里给出的各平台版本范围是分开写的**（见第 4 节），这也从侧面说明单一区间字段不可靠。

**本站不替它编一个区间，也不假装这个数据准确。**

### 2. ⚠️ 它不加速网络（这条必须先说）

**CleanPing 是显示层插件。它不改变你的网络延迟，一毫秒都不改。**

这是最容易误解的地方。看到「ping 插件」就以为能优化延迟，是两回事。

| | CleanPing 做的 | CleanPing 不做的 |
|---|---|---|
| 延迟显示 | ✅ 统一格式、按高低上色 | ❌ 不降低延迟 |
| 单位 | ✅ 统一成 ms | ❌ 不改单位换算方式 |
| 抖动 | ✅ 数字好看稳定 | ❌ **不消除真实抖动** |
| 网络传输 | 只读 | ❌ 不做任何优化 |

**真实延迟由什么决定**：你到服务器的距离、运营商、服务器带宽、路由质量、无线/有线、后台程序占用。**这些 CleanPing 一个都不碰。**

**如果你的延迟真的高**，方向是这些（和 CleanPing 无关）：物理层面（换网络、插网线、换个运营商）、服务器层面（见 [卡顿诊断](#/guide/lag-diagnosis) 和 [性能调优](#/guide/performance-tuning)）、代理架构（见 [用 Velocity 搭建群组服](#/guide/velocity-network)）。

### 3. 那它到底改善什么

**它改善的是「看起来」。而且这不只是虚荣问题。**

原版 `/ping`（F3 或命令）的显示有几个实际问题：

| 问题 | 表现 |
|------|------|
| **数字跳动** | 数字每秒钟都在变，看起来「很不稳」，哪怕实际很稳 |
| **看不出好坏** | 63ms 和 380ms 都是一串数字，玩家分不出哪个算好 |
| **单位混乱** | 有时是 ms，有时显示别的，容易被误解 |
| **看不到别人** | 只能看自己的，没法判断「是整服都卡还是只有我卡」 |

CleanPing 针对的就是这几点：

| 改进 | 说明 |
|------|------|
| **按区间上色** | 延迟低/中/高用不同颜色，一眼能判断 |
| **查别人** | `/ping <玩家>` 查在线玩家的延迟 |
| **两人对比** | `/ping <玩家1> <玩家2>` 看延迟差 —— **这个在排查「为什么他卡我不卡」时真的有用** |
| **格式统一** | 输出格式可控 |

**「延迟差」这个功能值得单独说。** 排查网络问题最有效的一步就是区分：

```
情况 A：所有人延迟都高 → 服务器端或运营商问题
情况 B：只有一个人延迟高 → 那个人的网络问题
情况 C：全服延迟差不多 → 正常
```

`/ping A B` 直接告诉你两人差多少，**这是原版没有的能力**。

另外 CleanPing 后续版本还加了 **Ping Monitoring**——延迟异常的玩家会收到一条带可能解决方案的消息（可配置）。这类功能对社区服体验有帮助，但也意味着**它在给玩家发提醒**（汉化相关的点见第 8 节）。

### 4. 平台支持

CleanPing **同时支持三个平台**，而且各平台的版本范围是分开的：

| 平台 | 官方 README 标注的范围 |
|------|---------------------|
| BungeeCord | 1.7 - 1.21.X 及 fork |
| Spigot | 1.7.10 - 1.21.X 及 fork |
| Velocity | **3.2.0 / 3.3.0 / 3.4.0** 及 fork |

**看第三行** —— 这正好解释了第 1 节的疑惑：**`3.2` / `3.3` / `3.4` 是 Velocity 的版本号，被混进 MC 区间字段里了。** 本页 version 字段里那个 `3.4` 就是这么来的。

**装在哪个平台：** Spigot / Paper 服装 `plugins/`；Velocity、BungeeCord / Waterfall 装代理端的 `plugins/`。**群组服里建议只装一处** —— 代理端装了就够了，两边都装会重复响应 `/ping`。

> 官方还提到支持 **RedisBungee / RedisVelocity** 环境（群组服跨服场景），以及后续版本对 **Folia** 有支持。「Folia 和 forks 支持」这类说明要看版本——官方更新日志里能看到「更好的 Folia 支持」是在某个版本才加的，**旧版本没有**。

### 5. 命令

| 命令 | 说明 |
|------|------|
| `/ping` | 显示自己的延迟 |
| `/ping <玩家>` | 显示某个玩家的延迟 |
| `/ping <玩家1> <玩家2>` | 显示两人的延迟差 |
| `/pingreload` | 重载配置 |

**命令可以从控制台执行。**

### 6. PlaceholderAPI 支持

装了 PAPI 的话可以用这些变量（**Spigot 端**）：

| 变量 | 说明 |
|------|------|
| `%cleanping_ping%` | 自己的延迟 |
| `%cleanping_coloured_ping%` | 自己的延迟（带配置里设的颜色） |
| `%cleanping_ping_<玩家名>%` | 某玩家的延迟 |
| `%cleanping_coloured_ping_<玩家名>%` | 某玩家的延迟（带颜色） |
| `%cleanping_difference_<玩家名>%` | 自己与某在线玩家的延迟差 |
| `%cleanping_difference_<玩家1>_ <玩家2>%` | 两个在线玩家之间的延迟差 |

**这组变量的价值在于做「延迟展示」类的内容：**

- 大厅里的记分板显示「你当前的延迟」
- 登录界面提示玩家「你延迟 320ms，可能影响体验」
- 配合 TAB / 记分板插件展示

> ⚠️ **变量名以你版本的文档为准。** 占位符命名在版本间可能调整。

### 7. 什么时候值得装

| 值得 | 不值得 |
|------|-------|
| 你的服有国际玩家（延迟差异大，上色有用） | 你想「优化」延迟 —— 见第 2 节，它不加速 |
| 你经常需要判断「是全服卡还是某个玩家卡」 | 服里没别人在线（查延迟差没意义） |
| 想在记分板/大厅展示玩家延迟 | 已经有别的插件提供了同样的显示 |
| 玩家抱怨「延迟数字乱跳看着不稳」 | —— |

**如果你的服只有一种延迟（比如都在同一个城市），这个插件的价值有限。** 上色和对比功能需要差异才有意义。

### 8. 关于汉化

**本站未核实 CleanPing 的官方中文语言文件机制。** 若要汉化需自行确认。

但有一点值得先说：**官方 README 提到「插件和翻译都可配置」**，也就是说它**有**可配置的消息文本（大概率是语言文件或配置里的消息段，具体形态以你的版本为准）。

引导式排查方法：

1. 进 `plugins/CleanPing/`（或它实际生成的目录名），找 `lang/`、`translations/`、`messages_xx.yml` 这类文件
2. 搜配置文件里有没有 `language`、`lang`、`locale`、`translation`、`messages` 关键词
3. **注意 Ping Monitoring 功能的提示**（第 3 节提到的「延迟异常时给玩家建议」）——**这类提示是玩家可见文本的一部分**，查汉化文件时留意它在哪个文件里

**需要汉化的内容量：** `/ping` 相关的消息不多，加上 Ping Monitoring 的提示也就几条。真要汉化，直接改配置文件里的消息文本可能比找语言文件更快——**但前提是你确认了它的实际读取机制**，别改了一个它根本不读的文件。

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 9. 常见坑

**装了之后延迟没变** —— 见第 2 节。**这是预期行为，不是 bug。** 换任何显示插件都不会让延迟降低。

**代理端和后端都装了，输出两条** —— `/ping` 被响应了两次。**群组服里只留一处。**

**用了新版本才有的功能，没反应** —— Folia 支持、Ping Monitoring、MiniMessage 支持都是**在特定版本加的**（官方更新日志里能看到时间点）。**确认你的版本包含它。** 若是 Folia 服行为异常，升级到最新版再看。

**延迟上色的阈值不对，某玩家显示绿色但他其实卡** —— 颜色阈值是**按延迟数值**判定的，而「卡」的主观感受还取决于玩家用什么网络、什么设备。**可能需要按你的玩家实际情况调阈值**，而不是照抄默认。

**变量不生效** —— 确认装了 PAPI（Spigot 端），且**拼写完全正确**。注意变量里带玩家名，**名字错了就不生效。**

### 10. 什么时候别用它

- **想优化延迟** —— 它不加速，见第 2 节
- **服里玩家延迟都差不多** —— 上色和对比的价值发挥不出来
- **已经有别的延迟展示插件** —— 重复功能
- **只有你一个人在线** —— 延迟差功能没意义
