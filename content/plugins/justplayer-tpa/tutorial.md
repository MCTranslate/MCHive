## JustPlayer-TPA 安装教程

### 1. 它做什么

```
你 → /tpa Steve        「我想传送到你那里」
Steve → /tpaccept you  「同意」
你 → 出现在 Steve 身边
```

**这套动作是服务器的通用语言。** 几乎每个 Minecraft 服务器都有它，因为这是「互相帮忙」的基础动作——队友在地里挖矿你送一箱食物过去、朋友在远处盖房子你想去看、队友在打 boss 你在旁边打药。

**没有它，玩家只能用坐标 + 走路，或者用 `/tp` 直接飞过去** —— 后者会破坏「家在哪个世界」的意义。

### 2. ⚠️ 装之前：你的服是不是已经有 TPA 了

**这是本页最需要先确认的一件事。**

很多基础插件包（EssentialsX、部分服务器整合包、某些一键安装的插件合集）**自带 TPA**。装两个的后果：

| 症状 | 原因 |
|------|------|
| `/tpa` 提示未知命令 | **另一个插件抢占了命令**（或反过来，你的没加载） |
| `/tpaccept` 有两个，行为不同 | 两套逻辑并存 |
| 传送后多一条消息 | 两个插件都在播报 |
| 传送后物品/背包异常 | 两套逻辑都在处理事件 |

**TPA 命令冲突非常常见**，而且排查起来很烦（要一个个插件试着禁用）。**排查方法**：逐个禁用怀疑的插件，重启，看 `/tpa` 恢复没有。

> 站内 [SimpleTPA](#/plugin/simpletpa) 也是做这个的。**两者不需要同时装**，选一个。

### 3. 作者为什么写它

JustPlayer TPA 的 README 里写得很直接：作者原本想找的是**已经满足自己需求**的 TPA 插件，没找到，于是自己写了一个。

这句话值得琢磨：**它是个人需求的产物，不是「大而全」的设计**；作者的取舍标准是「我要的有没有」，不是「社区觉得缺什么」；**功能上不会有惊喜，但也不会有臃肿**。这是好事也是风险——好事是它小、不折腾；风险是**遇到问题时你可能找不到资料**，得自己看配置和代码。

### 4. 版本与安装

- Modrinth：搜 `just-tpa`（项目 ID `GM9AuKjX`）
- 仓库：<https://github.com/JustPlayerDE/justplayer-tpa>
- 协议：MIT

**声明支持 MC 1.19 - 1.21.4。** 平台 **Bukkit / Paper / Spigot**。

- **1.19 是比较新的下限** —— 你的服如果在 1.18 或更早，**用不了**
- **API 层面用的是 Spigot 1.19** —— 作者说明，除非 Paper/Spigot 放弃 1.19 API 支持，或命令/传送机制有变动，否则大多数情况下不需要更新
- **Folia：作者说明在有空的时候会看，本页不替它承诺**

**没有前置依赖**（这是它适合当底层组件的原因）。安装：下载 jar 放进 `plugins/`，重启，生成配置文件目录。

### 5. 常用命令

这些命令**在官方 README 里明确列出**：

| 命令 | 权限 | 说明 |
|------|------|------|
| `/tpa <玩家>` | `justplayer.tpa.request` | 发起传送请求 |
| `/tpaccept [玩家]` | `justplayer.tpa.accept` | 同意请求，可指定只接受某个人的 |
| `/tpadeny` | `justplayer.tpa.deny` | 拒绝请求 |
| `/tpacancel` | `justplayer.tpa.cancel` | 取消自己发出的请求 |
| `/tpahere <玩家>` | `justplayer.tpa.here` | **反向**：让对方传送到你这里 |
| `/tpareload` | `justplayer.tpa.reload`（默认 OP） | 重载配置 |

额外权限：`justplayer.tpa.wait.bypass`（跳过传送等待）和 `justplayer.tpa.return-timeout.bypass`（跳过「返回」超时限制），**两者默认都是 OP**。

> `/tpahere` 这个命令值得说两句。**它能把别人拉到你面前** —— 这在 PvP 服上是危险动作，**权限别乱发**。见第 7 节。

**部分版本还提供了「返回」命令**（`/tpareturn` 或 `/return`），可以回到传送前的位置。**升级后记得检查配置和权限** —— 官方更新日志里专门提了这条。

### 6. 「简单」的代价

插件名里的 Just、README 里的 simple，都说明它只做传送请求这一件事。

| 它不做的事 | 你需要另找的方案 |
|-----------|----------------|
| 传送后的保护期 | PvP 管理类插件 |
| 跨世界权限限制 | 领地 / 世界管理插件 |
| 传送费用 | 经济插件 |
| 黑名单 / 「现在不接受任何请求」开关 | 它的权限节点粒度细，可以自己用权限实现变通 |

**这不是缺点，是取舍。** 小插件把一件事做干净、没一堆要配的选项，很多服反而更省心。**但你得知道缺什么。**

**尤其是传送后的保护期** —— 传送到队友身边然后被 PvP 秒杀，这是 TPA 类插件被诟病最多的场景。**JustPlayer-TPA 大概率不处理这个。** 如果你的服 PvP 活跃，这件事要单独想办法。

### 7. 权限设计里那个必须自己决定的问题

JustPlayer-TPA 的权限节点很细（每条命令一个），这给了你控制空间，但也把决策推给你。**`/tpahere` 是那个需要你想清楚才发的：**

```
管理员 → /tpahere 某个玩家
  → 那个玩家被强制拉到管理员面前
  → 如果管理员正在 PvP 里
  → 那个人落地就被打
```

**这不是插件的 bug，是命令本身的语义。** 建议只给 OP / 管理员，并且**想清楚 PvP 服上要不要开**。同理 `justplayer.tpa.wait.bypass`（跳过等待）也别发给普通玩家——它的存在意义是给管理员应急用。

想更细地控制（只控制发起、只控制接受、分别控制反向），权限节点的设计已经支持了。

### 8. 常见坑

**和别的插件命令冲突**

见第 2 节。**TPA 命令冲突非常常见**，先排查基础插件包。

**被队友卖到敌人面前**

```
你 /tpa 队友 → 队友 /tpaccept → 你 出现在队友身边 → 队友的敌人已经在那里等着了
```

**这是 TPA 机制的固有问题，不是插件的 bug。** 除非它带了「传送后短暂无敌」（**本页不替它承诺**），否则任何 TPA 插件都有这个风险。

**传送到很远的坐标，服务器卡一下**

跨世界/远距离传送会加载区块。**瞬间加载大量区块会掉 TPS。** 这是正常现象，不是 bug。

**和 EssentialsX / 其他插件的消息重复**

传送成功/拒绝的消息可能和别的插件的消息重复发。表现为同一件事播报两遍。

**「未知命令」**

两种可能：① 插件没加载（看控制台）；② 被其他插件抢了命令（见第 2 节）。

**MC 1.18 及更早装不了** —— 见第 4 节，声明区间从 1.19 起。

**升级后 `/return` 相关行为变了** —— 官方更新日志明确提醒过：**升级后检查配置和权限。** 新增的命令和权限节点不会自动出现在你的权限插件里。

### 9. 关于汉化

**本站未核实 JustPlayer-TPA 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/` 下它生成的目录，找语言相关文件（常见形态是 `lang/`、`messages_xx.yml`、`translations/`）
2. 搜配置文件里有没有 `language`、`lang`、`locale`、`message` 关键词
3. **需要汉化的内容很少** —— TPA 的消息量本来就小（请求发出、同意、拒绝、超时几个提示）

**一个务实的判断：** 极简插件的中文支持通常不是刚需。**玩家看到英文提示，几秒钟就明白了。** 除非你非常在意社区体验，否则这一项可以先放着。

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **已经有 TPA 了** —— 见第 2 节，冲突是主要风险
- **MC 1.18 或更早** —— 声明区间从 1.19 起
- **PvP 活跃且没有保护期方案** —— 传送落地被秒是 TPA 的通病
- **需要复杂传送规则**（费用、跨世界限制、保护区）—— 它的功能边界就到这里
- **团队要靠海量社区资料排错** —— 它是个人维护的小插件，资料少
