## Maintenance 安装教程

### 1. 它解决什么问题

改配置、装插件、导数据库、跑 WorldEdit 大批量操作——这些事都会**把玩家的存档搞坏**。解决方案是维护模式：

```
平时：    玩家正常在线
        ↓ 服主输一条命令
维护中：  在线玩家被踢出，白名单以外的人进不来
        ↓ 服主改完东西、手动关掉
平时：    玩家重新进来
```

核心机制是**踢出 + 阻止进入**两件事一起做。只踢出不阻止是错的——玩家会立刻重连。

**它不做什么：** 不帮你备份、不帮你热重载、不帮你回档。它只管「现在谁该被拦在外面」。备份用 [Backuper](#/plugin/backuper) 之类的插件，那是另一件事。

### 2. 为什么不用原版白名单

原版白名单能挡人，但有几个问题：

| 原版白名单的局限 | Maintenance 的差别 |
|----------------|-----------------|
| 开了就全服进不去，白名单外全被踢 | 支持临时切换，命令控制 |
| 白名单是一份永久名单 | 支持在维护状态临时放行管理员 |
| 踢出消息是原版那句 | 自定义踢出理由，可以带原因和恢复时间 |
| 开关要手动改 server.properties | 命令即时生效 |

**关键区别是「即时」和「有理由的踢出」。** 维护模式的价值在于告诉玩家「半小时后回来」，而不是让人一头雾水。

### 3. 版本与依赖

**支持 MC 1.8 - 26.3**（版本区间很宽，说明用的是稳定的低版本 API）。

- 无硬依赖
- 可选：权限插件（LuckPerms / Vault）

**没有前置要求**，这是它适合新服务器的原因。

### 4. 安装

1. 下载 jar 放进 `plugins/`
2. 重启服务器
3. 生成 `plugins/Maintenance/` 目录，含配置和语言文件

安装简单到几乎不需要教程——这符合它的定位：**运维工具越简单越可靠**。功能复杂的维护插件在改配置时反而容易出问题。

### 5. 常用命令

| 命令 | 说明 |
|------|------|
| `/maintenance` | 查看当前维护状态 |
| `/maintenance on`（或对应子命令） | 开启维护模式 |
| `/maintenance off` | 关闭维护模式 |
| `/maintenance reload` | 重载配置 |

> ⚠️ **具体命令和子命令写法以你版本的 `plugin.yml` 为准**。本页不逐条默写命令——维护插件的命令结构在不同版本间改过，写错的命令你敲了没反应，还以为插件坏了。**装完先进游戏敲 `/maintenance` 看帮助输出。**

### 6. 配置要点

配置在 `plugins/Maintenance/` 下。**具体键名以你手上版本的配置文件注释为准。** 逻辑上一般涉及这几类：

| 配置类别 | 管什么 |
|---------|-------|
| 维护状态 | 是否默认处于维护模式（服务器启动时自动进维护） |
| 踢出消息 | 玩家被踢时看到什么 |
| 放行 | 谁能绕过维护模式（通常接权限节点） |
| 自动开关 | 定时自动开/关（定时重启维护、凌晨低峰维护） |

**最值得配的是「自动进维护模式」这一项。** 服务器每次重启都自动开维护、服主手动关——这能消灭「重启后玩家进来看见半加载的服务器」这种事故。对配置复杂的服（Vault 经济、权限、数据库都依赖初始化顺序）尤其值得开。

### 7. 常见坑

**服主自己被踢出去了**
这是**开启维护后最常见的事故**。开启之前先确认自己的放行权限（一般是权限节点，具体节点名以 `plugin.yml` 为准），或者**用控制台执行命令**——控制台不受维护模式影响。

> 建议：开维护的流程固定为「先确认权限 → 控制台执行 → 改东西 → 关闭」。

**关掉维护之后部分玩家还是进不来**
可能是**被其他插件拦着**——BanList、IP 白名单、AuthMe 的登录限制、或者 Velocity 代理端自己也开着维护。**代理端和后端各有一层**，两边都要检查。

**踢出消息没变化**
语言文件没生效，或者消息在配置里而不是语言文件里。**看 `plugins/Maintenance/` 里到底哪个文件有这段文案。**

**开了维护，NPC 和假人玩家也被踢了**
如果服里有 NPC 插件（ Citizens 之类），它自己也是玩家。检查 NPC 是否在放行名单里。

**和别、维护相关的插件冲突**
如果同时装了两个维护模式插件，**两套逻辑会互相覆盖**。表现为：关了一个另一个还开着，或者开了之后立刻被另一个关掉。**这类功能只留一个。**

### 8. 关于汉化

**Maintenance 有繁体中文，但没有简体中文。**

仓库里存在的语言文件是：

```
language-zh_tw.yml    ← 繁体中文
```

**没有 `zh_cn.yml` 或 `zh-CN.yml`。** 这意味着：简体中文客户端进服，看到的仍然是默认英文。

这一点是本页要专门写出来的原因——**很多服主会默认「有中文 = 有简中」，实际不是。**

机制说明、怎么自己补一份简中、以及注意事项，见 [汉化机制](#/plugin/maintenance) 页。

### 9. 什么时候别用它

- **有稳定的停服公告流程（Discord 通知 + 论坛）** —— 服主手动踢人也行，维护模式是给「经常要改东西」的服用的
- **服务器已经有 VIP 预约 / 维护流程插件** —— 功能重叠
- **纯休闲服，一天没人动配置** —— 几乎用不到

### 10. 和备份的关系

这两个事经常一起做，但**一定要分清顺序**：

```
1. 先开维护模式      ← 没人写入，备份才一致
2. 再跑备份
3. 备份成功确认后
4. 再改配置 / 装插件
5. 改完关闭维护
```

**反过来做（先备份后开维护）会拿到一份可能写了一半的世界文件。** 恢复的时候才发现就晚了。

备份工具本身见 [Backuper](#/plugin/backuper)。
