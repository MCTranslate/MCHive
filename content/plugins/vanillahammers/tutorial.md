## ⚠️ 先看这里：这是 Nova 附属，不是独立插件

**Vanilla-Hammers 自己不做任何事。它是挂在 Nova 框架上的一个附属包。**

```
Nova 框架（必需，先装）
   ↓ 提供：物品注册、材质、GUI、网络包
Vanilla-Hammers（本文档）
   ↓ 提供：锤的具体配方、升级链、模型
玩家客户端：只需要自动下发的资源包
```

**没装 Nova 直接丢 Vanilla-Hammers 的后果：** 插件可能加载成功、也不报错，但**游戏里什么都不会出现**。因为它注册物品的接口是 Nova 提供的。这是最容易踩的坑——「装了啊，为什么没锤」。

官方仓库：<https://github.com/xenondevs/Vanilla-Hammers>

### 1. 它是什么

给 Nova 的自定义物品体系加一套**锤**。锤的逻辑不是「砍得更快」，而是**换个方向加速**：

| 工具类型 | 作用对象 | 典型用途 |
|---------|---------|---------|
| 镐 | 石质 / 金属方块 | 原版挖矿 |
| **锤** | **石头、矿石等整块方块** | **跳过耐久消耗地拆方块** |

锤的价值在于**耐久经济性**和**手柄**。原版挖石头要反复消耗镐子，锤能把这一段重复劳动压缩掉。

> ⚠️ 具体的锤种类、升级链、配方和数值，**以你版本 jar 内的实际内容为准**。本文档不列具体配方表——Nova 附属的配方通常写在附属自己的配置文件里，装完打开 `plugins/Nova/`（或附属目录）看注释最准。

### 2. 前置：Nova 必须先装

| 要求 | 说明 |
|------|------|
| **Nova** | **硬前置**。Vanilla-Hammers 是它的附属，Nova 不在 = 附属不工作 |
| 服务端 | Paper / Folia 系（跟随 Nova 的支持范围） |
| Java | 跟随 Nova 的构建要求 |
| 玩家端 | **不需要装模组**，只需接受进服时自动下发的资源包 |

**安装顺序不能反：**

```
1. 装 Nova          →  重启
2. 确认 Nova 正常加载 →  再重启一次，让它生成配置和资源包结构
3. 装 Vanilla-Hammers →  重启
4. 玩家进服接受资源包
```

**为什么中间那次重启重要：** Nova 首次启动会生成配置目录和它自己的资源包结构。附属的物品模型依赖这些文件，Nova 没跑完一次的话附属可能加载到不完整的环境里。

### 3. 安装步骤

1. 装好 Nova 并确认控制台无报错
2. 把 Vanilla-Hammers 的 jar 丢进 `plugins/`
3. 启动 Nova（它会为附属建立配置目录）
4. 把 Vanilla-Hammers 的 jar 丢进 `plugins/`
5. 完整重启服务端
6. 玩家进服，接受资源包，敲 `/nova` 之类的界面查看物品

### 4. 资源包是硬需求

Nova 系物品的**材质和模型走资源包下发**。所以：

| 现象 | 原因 |
|------|------|
| 物品是紫黑相间的破方块 | 玩家没接受资源包 |
| 物品完全看不见（手持无模型） | 同上，或者资源包版本和插件版本不匹配 |
| 有人看得见有人看不见 | 资源包在不同客户端上加载失败率不一样 |

**排查动作：** 让玩家在服务器列表里点进服时的资源包提示，确认没有点「拒绝」。基岩版玩家通过 Geyser 进入的话，资源包行为和 Java 版不一致——真要照顾基岩玩家，得单独测。

### 5. 和其他工具插件的关系

锤和 Timber、VeinMiner 不是同一类东西，别混着比：

| 插件 | 解决什么 | 和锤的关系 |
|------|---------|-------------|
| **Vanilla-Hammers** | 单个方块的拆解效率 | 锤本身 |
| [Timber](#/plugin/timber) | 一次砍倒整棵树 | 砍树场景下**比锤更直接** |
| [VeinMiner](#/plugin/veinminer) | 一次挖掉整条矿脉 | 采矿场景下**比锤更直接** |

**判断标准很简单：** 你的服想解决的是「单个方块拆得慢」还是「一次清一片」？前者用锤，后者用 Timber / VeinMiner。三个一起装有时候会打架（连锁挖矿的判定顺序、方块被连锁提前移除导致锤的判定落空），**先只上一个**。

### 6. 关于汉化

**本站未核实到 Vanilla-Hammers 的官方中文语言文件机制。** Nova 本体有一套自己的本地化体系（JSON 语言文件，含简繁中文，见 [Nova 页面](#/plugin/nova)），但**附属的物品显示名和提示文本是否走 Nova 那套机制，本站没有核实到**，不要假定。

引导式排查方法：

1. 打开 `plugins/` 下的 Nova 目录和附属目录，**搜文件名**里带 `lang` / `locale` / `messages` / `zh` 的文件
2. 打开附属的配置文件，**搜关键词** `message`、`locale`、`lang`、`name`、`display`
3. 判断物品名到底走哪条路：
   - **材质 / 模型 / 物品显示名** —— 走资源包，**改 YAML 没用**，得改资源包里的 json
   - **服务端发出的提示消息**（比如「锤子升级了」「耐久不足」）—— 可能在语言文件里
4. 如果发现硬编码英文，**先确认它到底在 jar 里还是配置文件里**，再决定改法

> 别一上来就新建 `lang/zh_CN.yml` 然后期待插件读它——**多数插件不会自动读你造的文件**。一定先确认插件实际的加载路径。

### 7. 什么时候别用它

- **没有装 Nova** —— 它单独毫无意义
- **服务器不允许玩家接受资源包**（某些硬核服为了防 XSS 会禁）—— 物品全是破方块
- **已经有 Timber + VeinMiner 且够用** —— 再加锤收益边际递减，还会引入判定冲突
- **纯 PvP 竞技服** —— 锤带来的方块快速拆解会改变建筑和开战节奏
