## Stargate 安装教程

### 1. ⚠️ 它和原版下界传送门是两回事

**这是最容易误解的一点，先说清楚。**

| | 原版下界传送门 | Stargate |
|--|----------------|----------|
| 谁造 | 所有人 | 玩家自己（或管理员预建） |
| 门框材料 | 黑曜石 | 苔石 / 各类自定义材料 |
| 怎么开 | 自动（点燃下界火） | 按钮 / 开关触发，或常开 |
| 连到哪里 | 固定：主世界 ↔ 下界，坐标按 1:8 换算 | **你自己指定**——任意两点、任意网络 |
| 跨服 | 不行 | 支持（BungeeCord / Velocity） |
| 能不能拆 | 能，但下界那个也一起没 | 门坏了会**禁用往来**并通知其他门 |

原版传送门是**世界机制**，坐标由游戏定死，改不了。Stargate 是**给玩家的交通网络**——他想连哪连哪，名字自己起。

它最早是 hMod 时代 Dinnerbone 写的插件，2011 年 Drakia 移植到 Bukkit，是这一类里最老也最长寿的实现。现在的维护由多个分支作者共同接手（Stargate Rewritten 项目）。

### 2. 它解决什么

原版跨世界移动只有两个办法：走路 / 船 / 末影船，或者挤下界传送门（1:8 坐标换算，很远）。

**Stargate 让你在两个自建的门之间瞬移。** 对玩家来说这意味着：

- 家和基地之间一条门搞定
- 常见地点（主城、商店、矿洞、农场）设固定对
- 玩家自己建门，不用管理员满世界飞着摆

**它的设计哲学是「玩家自主 + 无需命令」**——建门、连门、删门全靠告示牌交互，不敲命令。权限给够了，普通玩家就能自己搞网络。

### 3. 安装

**注意这里的仓库名有坑**，见下方说明。

```
仓库：https://github.com/Stargate-Rewritten
Wiki：https://github.com/Stargate-Rewritten/Stargate-Bukkit/wiki
官网：https://sgrewritten.org
发行：Modrinth 搜 stargate / Hangar 搜 Stargate
```

jar 丢进 `plugins/`，重启。首次启动会生成 `plugins/Stargate/`，里面带配置和门的设计定义。

**迁移**：如果你之前用过某个 Stargate 分支（2013 年后的绝大多数都兼容），把旧的 `stargate` 目录换进去，它会尽量自动迁移配置和数据。**先备份。**

### 4. ⚠️ 官方仓库名的坑（重要）

表格里记的仓库是 `Stargate/Stargate`，**但这个 GitHub 地址不是这个插件。**

- `github.com/Stargate/Stargate` → **DataStax 的 Apache Cassandra 数据网关**，一个企业级数据库中间件，和 Minecraft 毫无关系
- 真正的 MC 插件在 **`Stargate-Rewritten`** 组织下

这是个典型的名称撞车。搜「Minecraft Stargate」很容易被那个数据库项目的结果淹掉。**别按 `Stargate/Stargate` 去下载，你会下到一个 Java 数据库网关。**

### 5. ⚠️ 当前是 legacy 维护通道

**这个项目在整体重写。** 现状：

| 通道 | 状态 |
|------|------|
| legacy（0.11.x） | 维护中，功能全，你现在能下到的就是这个 |
| 重写版 | 公开 alpha，通过 Discord 招募测试者 |

legacy 通道在**尽量合并各个历史分支的功能**（本质上是各分支维护者的一次合力），所以它能用的功能比早期 Stargate 多。功能会继续往重写版迁。

**实际影响**：现在装能用，但**别指望它会一直维护**——作者明说了重写版发布后 legacy 会进入只维护状态。做长期规划的话，盯着重写版的进度。

### 6. 门怎么用

核心交互是**告示牌 + 按钮**：

1. 用苔石一类材料搭出门框
2. 在门附近放一个按钮（苔石上的按钮）
3. 敲按钮 → 弹出菜单，列出所有可用的门
4. 点一个 → 传送过去

两种模式：

| 模式 | 行为 |
|------|------|
| 常开（always-open） | 走进去就传 |
| 按钮触发 | 得按按钮 / 拉开关 |

按钮材料**可自定义**，很多方块都能当按钮用。只要按钮材料防水，门也能**建在水下**。

### 7. 功能面

| 能力 | 说明 |
|------|------|
| 传送对象 | 玩家 + 载具（船、矿车、坐骑）+ 拴绳的生物 |
| 网络 / 集群 | 门可以共享一个网络，也可以拆成互不相干的簇 |
| 固定目标 or 多选 | 门可以固定通一个地方，也可以给玩家选 |
| 公开 / 隐藏 / 私有 | 控制谁能看见、谁能用 |
| 旗标（flags） | 逐门定制行为 |
| 名字与颜色 | 门名、网络名可染色，支持 RGB |
| 跨世界 / 跨服 | 跨服需要 BungeeCord 支持 |
| Vault 经济 | 创建 / 销毁 / 使用可以收费 |
| Dynmap 集成 | 门在地图上标出来 |
| API | legacy 版有 API，供插件接入 |
| 权限分级 | 精细到不同操作 |
| 多语言 | 官方维护翻译 |

> **载具传送是实用功能里最被低估的一项**。矿车、船、驴子、末影船都能过门，等价于给自己省了一路铺铁轨。对农场和交通向的服很值。

### 8. 常见问题

**门建了但按钮没反应**
检查门框是否完整。legacy 版有个设计——**门被破坏后会禁用所有往来**，并给其他门发通知。所以别人能看到「这个门坏了」。

**跨世界传送把人传错地方**
跨世界/跨服的坐标处理在某些版本有过问题。**升级前备份 `plugins/Stargate/`。**

**老版本的门数据不认**
legacy 版号称兼容 2013 年后所有 Bukkit 系分支的数据迁移，但**「尽量支持」不等于「一定支持」。** 迁移前备份，出问题去 Discord。

**CraftBook 装了之后矿车过不去**
CraftBook 的自动移除矿车/船功能会和新生成的载具 NBT 冲突。legacy 提供了对应的兼容开关，**开这个才会正常传送**。这一条在官方文档里有明确说明。

**版本上装不了 legacy**
legacy 通道支持到 MC 1.21.3 一档。老版本另有 ESR 归档版本（早到 1.8）。**按你的 MC 版本选对应通道**，别拿错。

### 9. 什么时候别用它

- **服务器很小、人少** → 走路就够，传送门系统是纯复杂度
- **你不希望玩家自由建门** → 它的核心卖点就是玩家自主，锁死权限就失去意义了
- **群组服但没配好跨服** → 跨服传送需要额外配置，不是装上就有

### 10. 关于汉化

**没有核实到当前渠道的中文语言文件名与机制。**

（补充背景：项目历史上曾把**简体中文**列在支持语言里，但**具体语言文件名、存放位置、当前 legacy 通道是否仍内置，本站未核实**。）

不写猜测的路径。引导式排查：

1. 解压 jar，看 `resources/` 下的语言资源目录
2. 启动后看 `plugins/Stargate/` 下生成的文件
3. 官网 `sgrewritten.org` 有专门的翻译页面（历史上叫 Languages / translate），**去那里看当前版本实际支持哪些语言**——这是最权威的来源
4. 门牌告示牌的文字格式通常也可配置，翻配置文件找告示牌相关段落

> 如果你要的是「把门牌显示成中文」和「把系统提示改成中文」，这两件事可能在不同地方配。别混。
