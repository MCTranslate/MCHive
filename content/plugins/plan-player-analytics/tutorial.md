## ⚠️ 先说清楚：Plan 是数据分析插件，不是权限插件

这条最容易被搞错，说明白能省很多事。

**Plan 记录并展示玩家数据，但它不管理权限、不限制任何行为。**

| 误区 | 事实 |
|------|------|
| 「装 Plan 就能看到谁作弊」 | ❌ Plan 没有反作弊功能，看到作弊行为要靠 Vulcan 之类的反作弊插件 |
| 「Plan 能限制玩家挂机时长」 | ❌ 它只是**记录**时长，处罚要靠别的插件读它的数据或自己写逻辑 |
| 「Plan 的数据能当权限依据」 | ❌ **不要这么设计**——权限判断要用 LuckPerms 这类权限插件 |
| 「装了 Plan 就能查某人在线多久」 | ✅ 这个是真的，这是它的核心功能 |

Plan 的定位是**给服主看数据的仪表盘**。它的数据也可以被别的插件读取，但**Plan 自己不做判断**。

**为什么值得说这个：** 有些服主以为装了 Plan 就「有反作弊了」，结果外挂玩家照常在线。Plan 只是把画面记下来，不报警。

## Plan 安装教程

### 1. 它到底收集什么

| 数据类别 | 具体内容 |
|---------|---------|
| 玩家会话 | 每次进服/退服的时间、IP、UUID、客户端版本 |
| 在线时长 | 单次时长、日/周/月累计 |
| 活跃度 | 首次加入时间、最后在线时间、活跃天数曲线 |
| 服务器性能 | TPS 走势、MSPT、内存、CPU、磁盘 |
| 事件 | 玩家死亡、登录、登出、注册 |
| 世界 | 每个世界的访问频次（需世界数据） |

**性能数据是 Plan 最有价值的部分。** 「晚上 8 点 TPS 掉到 14」这种信息，比任何猜测都有用。

### 2. 版本与前置

**当前版本 5.8+build.3638，支持 MC 1.12.2 - 26.3。**

**1.12.2 是下限**——比你以为的要低，这个插件的 MC 兼容范围很宽。

前置：

| 依赖 | 必需性 | 说明 |
|------|-------|------|
| 数据库 | ✅ 必需 | 默认 SQLite，详见第 4 节 |
| 权限插件 | 可选 | 控制谁能看报表 |

**没有硬依赖的前置插件。** 装 jar 重启就能用。

### 3. 安装

1. 下载 jar（服务端 / Velocity / BungeeCord 三个平台要分清）放进 `plugins/`
2. 重启服务器
3. 首次启动生成 `plugins/Plan/` 目录和数据库文件
4. **报表网页需要一个 `bungee`/反向代理之外的方式访问**（详见第 5 节）

**平台搞错是最常见的问题。** 群组服里 Velocity 装 Velocity 版、后端装 Paper 版，别搞反。**搞反了数据不通，报表一片空白。**

### 4. 数据库：这是 Plan 最需要动脑子的地方

Plan 默认用 **SQLite**——不需要装数据库，图省事。

但 SQLite 有硬限制：

| 规模 | 建议 |
|------|------|
| 50 人以下 | SQLite 完全够 |
| 50-200 人 | 建议换 MySQL/MariaDB |
| 200+ 人、多服 | **必须** MySQL/MariaDB，SQLite 会成为写入瓶颈 |

**为什么大服要换：** Plan 每次登录、每次退服、TPS 每次采样都要写库。SQLite 是单文件单写者，高并发写入会锁表，表现为**服务器卡顿**。

数据库连接配置在 Plan 的配置文件里。**具体配置键名以你手上版本的配置文件注释为准**（不同版本的 database 段落结构不同）。

**换数据库的顺序不能错：**

```
1. 停服
2. 配好数据库连接
3. 删掉旧的 SQLite 文件（或改数据库类型）
4. 启动
5. 数据是新开始的（不迁移旧数据）
```

> ⚠️ **Plan 有 `/planmigrate` 这类迁移命令，但**别指望它跨数据库类型搬家。**换数据库基本等于重新开始统计数据。** 决定换之前想清楚。

### 5. 报表访问

Plan 会生成可交互的网页报表。访问方式取决于你的部署架构：

| 部署 | 访问方式 |
|------|---------|
| **群组服（Velocity）** | 在 **Velocity 端**装 Velocity 版 Plan，报表从代理端出，最省事 |
| 单服 Paper | 在 Paper 端装，报表走插件自带的轻量 Web 接口 |

> ⚠️ 报表界面暴露了玩家 IP 和会话数据。**别把它直接暴露在公网不加保护。** 至少做到：内网访问、或者加一层 Basic Auth、或者限制在 VPN 后面。

**群组服强烈建议只在代理端装一份。** 每台后端都装一份会导致数据割裂，报表没法看全服。

### 6. 常用命令

| 命令 | 说明 |
|------|------|
| `/plan` | 主命令（帮助、状态） |
| `/planb` | 在控制台执行（无 `/` 前缀），BungeeCord 端用 |
| `/planplayer <玩家>` | 查某个玩家的详细数据 |
| `/planmigrate` | 迁移数据 |
| `/plangenesis` | 关闭/重置统计（谨慎） |

> ⚠️ **具体命令与权限节点以你版本的 `plugin.yml` 为准。** Plan 的命令历史上改过多次（`/plan players`、`/plan server` 这类子命令在不同版本存在与否不一样）。**装完敲 `/plan` 看实际有什么。**

### 7. 数据保留：真正需要注意的地方

Plan 的数据库**会一直长大**。

日志类数据的增长速度和在线人数正相关。100 人活跃服，一年下来数据库到**几个 GB** 是很正常的。

**必须配的东西：**

| 配置类别 | 作用 |
|---------|------|
| 数据保留天数 | 超过多少天的数据被清理/聚合 |
| 事件类数据开关 | 死亡/登录等事件日志要不要记 |

**不配保留策略的后果：** 一年后 SQLite 文件几个 G，备份要备份半天，删服务器上的备份也占地方。

> ⚠️ **「保留天数」的具体配置键名以你版本的配置文件注释为准。** Plan 里这个设置的位置随版本变过。**别照抄任何教程（包括本站）里的键名——直接翻你手上那份配置的注释。**

### 8. 常见坑

**报表一片空白 / 看不到数据**
- 群组服里 Velocity 端和后端端版本装了不同平台（Paper 版装到 Velocity 上）→ **重装正确平台的 jar**
- 数据库连接失败 → 看控制台报错
- 只装了后端没装代理端，想看全服数据 → 数据是分散的，看不到

**服务器变卡了，装完 Plan 之后**
- 还在用 SQLite，人数上来了 → 换 MySQL
- 数据保留没配，数据库疯长 → 配保留策略

**数据统计不准 / 掉数据**
- 服务器非正常关闭（进程被 kill、崩溃）→ 最后一点数据没写进去
- 数据库扛不住写入 → 又是 SQLite 的问题

**和别的统计插件重复**
装了 Plan 又装了统计类插件，两个都在写库。**选一个。** 重复统计不增加价值，只增加开销。

**TPS 曲线是空的**
TPS 采样可能需要在配置里开启（不是所有版本默认开）。**查配置里的采样相关段落。**

### 9. 关于汉化

**本站未核实到 Plan 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/Plan/`，看有没有语言文件目录
2. 搜配置文件里有没有 `language`、`locale` 相关的段落
3. **注意区分两个界面**：
   - **游戏内的 Plan 消息**（`/plan` 的回显）—— 服务端发出，通常在语言文件里
   - **网页报表的界面文字** —— 报表是**前端资源**，往往是打包进 jar 的静态文件或远程加载的，**改服务端配置不会生效**
4. 如果报表界面是打包资源，唯一的汉化途径是**替换前端资源文件**——这对版本升级很不友好，升级后要重做

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **想知道「谁在作弊」** —— 它不做判断，用反作弊插件
- **服务器 10 个人、每天看一次** —— 控制台 `/plan` 就够，数据库可以不要
- **已经有 BStats 之类的统计** —— 两者不冲突，但 BStats 是匿名的总体统计，Plan 是你自己服的具体数据，可以共存
- **服主不想处理数据库** —— Plan 是**必须配数据库**的插件，这是它相比 BStats 的主要成本
