## ⚠️ 先看这里：squaremap 需要外部 HTTP 服务

**这是 squaremap 和 BlueMap 最大的区别，也是最容易卡住新人的地方。**

BlueMap **自带 Web 服务**，装完就能打开 `http://IP:8100/`。

**squaremap 不带。** 渲染出来的地图是**静态文件**放在磁盘上，你**必须**自己准备一个 Web 服务器（Nginx / Caddy / Apache）来伺服这些文件。没有外部 HTTP 服务，squaremap 渲染得再好，浏览器也打不开。

```
BlueMap:     插件 → 渲染 → 内置 Web 服务 → 浏览器打开  ✅
squaremap:   插件 → 渲染 → 磁盘上的静态文件 → 你自己 → Nginx → 浏览器  ⚠️
```

**为什么这么设计：** 静态文件伺服是 Nginx 的强项，让它干这个比让 Java 进程干更省资源、更稳定。这是合理的取舍，但代价是部署门槛。

**如果你不想搞 Nginx，选 BlueMap。**

## squaremap 安装教程

### 1. 它和 BlueMap 怎么选

两者是同类竞品，都做「把世界渲染成网页 3D 地图」。差别如下：

| 维度 | **squaremap** | **BlueMap** |
|------|-------------|------------|
| Web 服务 | ❌ **要自己配** | ✅ 内置 |
| 内存占用 | **低** | 较高 |
| 3D 地形渲染 | ✅ | ✅ |
| 洞穴 / 地下渲染 | ✅ | ✅ |
| 玩家点位 | ✅ | ✅ |
| 标记 API | 基础 | 更丰富（Marker API 文档完善） |
| 资源包上传 | 有 | 有 |
| **适合** | 小到中型服、内存紧张、已有 Nginx | 想要开箱即用、要用复杂标记 |
| **不适合** | 不想碰外部 Web 服务 | 内存极度紧张的服 |

**结论：**

- **内存吃紧、或者你已经有 Nginx** → squaremap
- **第一次装地图插件** → BlueMap（少一道坎）
- **需要复杂标记（传送点、领地可视化）** → BlueMap 的 Marker API 文档更成熟

> 注意别和 **Dynmap** 搞混。Dynmap 是老牌地图插件，但**它的新版 MC 支持已经落后**，和上面两个不在一个量级。本站另有 BlueMap 的说明页做更详细的对比。

### 2. 版本要求

**支持 MC 1.19.3 - 26.3。**

**1.19.3 是比较硬的下限。** 如果你的服在 1.19.2 或更低，squaremap 直接用不了，这个要先确认。

需要 **Paper 系服务端**（Paper / Purpur 等）。别在 Spigot 上试。

### 3. 安装

1. 下载 jar 放进 `plugins/`，重启
2. 生成 `plugins/squaremap/`
3. **配置 Web 路径**（关键一步）
4. 启动渲染
5. **自己搭 Nginx 伺服 Web 目录**

第 3 步和第 5 步是 squaremap 特有的，BlueMap 没这些。

### 4. 配置要点

配置在 `plugins/squaremap/` 下。**具体键名以你手上版本的配置文件注释为准。** 逻辑上涉及这几类：

| 配置类别 | 管什么 | 说明 |
|---------|-------|------|
| Web 服务路径 | 渲染出来的网页文件放哪 | 指向你的 Nginx 站点目录 |
| 允许下载资源 | 是否允许下载渲染所需资源文件 | 首次配置必须放开，否则地图缺材质 |
| 渲染线程 | 用多少线程渲染 | 吃 CPU，默认别调高 |
| 地图列表 | 渲染哪些世界 | 主世界 + 资源世界 + 副本世界 |
| 标记 | 传送点、出生点、领地标记 | 可选 |

**「允许下载资源」这一项首次装必须开。** 关着的话地图能渲染出地形和方块，但材质是空白的——很多人以为装坏了，其实是这一项。

**Web 服务路径配错的典型症状**：渲染完成、控制台显示无错、浏览器打不开或页面空白。**先去检查那个路径是不是 Nginx 站点能读到的目录。**

### 5. 渲染启动

装完和配完路径之后，需要**主动启动渲染**。渲染在后台异步跑：

- 吃 CPU 但**不卡主线程**（这是渲染器的设计目标）
- 首次全图渲染在大世界可能要**几小时到几十小时**
- 渲染进度可以在控制台查看

**大地图要提前规划磁盘。** 渲染结果占多少空间取决于世界面积和缩放级别——第一次渲染前先算一下，别把硬盘撑爆。

### 6. 用 Nginx 伺服（关键步骤）

既然 squaremap 不带 Web 服务，这步得自己做。最小配置：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    root /path/to/squaremap/web;   # 和 squaremap 配置里的 Web 路径一致
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

**两个注意点：**

- `root` 要和 squaremap 配置里的路径**完全一致**，写错就是白屏
- **不要给 Nginx 配 `proxy_pass` 到 Java 端口**——squaremap 没有这个端口可代理。**它就是纯静态文件伺服**

改完 Nginx 配置后 `nginx -t` 检查语法，然后 reload。

> 正式服**建议直接上 HTTPS**。地图会显示你的世界全貌、玩家点位、传送点，裸 HTTP 既不安全也容易被搜索引擎收录。

### 7. 常用命令

| 命令 | 说明 |
|------|------|
| `/squaremap` | 主命令，看状态和帮助 |
| `/squaremap reload` | 重载配置与标记 |
| `/squaremap render` | 启动/管理渲染 |
| `/squaremap zoomlock` 类命令 | 缩放锁定相关（具体子命令以实际输出为准） |

> ⚠️ **以你版本的 `/squaremap` 帮助输出为准。** 地图插件的子命令随版本变动较多，这里不逐条默写。

### 8. 常见坑

**渲染完了但网页打不开 / 白屏**
九成是**Web 路径和 Nginx 的 `root` 对不上**。这几乎是 squaremap 的头号问题。

**地图没有材质（一片空白/纯色）**
「允许下载资源」那项没开。地图只画几何体，材质要另外下载。

**直接访问 MCP 端口打不开**
**squaremap 没有 Web 端口可访问。** 别在 `server.properties` 里找端口设置——它不开服务。

**渲染吃满 CPU**
渲染是后台线程，但如果线程数配得高，还是会影响主线程的 tick。**用默认线程数**，别手动调高。

**磁盘满了**
渲染结果 + 备份 + 世界文件挤在一起。渲染前算空间。渲染完可以调低缩放级别重新渲染来省空间。

**和 Dynmap / BlueMap 同时装**
**别装。** 三个地图插件会同时渲染，白白吃三份 CPU 和磁盘。而且玩家能访问三个地图站，体验混乱。选一个。

### 9. 关于汉化

**本站未核实到 squaremap 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/squaremap/`，看有没有 `lang/` 或类似目录
2. 用编辑器搜配置文件里有没有 `language`、`locale`、`locale_name` 这类段落
3. **注意区分「插件消息」和「网页界面」是两条路**：
   - 插件消息（控制台输出、聊天栏回显）走服务端配置
   - **网页地图的界面文字往往是硬编码在 HTML/JS 里的**——如果是这种情况，服务端改任何配置都不会生效
4. 网页地图的界面文字，唯一的办法是**改渲染出来的静态文件**——**但那些文件会被下次渲染覆盖**，改了就白改

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **1.19.2 及以下的老服** —— 不支持
- **不想碰 Nginx** —— 选 BlueMap
- **想要成熟的标记 API**（传送点、领地边界、复杂图标）—— BlueMap 文档更全
- **只有 1-2 个玩家的小服** —— 没人会去看网页地图，渲染纯浪费磁盘
