## AxGraves 安装教程

### 1. 它解决的问题

**原版死亡掉落的三个老问题：**

| 问题 | 场景 |
|------|------|
| **掉落撒一地** | 死的地方被人捡走 / 掉进岩浆烧掉 / 掉进虚空 |
| **被延迟挖走** | 死亡后坐标就在那broadcast着，PvP 时被人抢先捡装备 |
| **找不回来** | 死得太远，记不清坐标，装备就永久没了 |

AxGraves 的做法：**把掉落物封进一个「墓碑」方块里**，玩家（或有权限的人）打开墓碑取回。

```
原版：  死亡 → 物品散落在地上 → 谁先到谁拿走
墓碑：  死亡 → 物品进墓碑 → 只有能找到墓碑的人能拿
```

### 2. 但要诚实地说：这**不是**完全防偷

**这一点必须讲清楚，不然玩家会觉得插件没用。**

墓碑防不住的情况：

| 情况 | 说明 |
|------|------|
| **别人能看到你的墓碑坐标** | 坐标会公开（这是它的设计——不然玩家找不到自己的墓碑）。**别人看到坐标，照样能挖** |
| **PvP 现场被补刀** | 对方站在你尸体旁边，墓碑生成在脚下了 |
| **队友/熟人拿** | 联机基建的场景下，队友捡你的装备根本不是什么问题 |
| **GriefPrevention 保护被绕过** | 保护没配好的话 |

**所以它的真实定位是：**

- ✅ **减少掉落物散落导致的意外丢失**（掉岩浆、掉虚空、跑太远）
- ✅ **给一个明确的「回来取」位置**（比记坐标靠谱）
- ⚠️ **增加一点偷取难度**（不是防住，是提高门槛）
- ❌ **不是防偷插件**

**如果你的服 PvP 是核心玩法，靠墓碑防装备被摸是不现实的。** 需要更强的是别的机制（护甲保护、死亡掉落上限、限时保护）。

### 3. 什么时候真的有用

| 场景 | 有用程度 |
|------|---------|
| **生存服，意外死亡为主** | ⭐⭐⭐ 很实用 |
| **联机建筑 / 朋友基建的服** | ⭐⭐⭐ 大家互相拿装备，墓碑让「谁的」变清楚 |
| **长期生存档，死亡后跑很远** | ⭐⭐⭐ 找回是真的重要 |
| **硬核 PvP** | ⭐ 帮不上什么忙 |
| **服务器有领地保护** | ⭐⭐⭐ 墓碑也可以被保护，见第 6 节 |

**第一个场景是最典型的。** 玩家在野外被骷髅打死，装备掉进岩浆了——**这个痛点非常真实**，而且没人会因此失去兴致。

### 4. 版本与依赖

**支持 MC 1.18 - 26.3。**

- 无硬依赖
- 可选：领地保护（**实际强烈建议**，见第 6 节）

**1.18 是下限。**

### 5. 安装

1. 下载 jar 放进 `plugins/`，重启
2. 生成 `plugins/AxGraves/`
3. 配置参数
4. 确认保护设置

**不需要额外资源包。** 这是它比 GSit 那种姿势插件省事的地方——**纯服务端逻辑，玩家不需要装任何东西。**

### 6. ⚠️ 必须做：保护墓碑

**墓碑本身是能被破坏/打开的。** 不保护的话：

```
玩家死了 → 墓碑生成
别人走过来 → 打开墓碑 → 装备拿走
玩家回来 → 墓碑是空的
```

**保护措施：**

| 措施 | 说明 |
|------|------|
| **墓碑生成在玩家自己领地内时** | 由领地保护管着，这部分天然安全 |
| **给墓碑方块设保护** | 很多保护插件支持「把这类方块设成不可破坏」——**以你的保护插件实际支持情况为准** |
| **限制谁可以打开别人的墓碑** | 这是**最有效的一条**。默认应该只有主人能开 |
| **PvP 期间加保护期** | 有些实现支持「死亡后短时间内墓碑受保护」 |

**「谁可以打开谁的墓碑」是重点。** 如果插件支持「只有主人能开自己的墓碑」，那这个插件的价值立刻上一个台阶。**装完第一件事就是确认这个逻辑在不在、默认设置是什么。**

> 具体配置键名以你版本的配置文件注释为准。**本页不列键名**——这类插件的配置结构随版本变过，写错的键名比不写更坑。

### 7. 常用命令

| 命令 | 说明 |
|------|------|
| 主命令（查看帮助） | 一般包括列出自己的墓碑、打开自己的墓碑等 |
| `/tpa` 类传送配合 | 找墓碑很常用（配合 SimpleTPA 之类） |

> ⚠️ **具体命令以你版本的帮助输出为准。** 墓碑类插件的命令通常比较简略，但**命名不一定统一**，不写死。

**实际最需要的「命令」是：找到一个墓碑并过去。** 这方面通常靠：
- 墓碑生成时给玩家发坐标/消息
- 玩家自己用 `/tpa` 让队友带过去
- 或者用地图插件（[squaremap](#/plugin/squaremap) / [BlueMap](#/plugin/bluemap)）在网页上看到墓碑位置

**如果你的服有网页地图，墓碑可以被标在地图上** —— 这对「找墓碑」的体验提升很大。

### 8. 常见坑

**墓碑被偷了**
见第 2 节和第 6 节。**「谁可以打开」这一项配了吗？**

**墓碑丢了 / 找不到**
- 死亡的世界不一样（不同维度的墓碑）
- **区块被加载/卸载了** —— 墓碑所在的区块必须加载才能交互。**玩家离太远时墓碑「不在」**
- 世界删了/重置了
- 进了末地，墓碑在下界

**死亡时背包是满的**
如果插件有「需要有空位才能生成墓碑」这类逻辑（防刷），玩家会遇到这个。**以你版本的说明为准。** 满背包死亡时物品去哪了，**一定要自己测一遍确认**——这是最不该有歧义的地方。

**和 CoreProtect 冲突**
CoreProtect 记录方块操作。**墓碑生成/打开是方块操作，会被记进去。** 这本身不是问题，但你可能不希望墓碑也进 CoreProtect 的记录——会导致「墓碑被打开」也被当成方块改动记录。**具体表现以实测为准。**

**PvP 结束后的墓碑怎么处理**
这是设计上要决定的：
- 一直留着（占地图/占实体）
- 自动清理（**但玩家没回来拿就永久丢了**）

**这个取舍要想清楚。** 很多服的做法是**保留较长时间**（一周之类），但要有清理机制，否则服务器里堆满空墓碑方块。**清理时长以你版本的配置能力为准。**

**和别的死亡/掉落插件冲突**
死亡处理、物品掉落逻辑很容易撞车。**同时只留一个处理死亡掉落的插件。**

**PvP 玩法被削弱**
如果你的服的核心是「抢装备」，墓碑会削弱这个。**这是设计取舍，不是 bug。** 硬核 PvP 服不该装这个。

### 9. 关于汉化

**本站未核实到 AxGraves 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/AxGraves/`，看有没有语言文件目录
2. 搜配置文件里有没有 `message`、`language`、`locale` 段落
3. **注意区分**：
   - **墓碑方块上的显示文字**（如果墓碑上有可交互的告示牌/名牌）—— 这部分**往往不走语言文件**，而是拿玩家名/自定义文本
   - **游戏内的提示消息**（生成墓碑时的提示、打开时的提示）—— 服务端发出，可能在语言文件里
4. 如果墓碑上有硬编码英文（比如「XXX 的物品」），**这可能是需要改代码才能汉化的部分**

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **硬核 PvP / 抢夺装备为核心玩法** —— 直接削弱玩法
- **已经有别的死亡处理插件** —— 会冲突
- **玩家从不在乎死亡掉落**（比如纯创造/建筑服）—— 没必要
- **服务器死亡率极低**（基本不死）—— 用不上

### 11. 搭配：想要完整的死亡体验

**AxGraves 解决的是「东西找得回来」，其他环节要别的插件：**

| 需求 | 靠什么 |
|------|-------|
| 掉落能找回 | **AxGraves** |
| 小误操作能回滚 | [CoreProtect](#/plugin/coreprotect) |
| 死亡点传送 / 回血 | 其他生存类插件 |
| 地图上看到墓碑 | [squaremap](#/plugin/squaremap) / [BlueMap](#/plugin/bluemap) |
| 墓碑不被偷 | 领地保护 + 本插件的权限设置 |

**别指望一个插件解决所有死亡相关的问题。**
