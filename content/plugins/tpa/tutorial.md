## 它的价值在「确认」这一步

`/tp` 直接传送，任何人能在你看不见的地方把你拉走。TPA 的做法是**加一次确认**：

1. A 想传送到 B，发请求
2. B 收到提示，选择接受或拒绝（有时还有超时）
3. 接受后 A 才真的传送

**这一步消掉了传送类插件最大的两个问题**：被莫名拉走，和被反复骚扰。

这类插件通常是原版 `/tp` 的替代品——**很多服务器的核心自带 `/tp` 和 `/tpa`，装这个插件的意义在于覆盖和扩展那套行为**（加冷却、加落地保护、支持反向请求）。

## ⚠️ 版本范围很窄

**这个版本只声明支持 MC 1.20.1。**

这不是笔误，是这个插件当前的真实状态。意味着：

| 你的服 | 能用吗 |
|--------|--------|
| 1.20.1 | 能 |
| 1.20.0 / 1.20.2+ | **不保证**，属于未声明支持 |
| 1.19 / 1.18 / 1.21+ | **不保证** |

**如果你不确定自己的版本符不符合，先装了在测试服验证。** 传送类插件逻辑简单，兼容性风险比大型插件低，但 1.20.1 是个具体版本点，不是范围——跨小版本就是没测过。

> ⚠️ 本站**未核实到该插件的官方发布仓库地址**。`TPA` 是极常见的插件名，SpigotMC / Modrinth / Hangar 上有大量同名项目，其中不少是**同一作者的不同分叉**。**认准作者和 jar 内 `plugin.yml` 的作者字段**，别装到一个你从没听过的分叉上。

## 安装

1. jar 丢进 `plugins/`
2. 启动一次生成配置
3. 重启

**装完先自测一遍完整流程**（发请求 → 接受 → 落地），再开放给玩家。传送类插件的问题通常在边界情况（跨世界、离线、超时），自测比看文档快。

## 核心命令

TPA 类插件的命令名是行业惯例，`tpa` / `tpaccept` / `tpdeny` 基本是通用的。具体命令和权限节点**以你版本的官方文档和配置注释为准**。

| 命令 | 作用 |
|------|------|
| `/tpa <玩家>` | 请求传送到对方那里 |
| `/tpaccept [玩家]` | 接受请求 |
| `/tpdeny <玩家>` | 拒绝请求 |
| `/tpasend <玩家>` / `/tpahere <玩家>` | 反向请求（让对方传送到你这） |
| `/tpcancel` | 取消自己发出的请求 |

**冷却和超时是这类插件的标配**：请求挂太久不处理自动过期，同一个人反复请求会被冷却限制。这两个行为是防骚扰的核心，不要关掉。

## 配置要调什么

**具体键名、文件路径以官方 config.yml 注释为准。** 本站不列配置键。

真正需要你做决策的是这几项：

| 项 | 决策点 |
|---|---|
| 冷却时间 | 太短挡不住骚扰，太长正常玩家互相传送会烦。**先从 30-60 秒起步** |
| 请求超时 | 挂多久自动作废 |
| 是否需要落地保护 | 传送后短暂无伤，避免摔死——**这个建议开着** |
| 关闭时的行为 | 玩家下线时请求怎么处理（保留 / 清除） |
| 跨世界是否允许 | 全服互通还是限制范围 |
| 战时是否禁用 | 战斗中能不能传送 |

**落地保护值得单独提一句**：传送落地摔死是玩家最气的传送类问题之一，摔死还掉东西的话投诉量会很大。

## 常见坑

**发了请求对方收不到提示**
- 目标玩家没装这个插件（**有些服只装了部分玩家的客户端能用的功能**）
- 权限没给全
- 目标正忙（战斗中 / 冷却中 / 被限制）

**传送后卡在方块里 / 摔死**
落地保护没开，或者目标位置是实心方块。**传送的落点计算是这类插件的核心逻辑，也是最容易出 bug 的地方。**

**和 EssentialsX 的 `/tpa` 冲突**
**同类功能只能有一个。** 如果你已经装了 EssentialsX 并且能用 `/tpa`，装这个插件之前先想清楚：你是要**换掉** EssentialsX 的实现，还是**增强**它。**两个都留着，命令会打架。**

**世界名带空格 / 特殊字符**
跨世界传送时目标定位出问题。比较少见，但排查传送异常时可以想到这一条。

**玩家用命令刷请求**
冷却被绕过或者被关掉了。**传送请求是骚扰的常见入口**，冷却别关。

**权限体系**
传送类权限要和你的权限设计对齐——**谁可以传送到谁、谁可以发反向请求、战时谁被禁止**，这些应该提前想清楚，不要让默认配置决定。

## 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

**这个插件的命令提示是玩家可见文案**，所以汉化的收益是实打实的——「传送请求已发送」「对方拒绝了你的请求」这类句子玩家天天见。

排查方式：

1. 启动一次服务器，看插件数据目录里生成了什么文件
2. 在生成的文件里搜 `lang`、`locale`、`message`、`translat`
3. 看有没有 `_zh_CN` 之类的中文变体结构

**更常见的情况是提示文字直接写在配置文件里**，不是独立的语言文件。**如果是这种情况，直接改配置里的字符串就行**，改之前备份。

更系统的汉化思路见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
