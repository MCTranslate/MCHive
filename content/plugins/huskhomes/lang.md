# HuskHomes 汉化机制

> ⚠️ **本节结论尚未完成独立核实，请谨慎对待。**
>
> 编写时曾定位到 HuskHomes 官方仓库中含 `zh-cn` 与 `zh-tw` 两个中文语言文件（共 17 个语言文件），但**本站复核时无法通过公开渠道重新定位到该仓库**（jsDelivr 对 `William278/HuskHomes` 的多个分支与版本均返回 404）。
>
> 在你实际使用前，**请以服务器上生成的目录为准**：启动一次后看它生成了哪些语言文件。如果里面有 `locales/` 目录且带 `zh-` 开头的文件，说明汉化确实存在，照下面的方法切换即可。

## 一、预期结论：应当自带简繁中文

按编写时的核实结果，HuskHomes 的语言文件结构是：

```
plugins/HuskHomes/locales/
├── en.yml        ← 英文（基准）
├── zh-cn.yml     ← 简体中文
└── zh-tw.yml     ← 繁体中文
```

当时记录的语言列表包含保加利亚语、德语、西班牙语、法语、意大利语、日语、韩语、波兰语、巴西葡萄牙语、俄语、土耳其语、乌克兰语、越南语，以及简繁中文共 17 个。

**以你实际目录为准**——不同版本的目录名和文件名可能变化。

## 二、怎么切换

预期是**默认跟随玩家客户端语言**，简体客户端自动生效。

想强制统一，在 `plugins/HuskHomes/config.yml` 里找 `locale` 相关配置项改成 `zh-cn`。**具体配置键名请以你手上版本的 `config.yml` 为准**，不要照抄本节。

## 三、能汉化的是什么

按编写时的核实，HuskHomes 的语言文件覆盖玩家能看到的全部文本：

| 内容 | 是否汉化 |
|------|---------|
| 家的列表菜单 | ✅ |
| 传送请求相关提示 | ✅ |
| 系统消息（成功/失败/无权限等） | ✅ |
| 命令帮助 | ✅ |

## 四、想改文案

1. 找到 `plugins/HuskHomes/` 下的语言覆盖目录（**具体结构以你版本实际生成的目录为准**）
2. 复制一份 `zh-cn.yml` 进去改
3. 完整重启服务器

**不要直接改 jar 里的文件** —— 升级就没了。

## 五、没找到中文语言文件怎么办

如果你的 `plugins/HuskHomes/` 目录里**没有**带 `zh-` 的文件，说明这个版本不带中文。可以：

1. 去插件的 Discord / GitHub Issues 问维护者有没有汉化计划
2. 自己补：在 `locales/` 下建 `zh-cn.yml`，对照 `en.yml` 逐条翻译。YAML 格式，保存时**必须用 UTF-8**
3. 或者用运行时翻译类插件

## 六、三个容易踩的坑

**改了没生效**

语言文件在启动时读取。改完**必须完整重启**，`/reload` 不行。

**占位符被删了**

语言文件里有 `%player%` 这类占位符。翻译时只换文案，别动占位符，否则玩家名字会显示不出来。

**用记事本存成了 ANSI**

YAML 文件必须存 **UTF-8**。存成 ANSI/GBK 会导致解析失败，症状是菜单显示乱码甚至整个配置文件读不出来。
