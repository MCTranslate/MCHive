# SkinsRestorer 汉化机制

> 以下结论来自对官方仓库文件树的核实。**这不是「没查到」，是它确实没有语言文件。**

## 一、结论：没有独立语言文件

你在 `plugins/SkinsRestorer/` 目录里**翻不到任何** `lang/`、`messages_*.yml`、`*.properties` 语言文件。这是设计如此，不是安装失败。

界面文本走的是两条完全不同的路：

| 界面部分 | 语言来源 | 简体中文客户端下显示什么 |
|---------|---------|----------------------|
| 原版 GUI 框架元素（物品槽、按钮边框、标题栏背景） | Minecraft 客户端的可翻译组件 | **中文**（跟随客户端语言） |
| 菜单按钮上的固定文字 | 插件代码里**硬编码的英文字符串** | **英文**（不跟随） |

所以实际效果是：**框架是中文，按钮文字是英文**，混在一个界面里。

## 二、为什么是这个结果

Minecraft 的可翻译文本（比如 `block.minecraft.stone`、`gui.done`）由**客户端**提供语言包。插件只要用原版已有的组件类型，客户端就能自动翻译。

但菜单按钮的标签——比如「应用」「下一页」「清除」这类插件自己定义的语义——**原版语言包里没有对应条目**，插件只能自己写字。写死在代码里还是放在语言文件里，是作者的选择。SkinsRestorer 选择了前者。

## 三、想汉化，只有三条路

### 路线 1：自己改 jar（不推荐）

解包 jar → 找到写死字符串的 class 文件 → 修改 → 重新打包。

| 优点 | 缺点 |
|------|------|
| 效果直接 | 每次升级都要重做一遍 |
| 能汉化所有硬编码文本 | 改编译产物容易出错，改坏了插件直接不加载 |
| | 15.12.6 升 15.12.7 你就得再来一次 |

**只适合**：自己长期维护的私服，愿意每次升级跟一次。

### 路线 2：不汉化，改用法

很多服的做法是**绕开菜单**：

- 用 `/skinset <玩家> <皮肤名>` 命令直接下发，不让玩家进 GUI
- 配合皮肤站自己的默认皮肤，玩家根本看不到 SkinsRestorer 的界面
- 服主公告里写「进游戏后输入 `/skinskin` 重载皮肤」，不要提菜单

对运营服来说这往往是**最省事**的解法——玩家不需要那个菜单。

### 路线 3：用外部插件补一层

某些功能（如给玩家发皮肤、批量管理）用别的插件做，SkinsRestorer 只在后台干活。**本站不推荐具体产品，需要请自行核实**——皮肤类插件质量差异很大。

## 四、常见问题

**Q：客户端语言设成简体中文，界面全中文了吗？**
没有。只有走 Minecraft 客户端可翻译组件的那部分是中文，插件硬编码的按钮文字还是英文。

**Q：有没有配置项能切语言？**
本站未核实到 SkinsRestorer 存在语言切换配置项。**不要相信论坛上说「改 config 里的 locale」的说法**——那多半是把别的插件的经验套过来了。以你手上版本的 `config.yml` 实际注释为准。

**Q：能不能用别的语言文件覆盖？**
不能。仓库里没有语言文件机制，放一个文件进去插件不会去读它。

**Q：菜单文字是英文就没法用了吗？**
能用。功能完全不受影响，只是界面观感问题。皮肤菜单本身交互很简单（搜索 + 点选），玩家第一次用之后就不看那些英文标签了。

## 五、与其他插件对比

| 插件 | 独立语言文件 | 简繁中文 |
|------|------------|---------|
| **SkinsRestorer** | ❌ 无 | ❌ 硬编码英文 |
| Carbon | ✅ `messages-zh_CN.properties` | ✅ 简 + 繁 |
| GSit | ✅ `zh_cn.yml` / `zh_tw.yml` | ✅ 简 + 繁 |
| Maintenance | ✅ `language-zh_tw.yml` | ⚠️ **仅繁体** |
| LifestealZ | ✅ `zh-CN.yml` | ✅ 简 + 繁 |

想找自带完整中文语言文件的插件，看本站的 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
