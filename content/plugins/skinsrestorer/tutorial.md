## SkinsRestorer 安装教程

### 1. 它解决什么问题

原版 Minecraft 的皮肤只能在启动器（Minecraft 启动器 / 皮肤站 / Modrinth 皮肤站）里换。服务器端的皮肤修改是另一回事：

| 需求 | 原版能做什么 | SkinsRestorer 补上什么 |
|------|-------------|---------------------|
| 换自己的皮肤 | 只能去启动器换 | 游戏内 `/skinsrestorer` 打开菜单直接换 |
| 离线模式玩家换皮肤 | 做不到（要正版账号） | 用 UUID 皮肤机制，可以给离线服玩家套皮肤 |
| 强制统一皮肤 | 做不到 | 管理端可给指定玩家下发皮肤 |
| 重载自己的皮肤 | 换完要退出重进 | `/skinskin` 一条命令重载 |

「UUID 皮肤」是这个插件的核心。皮肤站（MineSkin 之类）把皮肤绑定到**玩家的 UUID** 而不是账号名。离线模式服务器的 UUID 由服务器根据玩家名生成，所以同一台离线服可以给玩家发皮肤——**这是它下载量能到 7 万+ 的主要原因**。

### 2. 安装

服务端核心需要 **API 版本 ≥ 1.8**（本插件声明支持到 26.1.1，新版服务端可用）。

1. 从 [Modrinth](https://modrinth.com/plugin/skinsrestorer) 或 GitHub Releases 下载对应平台的 jar
2. 丢进 `plugins/`
3. 重启服务器，生成 `plugins/SkinsRestorer/`

首次启动会在控制台输出**本地 Web API 端口**（用于皮肤数据交互）。这个端口是插件的正常工作部分，不是异常。

> Modrinth 上有 `-paper`、`-bungee`、`-velocity`、`-fabric` 等多种构建。**纯 Paper/Spigot 服下 `-paper` 即可**；装了 BungeeCord/Velocity 群组才需要另外两个，别混装。

### 3. 菜单长什么样

`/skinsrestorer` 打开的是**铁砧 GUI**（原版铁砧的界面）：

- 搜索框输入玩家名或皮肤名
- 结果列表点一下就应用
- 应用时有粒子特效（可关）

菜单按钮上的文字是**硬编码英文**，这一点后面「关于汉化」会详细说。

### 4. 常用命令

| 命令 | 说明 |
|------|------|
| `/skinsrestorer` | 打开皮肤菜单（给自己用） |
| `/skinset <玩家> <皮肤名>` | 直接给指定玩家下发皮肤 |
| `/skinchanger` | 打开菜单，附带针对其他玩家操作的管理入口 |
| `/skinskin` | 重载自己当前皮肤（第三方皮肤站改完用这条刷新） |
| `/skinsrestorer help` | 帮助 |

> 权限节点以你版本的 `plugin.yml` 为准。本站不逐条抄节点名——**抄错的节点名比不写更糟**，照着 `/skin` 的报错提示反查更稳。

### 5. 配置文件

配置在 `plugins/SkinsRestorer/config.yml`。**具体键名请以你手上版本的 config.yml 注释为准**——SkinsRestorer 15.x 的配置结构里有 `enabled`（是否启用皮肤系统）、`disableForVersion`（在指定 MC 版本上禁用皮肤功能）、`applyOnJoin`（进服自动应用）、`mojangAPI`（走 Mojang API 还是自建）等类别，不逐条默写。

**部署前值得检查的几件事：**

| 检查项 | 为什么重要 |
|--------|-----------|
| 是否走外部 API | 皮肤服务要联网。断网时换皮肤会失败 |
| 玩家名含中文/特殊字符 | 某些 API 对非 ASCII 名字兼容差 |
| 皮肤名大小写 | 皮肤站通常全小写，写错就是「找不到皮肤」 |
| 是否有离线服 UUID 冲突 | 离线服 UUID 由名字派生，改名后皮肤就对不上了 |

### 6. 群组服（Velocity / BungeeCord）注意事项

**这是最容易踩坑的地方。**

在群组服里，玩家在 Velocity（或 Bungee）上有 UUID，在后端服务器上又可能生成一个 UUID。**SkinsRestorer 需要在代理端和后端都装**，且配置里的 UUID 传递方式要一致。

- 只装后端 → 玩家换皮肤换个服就变回去
- 只装代理端 → 后端不知道皮肤已应用，进服又被刷回默认
- 两边都装但配置不一致 → 皮肤时有时无

**群组服请直接参考官方文档里的群组部署章节**，这块配置不是默认值能覆盖的。

### 7. 常见坑

**「皮肤找不到」**
九成是**皮肤名写错**或者**这个皮肤根本没上传到对应的皮肤站**。皮肤站的皮肤是别人上传的，不是你想要就有。

**玩家换完皮肤还是旧样子**
让他用 `/skinskin` 重载。第三方皮肤站（不是 Mojang 官方）改的皮肤，客户端本地缓存不会自动更新。

**离线服玩家皮肤全乱**
离线模式的 UUID 是**按玩家名**算的。这玩家改个名，UUID 变了，之前发的皮肤就丢了。离线服上给皮肤，认名字不认 UUID。

**换皮肤后其他玩家还是看到旧的**
客户端缓存。让他**完全退出游戏**（不是退到主菜单）重进。

**菜单点不动 / 物品和皮肤不显示**
先确认客户端连上了你的服务端没。皮肤 GUI 传输走的是插件自己的服务通道，**如果你前面挂了 CDN、Nginx 反代或某些面板的 WAF，可能把包拦掉**。表现为菜单能开、内容全空。

### 8. 关于汉化

**SkinsRestorer 仓库里没有独立语言文件。** 这不是「本站没查到」，是它确实没有：

- 菜单按钮文字是**硬编码英文**写在代码里的
- 界面框架（标题、按钮标签）走的是 Minecraft 客户端的**可翻译组件**机制

也就是说：Minecraft 客户端语言设成简体中文，**原版可翻译的部分会跟着变中文**；但**插件自己硬编码的那部分仍然是英文**。

想汉化只有一条路：自己改 jar 里的字符串重新打包。**极其不建议**——升级就白改，而且改编译产物有风险。详见 [汉化机制](#/plugin/skinsrestorer) 页。

### 9. 什么时候别用它

- **玩家都是正版账号、愿意用启动器** → 原版皮肤站 + 启动器就够了，服务器端皮肤是多余的复杂度
- **服务器只有 1-2 人** → 直接在皮肤站改，不是世界末日
- **Velocity 群组但没人懂配置** → 代理端 + 后端的双端配置很容易配到一半放弃，先看官方群组文档
