## Towny 安装教程

### 1. 它是什么

Towny 是个**有二十多年历史、至今仍在活跃维护**的老插件。它的定位不是「圈地保护」，而是**完整的城镇 / 国家玩法层**。

| 能力 | 说明 |
|------|------|
| 城镇（Town） | 玩家建镇、圈地、招居民、设镇长 |
| 地块（Plot） | 城镇内进一步细分的小区，不同权限 |
| 国家（Nation） | 多个城镇结盟建国，有国库、外交关系 |
| 税收 | 居民向镇缴税，镇向国纳税；税收驱动城镇升级 |
| 升级 | 城镇/国家靠人数和资金升级，升级解锁更多能力 |
| 战争 | 国家之间宣战、占领城镇 |
| 法律 | 每个城镇可以自己定本地法规（禁 PVP、禁破坏等） |
| 外站 | 在主世界外单独开一片「城镇世界」，不占主世界空间 |
| 权限细分 | 城镇 / 地块 / 国家 三层权限，每层还能细分到「谁能进谁的地盘」 |

**和领地插件的根本区别**：WorldGuard 解决的是「这块地谁能挖」，Towny 解决的是「一群玩家作为一个政治实体的生活秩序」。

### 2. 竞品对比：选哪个

Towny 的直接竞品是 **Residence** 和 **GriefDefender**（GriefPrevention 是单机防熊的，不是同类）。三者差别不小：

| 维度 | Towny | Residence | GriefDefender |
|------|-------|-----------|--------------|
| 定位 | 城镇 + 国家玩法 | 玩家个人领地 | 通用防熊 + 土地 |
| 税收 / 经济 | ✅ 内建 | 部分（靠 Vault） | 部分 |
| 国家 / 外交 / 战争 | ✅ | ❌ | ❌ |
| 城镇升级 | ✅ 等级系统 | ❌ | ❌ |
| 玩家圈地门槛 | 相对高 | 低 | 低 |
| 内存占用 | 高 | 中 | 中 |
| 上手难度 | 高 | 中 | 低 |
| 长期可玩性 | 最高 | 中 | 低 |
| 单机小服适配 | 差 | 好 | 最好 |

**选型建议，说直白点**：

| 你的服 | 选 |
|--------|-----|
| 想做「玩家建城、互相外交、攻城略地」的长期 RPG 服 | **Towny** |
| 想做「玩家自己家，防熊 + 少量权限」 | Residence |
| 只想要防熊，不想搞领土政治 | GriefDefender |
| 只想保护主城和资源区 | [WorldGuard](#/plugin/worldguard) 就够了 |

**Towny 最大的坑就是重**。它会为每个地块维护大量数据，城镇多了内存吃得很明显。**开服前先看 [性能调优](#/guide/performance-tuning) 和 [数据库选型](#/guide/database-setup)。**

### 3. 前置条件

| 项目 | 要求 |
|------|------|
| Java | **17 或更新** |
| MC | 1.19 或更新 |
| 平台 | Bukkit / Spigot / Paper / Purpur / Folia |

Towny **自己是个大插件**，它的功能基本自足。但这些装了体验会好很多：

| 插件 | 联动 |
|------|------|
| [Vault](#/plugin/vault) + 经济插件 | 税收要有经济才有意义 |
| [PlaceholderAPI](#/plugin/placeholderapi) | 记分板 / Tab 显示城镇信息 |
| EssentialsX / CMI | 部分功能衔接 |
| 头像插件 | 城镇 GUI 里可能要用 |
| 地图插件 | 城镇地图可视化 |

**数据库必须认真选**，见第 5 节。

### 4. 安装

1. 确认服务端是 **Java 17+**
2. 下载 jar 丢进 `plugins/`
3. 重启。Towny 会自动生成配置文件和世界文件
4. **Towny 的配置文件和数据库在升级时不会被破坏**——它是「拖放更新」，换 jar 重启即可

> 0.101.2.0 是 0.101.* 系列的第三个版本，官方说明是「改动不多，但对某些 MC 版本有关键修复」，并且明确说**这是拖放更新：把旧 jar 换成新 jar，Towny 自己会处理迁移，配置文件和数据库都不会坏**。

安装完你会看到：

```
plugins/Towny/
├── config.yml        # 主配置
├── translation.yml   # 翻译
├── towns/            # 城镇数据
└── ...
```

**每次升级前还是备份一遍。**「官方说不会坏」和「你不出事」是两件事。

### 5. 数据库选型（这一步决定后期能不能撑住）

Towny 支持多种存储。**这个决定在开服第一天做，晚了迁移很痛。**

| 存储 | 适用 | 说明 |
|------|------|------|
| flat 文件（默认） | **单机、小服** | 一个世界一个数据文件。**不能跨服** |
| MySQL / MariaDB | **多服、长期服** | 群组服必选 |

**单机生存小服**：默认的 flat 文件够用，省事。

**群组服 / 长期运营服**：**必须 MySQL**。原因很直接——flat 文件是本地文件，A 服建的镇 B 服看不到。多服玩家会遇到的直接后果是「我在主城建的镇，进资源服就没了」。

MySQL 怎么配 → [数据库选型与配置](#/guide/database-setup)。

### 6. 第一次上手

安装完重启，Towny 会创建**自己的世界**（通常叫 `Towny`）。你不需要在主世界里划地，标准玩法是让玩家在 Towny 世界里建镇。

**第一个城镇**：

```
1. 进服，找个地方
2. /town new <城镇名>    ← 建镇，要消耗资源（方块）
3. /town claim           ← 站在地上圈第一块地
```

> 0.101.2.0 新增了「城镇/国家的 rank 可以要求城镇或国家达到最低等级」：给 rank 加上 `towny.town_level_requirement.4` 这样的权限，就要求 town_level 到 4 以上才能分配该 rank。城镇人数掉了会掉级、人数回来了 rank 会自动恢复。**这个机制适合做「贡献不够不能当官」的等级化城镇管理**，改的是 `towns.ranks` / `nations.ranks` 段落。

**一些玩家用得上的命令**（Towny 命令体系很大，这里列最核心的）：

| 命令 | 说明 |
|------|------|
| `/town` | 城镇主菜单 |
| `/town new <名>` | 建镇 |
| `/town claim` | 圈地 |
| `/town unclaim` | 放弃当前地块 |
| `/town claim outpost` | 圈离岸据点（高级玩法） |
| `/t` | 城镇传送 |
| `/t deposit <金额>` | 存钱进镇库（0.101.2.0 起支持 `1k` / `1m` / `1b` 简写） |
| `/t withdraw <金额>` | 从镇库取钱 |
| `/town leave` | 离开城镇（0.101.2.0 起有 `-ignore` 子命令可跳过确认） |
| `/n` | 国家菜单 |
| `/n new <名>` | 建国 |
| `/n ally add <城镇>` | 结盟 |
| `/towny` | 管理命令总入口 |

`/town` 和 `/n` 都是 GUI 菜单，**先点菜单比背命令快**。

### 7. 关键配置思路

不写具体键名，写你要做决定的地方（**键名以你的 `config.yml` 为准**）：

**① 建镇成本与税收**

建镇要消耗方块，税收决定城镇资金积累速度。这两个数要一起看：

- 建镇成本太高 → 玩家建不起，玩法空转
- 税收太高 → 玩家收入被吃光，怨声载道
- 税收太低 → 城镇没钱升级，等级上不去

**升级是 Towny 玩法的驱动器**：城镇等级解锁更多地块数量、更多居民位、更多能力。玩家能看到「离下一级还差 X 人 / Y 钱」，这个进度感就是驱动力。**把这个数字调得舒服一点，玩法就活了。**

**② 法务开关**

每个城镇能自己定法规：禁 PVP、禁破坏、禁 TNT、限外人进入等。**这些是 Towny 的核心吸引力**——玩家在自己家里完全自主，出了镇子就是另一个世界。这个设计比 WorldGuard 的区域 flag 更符合直觉。

**③ 外部世界映射**

主线服通常想控制「Towny 世界里的城镇和主世界哪些区域重叠/冲突」，这里有一段配置。**这是 Towny 配置里最容易配错的一块**，配错的表现是「玩家在主城盖房子，但被 Towny 的城镇判定管到了」。

**④ 版本升级的自动改配置**

0.101.2.0 会自动往 config 里加新版本的方块和药水名（比如把 1.21.4 的木头、花、苔藓块加进农场允许列表，把 1.21 的负面效果加进保护列表）。

**这意味着：不重启就不会生效，而且新旧版本的 config 内容会不一样。** 别手动去删这些自动加的内容——删了下次升级还会加回来，但中间那段窗口期会出保护漏洞。

### 8. 常见坑

**建镇失败，提示资源不够 / 不能建在这**

常见原因：不在 Towny 世界里、位置被别的城镇/国家占着、地块数量超限、世界生成配置有问题。**先确认坐标和世界**。

**建了镇但传送不过去**

Towny 的安全传送需要事先算好目标点的安全位置。**如果传送点附近被别的建筑挡了，会传送失败。** 这个在密集的城镇区是常见问题。

**多服数据不一致**

用 flat 文件导致的。必须 MySQL。**这是 Towny 群组服第一大坑。**

**内存持续上涨，城镇多了之后开始卡**

Towny 的数据结构本身吃内存。三个方向：给 Java 足够的堆内存（先看 [Java 运行时选择](#/guide/java-runtime-choice)）、精简城镇里不必要的地块细分、别让玩家随便乱圈地。

**权限体系太复杂，配到崩溃**

Towny 的权限节点数量在领地类插件里属于最变态的一档。**强烈建议只给普通玩家最小必要权限，把复杂的部分用 rank 打包。** 0.101.2.0 新增的 rank 等级要求机制（见第 7 节）就是为此设计的。

> 配权限前先读 [权限系统设计](#/guide/permissions-design)。Towny 是那种「权限设计没做好就一定配错」的插件。

**升级到 0.101.2.0 后 farm 保护出问题**

它往 config 的 farm 允许列表自动加了一批新方块。如果你的服用了自定义农场机制，检查一下有没有意外的交互。

**玩家退出城镇后 rank 没掉 / 掉了没回来**

0.101.2.0 的新机制：城镇人数掉到等级要求以下时，超出等级的 rank 会被移除；人数恢复后 rank 自动重新分配。**如果你不想用这个行为，不要加那些 `town_level_requirement` 权限节点。**

**和 WorldGuard 冲突**

能共存，但**同一块地上两套保护会互相打**。症状是「WorldGuard 说能建，Towny 说不能建」，或者反之。**划清边界：主城用 WorldGuard，Towny 世界用 Towny。**

**数据库崩了，城镇全没了**

flat 文件被删了 / MySQL 连接断了。**城镇数据就是玩家的全部资产，没备份等于没服。** 定时备份 → [服务端维护](#/guide/server-maintenance)。

### 9. 汉化

> **本站未核实到 TownyDev/Towny 官方中文语言文件机制。**

这一点要说清楚：官方仓库是 `TownyDev/Towny`，社区确实有 Crowdin 翻译平台，Towny 的界面上很多玩家看到的确实是多语言的。**但本站未能核实到其语言文件的具体机制、文件名、路径和简体中文的完整覆盖度**，所以不提供任何逐键对照的汉化文件。

**实际操作建议**：

```
1. 打开 plugins/Towny/ 目录，看有没有 translation.yml 或类似的语言文件
2. 有 → 逐条看哪些是英文，直接改成中文
3. 没有 → 搜 config.yml 里的 messages / locale 段落
4. 都没有 → 打开 jar 看 plugin.yml 的 [messages] / [commands] 段落有没有 messages: 前缀指向的文件
5. 改之前备份整个 plugins/Towny/ 目录
```

> ⚠️ **一切以你手上版本的实际文件为准。** Towny 跨版本改动频繁，配置结构和文件布局在几个大版本间动过。**别照抄别人的汉化文件**——别人的版本和你的不一致，套上去会部分失效甚至报错。

Towny 的界面文本量很大（菜单、提示、错误信息），**逐条汉化是个体力活**。实际做的时候优先改玩家最常看到的：菜单标题、提示语、错误原因。深层菜单的英文可以先放着。

### 10. 我该不该用 Towny

最后给个直接的判断：

**该用**：
- 服要长期运营（半年以上），需要玩家之间有「资产」和「归属感」
- 想做国家、外交、战争这类能产生故事的内容
- 玩家规模够大（有足够的人去建镇、结盟、竞争）

**不该用**：
- 单机生存小服，3-5 个人 — **Towny 的复杂度远超需求，纯属折磨自己**
- 只想给主城加个保护 — [WorldGuard](#/plugin/worldguard) 十分钟搞定
- 短期活动服 — 没有时间培养城镇生态
- 服务器内存紧张 — Towny 吃内存

**如果你的服还在犹豫，先用 WorldGuard 开服，等玩家稳定了再迁移到 Towny。** Towny 的数据是持久化的但生态不好重建，早做早好，但**晚做总比硬做错好**。
