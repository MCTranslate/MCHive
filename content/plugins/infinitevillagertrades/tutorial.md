## ⚠️ 先搞清楚是哪个「Infinite Villager Trades」

**市面上叫「无限村民交易」的插件不止一个，名字非常接近：**

| 名字 | 作者 | 特点 |
|------|------|------|
| **Infinite Villager Trades** | TherougeOM | Modrinth，改动交易上限 |
| **Infinite Villager Trading** | Mqrshe / rebot | Modrinth，下载量更高，去掉补货机制 |
| **Infinite Villager Trades Plugin - Full Description** | TherougeOM | 名称带「Full Description」，是同一个 |

**这页写的是不限次数的核心做法**——不管哪个版本，你要的东西都是「去掉村民交易次数限制」。

⚠️ **本站未核实到你手上那个 jar 的确切版本号和确切功能范围。** 本文讲的是这类插件的通用原理，具体行为以你的插件页面为准。

## 1. 它改的是什么

原版村民交易有两层限制：

```
第一层：单个配方有次数上限
        比如「 librarian 卖附魔书」这个配方只能交易 2 次
        用完了要等村民补货（工作）

第二层：补货需要时间
        村民不能一直无限供应，要"工作"一段时间
```

**这类插件做的就是在玩家打开交易界面时，把配方次数设成无限。**

典型实现只有一个事件钩子：

```
玩家打开村民交易界面（InventoryOpenEvent）
    ↓
拿到这个村民当前的全部交易配方
    ↓
对每一个配方：
    设 maxUses = Integer.MAX_VALUE
    设 uses = 0
    ↓
写回村民
```

**无配置、无命令、无数据库。** 逻辑就这么简单。

## 2. 它的实际用途

| 场景 | 为什么需要 |
|------|-----------|
| **交易大厅 / 玩家市场** | 玩家要反复交易同一个村民，每次都去换村民效率极低 |
| **挖附魔书（刷书）** | 生存服里刷附魔书靠的就是无限交易，否则要养几百个村民 |
| **经济服定价锚点** | 无限交易让「书的价格」有稳定的兑换率 |
| **管理便利** | 不想用 WorldEdit 之类的工具改村民时，直接用这个 |

**最典型的场景是刷书。** 生存服的经济结构经常依赖「村民 → 附魔书 → 附魔台 → 高级附魔装备」这条链。村民交易次数限制会让这条链的效率被卡住。

## 3. 前置条件

| 要求 | 说明 |
|------|------|
| 服务端 | **Paper / Spigot / Purpur** |
| MC | 1.14+（**注意：有些版本要求高得多**） |
| Java | 以你的 MC 版本为准 |
| 硬依赖 | **无**（基于 Bukkit API） |

> ⚠️ **版本要求差异很大。** 同名的几个插件里，有的只支持 1.14-1.18，有的只支持 1.21.11+。**装之前先确认你手上那个 jar 支持你的 MC 版本**——这类插件体量小，通常只针对某几个 API 改动做适配。

## 4. 安装

丢进 `plugins/`，重启。**没有配置文件生成**（这类插件通常无配置）。

就这一步。

## 5. 常见坑

**村民还是只能用几次**

大概率是**版本不匹配**——插件只在 `InventoryOpenEvent` 里处理，如果你打开界面的方式绕过了这个事件（比如某些 GUI 插件重新实现了界面），就不会生效。

**装了不加载 / 报错**

Java 版本或者 MC 版本对不上。看控制台最上面的异常。

**和交易类插件冲突**

| 冲突对象 | 表现 |
|---------|------|
| **经济插件** | 如果经济插件自己接管了交易逻辑，两边都在改配方 |
| **ShopGUIPlus / 商店 GUI 插件** | 箱子式商店界面不是村民界面，不走这个事件 |
| **其他村民修改插件** | 谁后处理谁生效 |

**控制台刷屏**

这类插件通常每次打开界面都做一次修改。如果有什么东西每次打开都触发日志，你会在控制台看到刷屏。

## 6. 缺点和取舍（这条最重要）

| 缺点 | 说明 |
|------|------|
| **直接破坏村民经济平衡** | **这是最大的问题。** 无限交易意味着「书的价格」失去稀缺性，整个经济结构可能崩 |
| **对交易大厅是必需的，对生存服是灾难** | 看你的服靠什么驱动经济 |
| **和村民驯服 / 繁殖机制脱节** | 玩家不需要养一堆村民了，原版这套玩法直接被绕过 |
| **和绿宝石定价脱钩** | 原版里书和绿宝石的汇率是设计好的，无限交易 + 无限产出 = 绿宝石贬值 |
| **无配置 = 无法精细控制** | 只能全开，不能「只对某个村民」 |
| **版本碎片化严重** | 同名插件多，MC 版本要求差异大 |

### 🔥 装之前必须想清楚的一件事

**如果你的服有玩家靠「刷书」赚钱：**

```
装之前：刷一本书要养村民 → 有成本 → 书价有支撑
装之后：无限交易 → 书无限产出 → 书价崩盘
```

**这不是「顺便加个便利功能」，这是改写服务器经济基础。** 一个平衡的经济服装了它，可能几天之内绿宝石通胀、物价全线飘。

**建议：先在小号/测试服装，看你的经济会不会跑偏，再决定要不要上生产服。**

**如果你就是想要刷书玩法**（很多生存服就是靠这个驱动），那这个插件是必需品，不是问题。

## 7. 关于汉化

> ⚠️ **本站未核实到这类插件的官方中文语言文件机制。**

这类插件通常**完全没有玩家可见的文案**——它不发消息、没有 GUI、没有命令。所以：

**找不到语言文件是正常的，不是装错了。**

如果你想给操作加提示，用 PlaceholderAPI 或一个轻量提示插件就够了。
