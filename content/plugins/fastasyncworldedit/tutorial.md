## FastAsyncWorldEdit 安装教程

### 1. 它和 WorldEdit 是什么关系

**FAWE 是 WorldEdit 的 fork（分支），不是「类似插件」。**

这句话很重要，因为它们的关系直接决定了你该怎么装：

| 关系项 | 说明 |
|--------|------|
| **代码来源** | FAWE 从 WorldEdit 分叉出来，重写了核心的方块修改逻辑 |
| **命令兼容** | `//wand`、`//set`、`//fill`、`//copy`、`//paste` 这些**基本照搬**，用惯 WorldEdit 的人不需要重新学 |
| **API 兼容** | 提供 WorldEdit API，**依赖 WorldEdit API 的其他插件装 FAWE 也能跑**（官方 README 原话：装 FAWE 会让它们更快） |
| **性能差距** | 大范围操作下差距是**数量级**的，不是快一点点的区别 |

**为什么快**：WorldEdit 是同步改方块——你执行一次 `//fill 10000`，主线程要一格一格算完才继续。FAWE 把这个过程改成异步分片处理，让服务器主线程在操作期间还能干别的。**这就是为什么你 FAWE 铺 10 万格方块时，服务器还能有玩家在线走动，WorldEdit 早就卡死了。**

> **一句话**：WorldEdit 是老牌标准，FAWE 是它的性能分支兼继任者。

### 2. ⚠️ 不要和 WorldEdit 同时装

**这是本节最要紧的一条。**

两个都塞进 `plugins/`，结果是：

- 命令冲突——`//wand` 归谁？
- 剪贴板格式可能不兼容
- 内存/性能互相拖累
- 大概率其中一个被另一个静默禁用，或者两个都半残

**如果你已经在用 WorldEdit，换 FAWE 的正确姿势：**

1. **删掉**原 WorldEdit 的 jar（**不是禁用，是从 `plugins/` 移走**）
2. 清理残留——检查 `plugins/WorldEdit/` 目录和 `worldedit` 相关数据
3. 装 FAWE
4. 启动，检查控制台里 WorldEdit 是否被正确跳过

**反过来也一样**：装了 FAWE 就别再装 WorldEdit，包括别的插件「顺手帮你带进来的」那份。

> ⚠️ **如果你还有插件依赖 WorldEdit API**：装 FAWE 是可以的，官方明确说 FAWE 提供兼容 API。但**不要因此就两个都装**——依赖 API ≠ 需要原版 jar。

### 3. 什么时候真的需要 FAWE

**WorldEdit 够用的场景**：

- 单人/小团队做小项目
- 改动范围在几千格以内
- 服务器本来就很空（没人在你操作时上线）

**FAWE 明显更好的场景**：

| 场景 | 为什么 |
|------|--------|
| **大范围地形改造** | 世界边缘平整、挖空基岩、刷大山——WorldEdit 会卡死，FAWE 不会 |
| **服务器有真实玩家在线** | 异步改方块，玩家不掉线、服务器不假死 |
| **批量刷建筑** | 复制粘贴大片结构 |
| **配合其他 WorldEdit 系插件** | 依赖 API 的插件会一起变快 |

**如果你的服平时没人在线，只有你自己在造东西**——说实话，WorldEdit 也够用，FAWE 的优势发挥不出来。

**FAWE 能干的大活举例**：

- `//set` / `//fill` 一次改几十万格
- 调整世界边界、削平地形
- 批量替换方块（换建筑材料）
- 导入超大建筑结构

### 4. 安装

1. 从 Modrinth 或 CurseForge 下载（**认准官方仓库**：IntellectualSites）
2. 确认 `plugins/` 里**没有 WorldEdit**
3. 丢入 FAWE jar
4. 启动

生成配置目录 `plugins/FastAsyncWorldEdit/`。

**FAWE 是 Crowdin 众包翻译平台项目**，界面和消息有多语言。

### 5. 上手：管理员要先配一件事

**这一步不做，你会觉得「FAWE 也太慢了」——问题在设置。**

FAWE 默认的**限额**是为了防止管理员误操作把服务器搞挂而设的。**默认限额下，你的大范围操作会被拦住或者被切成很多段慢慢做。**

管理员流程：

1. 用权限插件（LuckPerms 等）给管理员组授予 FAWE 的相关权限
2. 拿到 FAWE 的配置目录，按注释调整限额

> ⚠️ **具体权限节点和配置键名请以你版本的 `config.yml` 注释和权限文件为准。** FAWE 的配置项很多（按玩家、按世界的限额，实体/方块/内存/迭代数限制等等），**本页不列键名**——照抄旧教程的键名很可能配错，而且 FAWE 早期版本和现在的配置结构差别很大。

**要调整的思路（不是键名，是概念）**：

| 概念 | 作用 |
|------|------|
| 单次改动方块数上限 | 决定一次能做多大 |
| 单玩家内存上限 | 防止一个玩家把服务器内存吃光 |
| 并发改动数 | 决定同时允许多少人操作 |
| 粘贴时的限制 | 保护服务器不被巨型剪贴板搞崩 |

**为什么限额该留着**：管理员也会手滑。没有限额的 WorldEdit API 被滥用一次，服务器就得重启。**先把限制调高到你够用，别直接关掉。**

### 6. 常用命令

FAWE 的命令体系和 WorldEdit 一致，命令以 `//` 开头：

| 命令 | 说明 |
|------|------|
| `//wand` | 拿建筑工具（左键选点、右键选第二个点） |
| `//set <方块>` | 把选区填成某方块 |
| `//fill <方块>` | 填充选区 |
| `//copy` / `//cut` | 复制 / 剪切选区到剪贴板 |
| `//paste` | 粘贴剪贴板 |
| `//undo` / `//redo` | 撤销 / 重做 |
| `//pos1` / `//pos2` | 用命令设选区点（不 wand 也行） |
| `//expand` / `//contract` | 按格数扩大/缩小选区 |
| `//replace` | 替换选区内的方块 |

**FAWE 独有的强项**：

| 能力 | 说明 |
|------|------|
| **几乎无限的 `//undo`** | WorldEdit 的撤销历史有上限，FAWE 基本没限制 |
| **按世界独立历史** | 每个世界各自独立的撤销栈 |
| **即时回滚** | 大操作的撤销也快 |
| **跨服剪贴板** | 配合跨服设置可共享剪贴板 |
| **网页版剪贴板** | 官方提供 Clipboard 网页集成 |

> ⚠️ **命令集以你版本的命令列表为准**（`//help` 或 200 多个命令，FAWE 官方说是 200+）。这里只列最核心的。**FAWE 的具体命令参数和 WorldEdit 略有差异**，跨版本迁移的老脚本可能需要微调。

### 7. 常见坑

**装完启动报 WorldEdit 相关的错**

`plugins/` 里还留着 WorldEdit。按上面说的清掉。

**`//wand` 没反应 / 命令找不到**

权限不足。检查 LuckPerms 里有没有 FAWE 的权限，以及这个权限是不是只给了 `default` 组。

**大范围操作还是卡**

没调限额。这是最常见的原因——不是 FAWE 不行，是它在按默认限额一刀一刀切。

**内存爆了**

剪贴板太大。FAWE 的剪贴板会长期占用内存，一次复制几百万格然后放着不动，内存就下不来。**用完就清剪贴板。**

**`//undo` 撤销了但世界还是乱的**

FAWE 的撤销是按「操作」为单位的。如果你做了 10 个操作，撤一次只撤最后一个。**要回到最初就得撤 10 次。** 养成大改前备份世界的好习惯。

**其他插件的 WorldEdit 功能变怪了**

优先怀疑限额冲突。别的插件用 WorldEdit API 时也会受 FAWE 的配置影响，**FAWE 的配置里有一整段就是给第三方 API 用的调整项**。

### 8. Folia

FAWE 支持 Folia（区域化调度）。如果你跑 Folia，FAWE 是少数几个能正常工作的建筑类插件之一。

但**如果你用的是普通 Paper/Spigot，就别专门为了插件去上 Folia**——迁移成本远大于收益，详见版本兼容页。

### 9. 什么时候别用 FAWE

- **只是想在自家世界搭点小建筑** —— WorldEdit 够用，别多装一个
- **服务器内存很小（2 GB 以下）** —— FAWE 自身 + 剪贴板内存要算进预算
- **策划/协作者是普通人，想用 WorldEdit 的教程** —— 基本兼容，但细节差异会卡住他们
- **你还没搞懂 WorldEdit 就想上 FAWE** —— **先学 WorldEdit 的概念**（选区、剪贴板、掩码），FAWE 只是跑得快的同一套东西

### 10. 关于汉化

**FAWE 使用 Crowdin 众包翻译**，界面与消息支持多语言。

**但本站未核实到其官方中文语言文件的具体机制**（未确认是通过 Crowdin 打包进 jar，还是通过 `translations` 目录加载）。若要汉化或修改文案，需自行确认：

1. 进 `plugins/FastAsyncWorldEdit/` 目录，看有没有语言相关文件或目录
2. 在 `config.yml` 里搜 `lang`、`locale`、`message`、`translat` 关键词
3. FAWE 源码在 GitHub（IntellectualSites/FastAsyncWorldEdit），可搜 `translations` 目录

**不要照抄其他版本的路径**——FAWE 的配置和翻译结构在大版本间改过多次。
