## ⚠️ 先说清楚：这是 Nova 的附属插件

**这一节是本页最关键的内容。搞错了装完就是白装。**

`Simple-Upgrades` **不是一个独立的插件**。它是 **Nova 插件的附属（addon）**。

| 情况 | 结果 |
|------|------|
| 装了 Nova + Simple-Upgrades | ✅ 正常工作 |
| **只装 Simple-Upgrades** | ❌ **完全无效** |

**Nova 是干嘛的？** Nova 是一套「职业 / 等级 / 技能」体系插件——玩家选一个职业，挖矿、砍树、战斗分别涨不同的等级，等级带来属性或技能成长。**它提供的是「成长」这个框架。**

**Simple-Upgrades 在这个框架上补一件事：让玩家用等级（或其他条件）直接兑换属性提升。**

```
Nova 负责：         玩家升级（挖矿、战斗…）→ 获得等级
Simple-Upgrades：   拿等级去换属性提升（更大的背包、更远的传送、更快的挖掘…）
```

**所以：Nova 是地基，Simple-Upgrades 是上面的一栋小楼。** 地基没有，小楼无从谈起。

**如果你还没决定要不要用 Nova，那就先别装这个。** 先想清楚要不要引入 Nova 体系（这是个挺重的决定，见第 6 节）。

### 1. 版本要求

**支持 MC 1.19.4 - 26.3。**

- **1.19.4 是下限**
- 需要 Spigot / Paper 系服务端

**Nova 和 Simple-Upgrades 的 MC 版本要能对上。** 装之前确认一下 Nova 的支持区间包不包含你的 MC 版本 —— **附属装上了但 Nova 版本不兼容，一样不工作。**

## Simple-Upgrades 安装教程

### 2. 安装顺序（不能反）

```
1. 先装 Nova，重启，确认 Nova 正常工作
2. 再装 Simple-Upgrades，重启
3. 确认插件已加载（控制台日志）
4. 到 Simple-Upgrades 的配置里定义升级项
5. 玩家就能在 Nova 的 GUI 里看到并购买升级
```

**⚠️ 第 1 步不能跳。** 装了 Simple-Upgrades 但 Nova 缺失或损坏的话，Simple-Upgrades **不会正常工作**（具体表现是加载失败、或者功能静默不可用——**以控制台日志为准**）。

**Nova 自己也是个不算轻量的插件**（它有 GUI、职业、技能、等级存储）。引入它意味着你的服要按「有 RPG 系统」来配置。

### 3. 它提供什么

这类 Nova 附属的典型内容是**一类可购买的能力**。具体有哪些升级项，**以你版本的配置和官方文档为准**——本页不列具体升级项名，因为那属于配置内容而非插件能力。

**可以按类型理解：**

| 类型 | 例子（示意，非具体配置） |
|------|---------------------|
| 背包类 | 额外的背包行数 |
| 传送类 | 更远的传送距离、更便宜的传送 |
| 挖掘类 | 更大的挖掘范围、方块自动收集 |
| 交互类 | 更多家/更多传送点/更大的堆叠 |
| 便利类 | 额外的飞行时间、更好的坐骑 |

**这些只是「这类插件通常提供什么」的示意。** 实际有哪些项、每项消耗多少、效果多强，**全在配置里，以你手上的配置文件为准**。

### 4. 配置要点

配置在 `plugins/Simple-Upgrades/` 下。**具体键名以你手上版本的配置文件注释为准。**

逻辑上会涉及：

| 类别 | 管什么 |
|------|-------|
| 升级项定义 | 有哪些升级、各几级 |
| 消耗 | 每级要多少等级 / 多少钱 |
| 效果 | 每级给什么能力 |
| 权限 | 谁能用（全部玩家？特定职业？） |
| 提示文本 | 购买成功/失败的提示 |

**最需要自己决定的是「消耗」**：

- 用 **Nova 等级** 消耗 → 和 Nova 体系深度绑定，玩家升级变慢但有意义
- 用 **货币** 消耗 → 需要经济插件，引入额外依赖
- 用 **两者** → 灵活但复杂

**选哪种影响很大。** 等级消耗意味着「升级本身成了瓶颈」；货币消耗意味着你需要一个健全的经济系统，否则「有钱」的玩家会碾压其他人。

### 5. 常见坑

**装完没反应 / 看不到升级选项**
**九成是没有 Nova，或者 Nova 版本不兼容。** 回控制台看日志，确认 Nova 正常加载。

**Nova 装了但升级项看不到**
- Simple-Upgrades 的配置里没定义任何升级项（**首次启动可能只有模板或空配置**）
- 玩家没权限
- GUI 缓存 → **重进游戏**（Nova 的 GUI 状态会缓存）

**和 Nova 版本不匹配**
- Nova 更新了，附属没跟上 → **升级 Nova 前先看附属的兼容说明**
- 附属要求某个 Nova 版本范围 → 看实际报错

**升级项效果没生效**
- 可能被**其他插件的同类能力覆盖**（比如你已经有别的插件加了额外背包行数）
- 可能 Nova 的相关功能没开

**经济崩了**
如果消耗用的是货币，**要小心通胀**。玩家大量购买升级 → 货币回收 → 物价变化。**这个影响是长期的，不是装完就结束的。**

**和 EssentialsXChat 的 GUI / 消息冲突**
Nova 有自己的 GUI 系统。**如果别的插件也改 GUI 相关行为，可能出现点不动、显示异常。**

**升级了但玩家反感**
**平衡问题。** 升级系统一旦给得太强，「努力变强」的成就感就没了；给得太弱，玩家觉得花钱没意义。**这个数值没有通用答案，只能看你的服实际反馈。**

**Base 版本升级后数据丢失**
Nova 的数据（等级、职业）存在数据库里。**换数据库类型/删库 = 玩家等级全没。** 改 Nova 相关配置前先备份数据库。

### 6. ⚠️ 决策：要不要引入 Nova 体系

**Simple-Upgrades 本身很简单，难的是「要不要 Nova」这个决定。**

| 引入 Nova 意味着 | |
|----------------|---|
| 多了职业 / 等级 / 技能 | 玩法的核心循环变了 |
| 多了 GUI | 玩家要适应新界面 |
| 多了数据库存储 | 备份要注意 |
| 多了平衡问题 | 每个职业/升级项都要调 |
| **多了一个重插件** | 性能、多标签、和其他插件的兼容 |

**适合引入 Nova 的服：**

- RPG / 生存混合，想给长期目标
- 想让「挖矿」不只是挖矿，有成长感
- 已经有其他 RPG 类插件，想要一套统一的

**不适合的：**

- **纯 PvP 竞技** —— 等级成长会破坏公平
- **纯建筑 / 创造** —— 没有成长需求
- **休闲小服（几个朋友）** —— 没人会为了升级去挖矿
- **想保持原版生存的纯粹** —— Nova 就是在改这件事

**先试 Nova 本身，再决定要不要 Simple-Upgrades。** Nova 有没有用，和附属有没有用，是两个问题。

### 7. 关于汉化

**本站未核实到 Simple-Upgrades 的官方中文语言文件机制。** 若要汉化需自行确认。

**注意：这个插件的文本有两层来源，容易搞混。**

| 文本来源 | 改哪里 |
|---------|-------|
| **Simple-Upgrades 自己的**（升级项名字、描述、购买提示） | 它的配置 / 语言文件 |
| **Nova 的**（GUI 框架、货币名称、等级相关文案） | **Nova 的**配置 / 语言文件 |

**很多「汉化不了」的情况其实是找错了文件** —— 文本在 Nova 那边。

引导式排查方法：

1. 进 `plugins/Simple-Upgrades/`，看有没有语言文件目录
2. 搜配置文件里有没有 `message`、`language`、`locale` 段落
3. **升级项的名称和描述是配置内容，不是语言文件** —— 大概率在你的配置文件里直接改
4. **Nova 那边也要单独看** —— 尤其如果你发现只有部分文本是英文

**务实的判断：** 升级项的名字和描述**在你的配置文件里改中文是可行的**（如果它们是配置项的话）。**先找到文本实际在哪，比找汉化机制更直接。**

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 8. 什么时候别用它

- **没装 Nova / 不打算装 Nova** —— 见开头
- **纯 PvP / 竞技服** —— 成长系统破坏公平
- **纯建筑 / 创造服** —— 没有成长需求
- **休闲小服** —— 没人玩升级
- **已经有其他成长/技能系统** —— 成长线重复，玩家不知道该升哪个
- **服主不想维护平衡** —— 升级系统的数值调优是长期工作
