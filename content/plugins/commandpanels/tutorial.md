## 它是什么

CommandPanels 让服主用一份 YAML 配置生成 **GUI 菜单**——玩家右键某个方块，或者敲一条命令，弹出一个带自定义图标的界面，点哪个格子就执行对应动作。

本质是**把「一堆命令 + 一堆权限判断」包成一层界面**。

典型场景：

| 场景 | 怎么做 |
|------|-------|
| 服务器传送选择器 | 一个面板，每格一个目的地，权限控制可见性 |
| 帮助 / 规则菜单 | 图标 + 文本，纯粹展示 |
| 商店入口 | 分类按钮，点进去开商店 GUI |
| 团队选择 | 无权限的玩家看不到对应格 |
| 领取奖励 / 打开邮箱 | 图标指向指令 |

**它的强项是「可见性由权限控制」。** 同一份面板，OP 看到 20 格，普通玩家看到 5 格——这比给每人发一堆命令强得多。

## 版本跨度大，但要注意

**支持 1.8 - 26.3**，跨度极大，说明它一直在跟着核心更新维护。1.8 这个下限是好事——老服也能用。

但反过来说：**跨度大不等于你的版本一定没问题。** 老版核心 + 新版插件的组合是崩服重灾区。装之前看一眼你手上那个版本是不是在支持范围里，别默认「跨度这么大全兼容」。

## 安装

1. jar 丢进 `plugins/`
2. 启动，生成配置和面板目录
3. 重启或重载

面板文件通常放在插件数据目录下的一个独立文件夹里，**具体目录名和文件组织方式以你版本的官方文档为准**（这类插件的面板文件结构版本间变过，本站不写死路径）。

> ⚠️ 本站**未核实到该插件的官方发布仓库地址**。CommandPanels 在 SpigotMC / Modrinth / Hangar 上都有同名或近似名的项目，**认准作者**。搜的时候留意 jar 内 `plugin.yml` 的作者字段。

## 面板是怎么组织的

CommandPanels 的模型大致是这样（**字段名以官方文档和配置文件注释为准**）：

| 概念 | 作用 |
|------|------|
| 面板（panel） | 一个界面，含若干格子 |
| 格子（item） | 图标物品 + 显示名 + 动作 |
| 动作（action） | 点击后执行的指令 |
| 权限（permission） | 能不能看到这个面板 / 这个格子 |
| 尺寸 | 面板的行数 |

**核心逻辑很简单：玩家点格子 → 检查权限 → 执行指令。** 权限决定格子可不可见，动作决定点了发生什么。

**一个面板里放几十个格子是可以的，但超过四五十个就该拆。** 玩家在 GUI 里翻找的时间是真实成本——格子越少，转化率越高。

## 配菜单的实用建议

**一、图标要能自解释。**
玩家看不懂的图标就是无效图标。名称写清楚（「主城传送」「商店」），别用「图标1」「图标2」。

**二、能用指令实现的别过度设计。**
CommandPanels 的价值在可见性控制和易用性，不在炫技。一个面板三层嵌套才能到的东西，玩家会直接放弃。

**三、给「无权限玩家」一个交代。**
玩家点不进去、被隐藏了格子，完全不知道原因。**加一个「你没有权限」的说明项，或者在别的地方说明**——这个体验细节比面板本身更影响口碑。

**四、图标物品会和其他插件撞。**
面板要显示自定义物品（比如货币、钥匙），这些物品的定义可能来自别的插件。**两套插件都想定义同一个物品 ID，结果就是物品变形。** 先理清谁负责定义物品。

**五、别在一个面板里塞传送 + 商店 + 任务。**
按用途拆开，权限边界才清晰。

## 常见坑

**面板不弹出来**
权限没给够，或者绑定的方块/命令被别的插件抢了。检查玩家是否拥有对应权限节点——**具体节点名以官方文档为准**。

**点格子没反应**
多数情况是那条指令本身执行失败了（权限不足、指令写错）。**去控制台看有没有报错**，GUI 界面不显示执行结果，这是最常见的误判来源。

**图标显示成紫黑方块**
自定义材质没装或者材质包没生效。**用原版物品做图标可以绕开这个问题**，新手期建议就这么做。

**和箱子菜单类插件冲突**
同类 GUI 插件**只能装一个**。两个都装会互相抢事件，表现为点不开、或者界面闪一下就关。同时装 ChestCommands、DeluxeMenus 之类的一律先删掉。

**面板太多加载慢**
每个面板都要读文件。**几十个小面板没问题，几百个就会拖慢启动和开面板的速度。** 合并同类项。

## 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

**但这个插件的汉化其实是半确定的**：菜单上显示的文字绝大多数是你自己写在面板 YAML 里的**显示名和描述**——那本来就是中文，你直接写中文就行。**这一步不需要任何语言文件机制。**

真正需要确认的是另一部分：**系统提示类文案**（比如「你没有权限」这类内置消息）是否走语言文件。排查方法：

1. 启动一次服务器，看插件数据目录里生成了什么文件
2. 在生成的文件里搜 `lang`、`locale`、`message`、`translat`
3. 看有没有 `_zh_CN` 之类的中文变体结构

找不到语言文件，说明内置提示要么写死在代码里（只能改 jar，不建议），要么就是由面板配置自己控制。**具体以你的配置文件注释为准。**

系统性的汉化思路见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
