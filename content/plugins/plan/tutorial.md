## Plan 安装教程

### 1. 它是什么

Plan（Player Analytics）给你一个**网页后台**，回答那些日志文件回答不了的问题：

- 今天有多少人上线？高峰是几点？
- 哪个玩家最近一周没来了？
- 平均游玩时长是多少？留存曲线是什么形状？
- 服务器 TPS 和内存什么时候开始掉的？
- 一周里哪天最冷清？

**为什么不用 bStats / spark？** 它们给的是全服聚合的技术指标。Plan 给的是**按玩家的行为数据**——谁来了、来了多久、上次什么时候来的。这两件事不能互相替代。

### 2. 先想清楚一件事：要不要开

Plan 会记录**每一个玩家的登录时间和游戏时长**，存进数据库。

这在服主眼里是正常运维数据，但它确实构成个人数据。开源公益服、社区服尤其要想清楚：

- 玩家知不知道你在记录？
- 保留多久？
- 要不要支持删除？
- 数据库泄露了怎么办？

**这不是说不能用。** 但别稀里糊涂就开了，尤其别开在有明确隐私要求的场景里。关掉某些模块的选项是有的，具体以你版本的配置注释为准。

### 3. 前置条件

| 要求 | 说明 |
|------|------|
| Java | 11+ |
| 服务端 | Paper / Spigot / Purpur / Folia；代理端支持 BungeeCord / Velocity / Waterfall；也有 Sponge 版 |
| 数据库 | SQLite（默认，开箱即用）或 MySQL |
| 额外端口 | **需要开一个 Web 面板端口**（默认 8804） |

> ⚠️ **端口是 Plan 最容易被忽略的地方。** Web 面板默认监听 `8804`。玩家在浏览器访问 `http://你的IP:8804`。**云服务器必须放行这个端口**，不然装完以为坏了，其实是防火墙拦了。

### 4. 安装

- 仓库：<https://github.com/Player-analytics/Plan>
- 文档：<https://github.com/Player-analytics/Plan/wiki>

**单服**：

1. jar 丢进 `plugins/`
2. 重启，生成 `plugins/Plan/config.yml`
3. 浏览器访问 `http://服务器IP:8804`

**群组服（代理 + 多后端）**：

1. **代理端和每个后端都装 Plan**
2. **所有节点共用同一个 MySQL 数据库**
3. 代理端保留 Web 面板，后端可以关掉各自的 Web 服务（都指向同一个库）
4. 各后端的 `Server.IP` 要填**本机可达的地址**

> 群组服用 SQLite 是错的。**SQLite 不能跨机器共享**，你会发现代理端看不到后端的数据。

### 5. 常用命令

| 命令 | 说明 | 权限 |
|------|------|------|
| `/plan` | 主命令，**只显示你有权用的子命令** | 无 |
| `/planproxy` | 代理端主命令（别名 `planbungee` / `planvelocity`） | 无 |
| `/plan info` | 插件状态 | `plan.info` |
| `/plan reload` | **重启插件并重载配置** | `plan.reload` |
| `/plan player [名字/UUID]` | 打开该玩家页面 | `plan.player.self` / `.other` |
| `/plan players` | 玩家列表页 | `plan.player.other` |
| `/plan server [名字]` | 服务器详情页 | `plan.server` |
| `/plan servers` | 列出数据库里所有服务器及 ID | `plan.servers` |
| `/plan network` | 群组网络页 | `plan.network` |
| `/plan search` | 搜索玩家名 | `plan.search` |
| `/plan json [名字/UUID]` | 玩家 JSON 数据下载 | `plan.json.self` / `.other` |
| `/plan register` | 注册网页面板账号 | `plan.register.self` |
| `/plan unregister [用户名]` | 注销面板账号 | `plan.unregister.self` |
| `/plan users` | 已注册用户列表 | `plan.users` |
| `/plan logout [用户名/*]` | 强制某用户或所有人登出 | `plan.logout.other` |
| `/plan setgroup <用户> <组>` | 设置用户组 | `plan.setgroup.other` |
| `/plan groups` | 列出面板用户组 | `plan.setgroup.other` |
| `/plan disable [功能]` | 临时禁用插件或某功能 | `plan.disable` |
| `/plan accept` / `cancel` | 确认/取消待执行操作 | 无 |
| `/plan export <类型>` / `import <类型>` | 导出/导入数据 | `plan.export` / `plan.import` |
| `/plan db` | 数据库操作 | `plan.data.base` |

**`/plan` 的权限设计值得夸一句**：它会**只列出你有权限的子命令**。给普通玩家 `/plan` 不会泄露管理功能的存在——这在权限设计上比「全部列出然后报权限错」好得多。

> ⚠️ 命令和权限节点在 5.x 里基本稳定，但以你版本的 `/plan` 输出和 Wiki 为准。

### 6. 网页面板

装好后浏览器访问：

```
http://服务器IP:8804
```

**能看到的**：

| 页面 | 内容 |
|------|------|
| 服务器总览 | TPS、内存、CPU、各世界玩家数 |
| 玩家列表 | 按在线/总时长排序 |
| 玩家详情 | 每次会话的时间、时长、IP |
| 留存分析 | 新老玩家留存曲线 |
| 排行 | 游玩时长榜 |
| 世界分布 | 各世界在线人数（热力图） |
| 玩家趋势 | 某段时间的活跃度曲线 |

**要注册账号才能看详细数据**，别把 Web 面板直接暴露在公网。

### 7. 安全：这是 Plan 最该认真对待的部分

Plan 的 Web 面板**自带登录认证**，但默认配置往往偏松。至少做这些：

| 措施 | 怎么做 |
|------|--------|
| **限制访问来源** | 防火墙只放行你自己的 IP，别对全网开 |
| **一定要上 HTTPS** | 认证信息在明文 HTTP 下就是明文传 |
| **改掉默认端口** | 8804 是公开默认值，扫端口的能找到 |
| **数据库账号最小权限** | MySQL 账号别用 root |
| **定期清数据** | 玩家数据会持续增长，繁忙服一年能到 GB 级 |

> **最要紧的一条：不要把 Web 面板端口对全网开放。** 就算有认证，它也是攻击面。正确做法是**只允许管理组 IP 访问**，通过 VPN 或跳板机连。

### 8. 数据库选择

| 场景 | 推荐 | 原因 |
|------|------|------|
| 单服、几十人 | SQLite | 开箱即用，零配置 |
| 单服、几百人+ | **换 MySQL** | SQLite 写入锁会引发延迟毛刺 |
| 群组服 | **必须 MySQL** | 跨机器共享 |

**从 SQLite 换 MySQL 的正确流程**（别直接改 `type`）：

1. 配好 MySQL 数据库
2. 改 `config.yml` 里的数据库配置
3. 启动后用 `/plan` 相关命令或官方文档提供的迁移方式转移数据

> ⚠️ 5.7 → 5.8 升级通常不需要手动操作，5.8 移除了 `plan_settings` 表和 `Networks` 的 `serverConfiguration` 目录。**升级前备份数据库**，旧版在定时任务里报相关错误通常可以忽略。

### 9. 常见坑

**浏览器打不开面板**

按顺序查：

1. 云服务器**安全组/防火墙有没有放行 8804**
2. 容器/面板环境（1Panel、Moonzoon、Pterodactyl）**有没有额外端口限制**
3. 客户端防火墙
4. 浏览器访问 `http://IP:8804`（**注意是 http 不是 https**）

**群组服看不到后端数据**

- 数据库是不是共用同一个 MySQL？
- 各后端的数据库配置是否**完全一致**？
- `Server.IP` 填的是不是**本机能访问到的地址**（`localhost` 在群组服是错的）

**TPS 图断断续续 / 曲线没数据**

数据是定时采样的，间隔由配置控制。刚重启没数据是正常的，等一个采样周期。

**内存占用变高了**

Plan 要存玩家数据。数据量随时间线性增长，繁忙服一年 GB 级。**在配置里设置数据保留期并定期清理**，别让它无限涨。

**升级后报数据库相关错误**

备份后按 Wiki 的升级说明走。5.8 移除了几个表和目录，旧版残留的报错通常无害。

**`/plan reload` 之后玩家数据不见了**

`reload` 会重载配置。确认数据库配置没被改错。

### 10. 什么时候别用 Plan

- **1-5 人的小服** —— 你自己就知道谁在线，不需要面板
- **「不想存玩家数据」** —— 那就别装，这不是技术问题
- **不会配安全** —— Web 面板暴露在公网是真实风险，不是理论风险
- **只是想看 TPS** —— 用 spark 就够，Plan 是重得多的方案
