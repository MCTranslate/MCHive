## UserPrefix 安装教程

### 1. 它是什么

UserPrefix 做一件事：**让玩家名字前面挂一段前缀，并且这段前缀跟着权限实时变**。

它轻。3.4.x 版本的定位就是「轻便、高效、实时」，没有商店、没有经济、没有 BUFF 引擎。就是前缀本身加上一个选择界面。

| 能力 | 说明 |
|------|------|
| 权限驱动 | 有权限节点就有对应前缀，权限一改立刻生效 |
| 实时监测 | 玩家权限被撤销时自动换回默认前缀并提示 |
| 游戏内重载 | 改完配置不用重启，玩家在线就能生效 |
| Tab 自动排序 | 按前缀权重排序，权重冲突时可以关掉 |
| 玩家头顶前缀 | 独立开关（和 Tab 显示是两条链路） |
| 选择 GUI | 自动排序 + 可翻页 |
| HEX 颜色 | 16 位颜色码 |
| 前缀图标 | 同一个前缀可配「选中 / 有权限 / 无权限」三种状态的物品 |
| PAPI 变量 | 兼容 BungeeTabListPlus 之类的插件 |

### 2. 什么时候该用它，什么时候不该

| 用它 | 不用它 |
|------|--------|
| 只想给 VIP /  staff / 老玩家加前缀 | 想要「玩家自己花钱买称号」→ 需要商店+经济 |
| 追求轻量，不想要庞大称号系统 | 想要称号带 BUFF、粒子、限时 |
| 前缀跟权限强绑定（等级/身份自动变） | 想做多称号并行、聊天和 Tab 显示不同称号 |

如果你要的是**完整的称号经济系统**，看 [PlayerTitle](#/plugin/playertitle)。要的是**多称号并行的标签框架**，看 [MythicPrefixes](#/plugin/mythicprefixes)。UserPrefix 是这条链上最轻的一环。

### 3. 前置依赖

| 依赖 | 必要性 | 说明 |
|------|--------|------|
| Spigot / Paper / Folia / Purpur API | 必须 | 平台本身 |
| [LuckPerms](#/plugin/luckperms) 或等价权限插件 | **必须** | 前缀数据挂在权限上 |
| [PlaceholderAPI](#/plugin/placeholderapi) | 强烈建议 | 不装就用不了变量功能 |

LuckPerms 是硬性依赖——**UserPrefix 不自带玩家前缀数据存储**，它靠权限表达「这个玩家该戴哪个前缀」。这点和 [MythicPrefixes](#/plugin/mythicprefixes) 是同一个设计哲学。

### 4. 配置文件结构

装完之后 `plugins/UserPrefix/` 下有三类文件，**分得很清楚，这个设计比同价位插件整洁**：

```
plugins/UserPrefix/
├── config.yml      # 插件总配置：GUI、显示行为、消息
├── messages.yml    # 消息文本
└── prefixes/       # 前缀定义，每个前缀一个独立 yml
    ├── vip.yml
    ├── mvp.yml
    └── staff.yml
```

三个值得注意的点：

**① 前缀拆成独立文件。** 一个前缀一个文件，放在 `prefixes/` 目录下。好处很实在：加称号时**只需要新建一个文件**，不会在一个巨大的 YAML 里翻找，也不存在多人编辑同一个文件冲突的问题。删称号就是删文件。

> ⚠️ 文件名里避免用特殊符号，作者明确提过部分符号会导致读取失败。

**② 消息单独放 `messages.yml`。** 需要汉化的话这是你最该看的文件。

**③ 总配置和前缀分离。** 调 GUI 行为去 `config.yml`，加前缀去 `prefixes/`。

### 5. 权限与命令

| 命令 | 用途 |
|------|------|
| `/prefix` | 打开前缀选择 GUI |
| `/UserPrefix` | 同上（完整名写法） |
| `/UserPrefixAdmin` | 查看管理命令帮助 |
| `/UserPrefixAdmin reload` | 重载配置 |
| `/UserPrefixAdmin list` | 列出所有已配置的前缀 |

> 建议统一用 `/UserPrefixAdmin reload` 而不是别的方式重载——**它设计上就是游戏内重载，玩家不掉线**。这一点是 UserPrefix 相对同类的优势。

玩家侧命令权限给普通玩家就行，管理命令留给 OP。

### 6. PAPI 变量

装了 PlaceholderAPI 之后可以查全部变量：

```
/papi info UserPrefix
```

主要变量：

| 变量 | 用途 |
|------|------|
| `%UserPrefix_prefix%` | 当前前缀内容 |
| `%UserPrefix_weight%` | 当前前缀权重（给 Tab 排序用） |
| `%UserPrefix_identifier%` | 当前前缀的标识 |
| `%UserPrefix_name%` | 当前前缀名称 |
| `%UserPrefix_has_<某前缀>%` | 判断玩家是否有指定前缀，返回 true/false |

`%UserPrefix_has_%` 这个判断变量很实用：可以在别的地方（任务条件、菜单权限、聊天格式）直接问「这个玩家有没有 X 前缀」，不用自己再写权限判断。

### 7. 关键决策：Tab 排序和头顶显示

这两个开关有坑，得单独说。

**Tab 自动排序**

按权重排序前缀。3.4.0 引入了 group view（分组视图），3.4.1 又加了「控制分组视图下默认前缀可见性」的选项。

问题在于：**排序靠 Tab 显示名字实现，名字长度的限制会连带影响排序效果**。前缀堆太多会出现「名字太长被截断，看起来所有人都一样」的情况。

建议：Tab 上最多留 1-2 个前缀，权重分层，别超过 3-4 个可选项。

**玩家头顶显示**

独立开关，可以关。这条链路和 Tab 不是一回事——**开了头顶显示只在自己视角/近距离生效**，而且它是通过数据包实现的，**和别的改名牌的插件会冲突**。

同一时刻只能有一个插件控制玩家头顶名字。要做头顶显示，先确认 EssentialsX 的 nick 之类的功能没在管这件事。

**同屏 3.x 兼容性提醒**：1.20.5 起服务端给玩家名的长度上限被收紧（16 字符），前缀 + 名字超长会导致某些客户端看不到完整名字。**前缀别做长**。这是新版最常见的「头衔看不见」原因。

### 8. 汉化

> **本站未核实到该插件的官方中文语言文件机制，若要汉化需自行确认。**

不过它的文件结构已经把汉化的活分得很干净，实际操作很直接：

| 改什么 | 在哪改 |
|--------|--------|
| 前缀文本本身 | `prefixes/*.yml` 里每个前缀自己的文本项，直接写中文 |
| 插件提示消息 | `messages.yml` |
| 拒绝消息 / 权限不足提示 | `messages.yml` |
| GUI 按钮与菜单标题 | `config.yml` 里的 GUI 相关段落 |
| 换前缀时的音效、提示 | `messages.yml` / `config.yml` |

> ⚠️ **以实际文件为准。** 打开 `messages.yml` 逐条改，别照抄网上的汉化文件——**不同版本的消息键名会变**，别人的文件很可能是旧版本的，套上去会部分失效。

前缀文本用 HEX 颜色时，中文建议只给**首尾两个字**上色，中间留白。整句渐变在中文上永远是糊的。

### 9. 常见坑

**权限给了但前缀不显示**

按顺序排查：

1. 玩家真的有那个权限节点吗（用 `/lp user <名> verbose on` 查）
2. 改完配置重载了吗（`/UserPrefixAdmin reload`）
3. 服上是不是**另一个插件也在改 Tab 名字**（Essentials nick、其他前缀插件、某些 TAB 插件）——两个插件改同一个东西，后加载的赢

**Tab 里所有人前缀一样 / 看不到前缀**

先怀疑名字长度超上限（1.20.5+ 收紧到 16 字符）。然后检查 Tab 排序是不是被别的插件接管了。

**GUI 打开是空的**

`prefixes/` 目录里文件读不到。检查文件名有没有特殊符号，检查 YAML 缩进是不是用了 Tab。

**权限一撤销，前缀还挂着**

正常情况下会自动切回默认前缀并提示。如果没切换，reload 一次让缓存刷新。3.4.1 主要就是在改这块的可见性逻辑。

**和 [MythicPrefixes](#/plugin/mythicprefixes) / [PlayerTitle](#/plugin/playertitle) 冲突**

三个都改昵称显示，**只能选一个**。真要叠加（聊天用 A、Tab 用 B）需要让它们输出到不同渠道并关掉其中一方的直接显示，这在实践中非常难调稳，不建议。
