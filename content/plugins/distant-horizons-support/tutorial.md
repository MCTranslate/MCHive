## ⚠️ 先看这里：这是「玩家端要装模组」的插件

**这不是一个装了就能白嫖功能的插件。分清两侧：**

| 侧 | 要装什么 | 谁装 |
|----|---------|------|
| **服务端** | 本插件 + Distant Horizons 服务端组件 | 你（服主） |
| **玩家客户端** | **Distant Horizons 模组（Fabric / Forge / NeoForge）** | **每个想看远景的玩家** |
| **不装模组的玩家** | —— | 正常游戏，**看不到远景，但不受影响** |

**这个区别必须先想清楚。** 如果你的服 200 人只有 5 个人愿意装 Fabric 模组，那你装这个插件的收益覆盖不到 200 人，却要付服务端的成本。

> **⚠️ 本站未核实到该插件的官方源码仓库。** 下载来源请自行确认（Modrinth / 插件站搜索插件名，认准作者）。本文档不提供可验证的仓库链接。

### 1. 原版视距为什么不够

原版 Minecraft 的视距上限是硬的：

| 项 | 原版 | DH 的做法 |
|---|------|----------|
| 渲染距离 | 软上限约 32 区块（有上限） | 可以拉到很远 |
| 远景细节 | **没有**——超出视距直接不渲染 | **LOD 层级细节**，远处是低精度模型 |
| 世界生成 | 服务端只生成玩家周边 | 按需生成/加载更大范围 |

**DH 的核心是 LOD（Level of Detail）：** 近处高精度，远处低精度。所以它能做到「看到很远」而不需要服务器一次性渲染那么多方块。

**Distant Horizons 是一个有专利/授权背景的模组项目**，装之前自己确认一下它的分发条款和你服的情况是否匹配。

### 2. 它是怎么联动的

```
服务端：维护「视野数据」（哪些区块、玩家视距、要发什么 LOD 信息）
    ↓ 通过网络协议发
玩家：装了 DH 模组 → 收到视野数据 → 在自己机器上渲染远景
```

**关键点：远处的画面是玩家客户端渲染的。** 所以：

| 影响 | 说明 |
|------|------|
| 服务端负担 | **不是零**。要存/发视野数据、可能要预生成区块 |
| 玩家负担 | **实打实的 GPU 和显存消耗** |
| 掉帧风险 | **在中低端机器上很明显** |

**很多玩家装完 DH 发现变卡了，会来怪服务器。** 提前知道这个点，能省掉一堆解释工单。

### 3. ⚠️ 成本在服务端这边

很多人以为「反正渲染在客户端，服务端没负担」——**不完全对**：

| 成本项 | 说明 |
|--------|------|
| **内存** | 服务端要维护视野数据，这是实打实的内存占用 |
| **区块预生成** | 玩家看得远 → 更多区块被加载/生成 → **CPU 和 IO 压力上升** |
| **带宽** | 视野数据的网络传输 |

**在你服本来就吃紧的机器上装这个，是有风险的。** 先看 [服务器性能调优](#/guide/performance-tuning) 里的内容，确认你有余量。

### 4. 安装

**服务端侧：**

1. 确认服务端版本在支持范围内（**MC 1.16 - 26.2**）
2. 按插件页面说明装好本插件
3. **按插件要求处理 DH 的服务端组件** —— 模组通常需要对应的服务端端安装，**具体方式以插件实际说明为准，本站未核实**
4. 启动，看控制台有无异常
5. 测：你自己装上 DH 模组连进来，看能不能看到远景

**客户端侧（每个想用的玩家）：**

1. 按自己的加载器（Fabric / Forge / NeoForge）装 Distant Horizons 模组
2. 版本必须和服务端对得上
3. 进服，看效果

> ⚠️ **版本匹配是这里最大的坑。** 模组端、服务端端、插件端三方的版本要对齐，对不上就是连不上或者看不到东西。装之前先看插件页面的版本支持说明。

### 5. 常见问题

**玩家说看不到远景**

按这个顺序查：

| 检查 | 说明 |
|------|------|
| 模组装了吗 | 最常见原因，**没装就是看不到，这不是 bug** |
| 版本对得上吗 | 模组版本和服务端差太多 |
| 有没有 optifine / 冲突模组 | DH 和某些优化模组有兼容问题 |
| 服务端插件加载了吗 | 看控制台 |

**玩家说装了 DH 之后卡**

| 现象 | 原因 |
|------|------|
| FPS 掉得厉害 | **LOD 渲染吃 GPU**，客户端配置不够 |
| 内存暴涨 | 视野数据缓存，加上其他模组 |
| 区块加载卡顿 | 远视距导致大量区块加载 |

**解法在客户端**：调 DH 的设置（降低渲染距离、提高 LOD 细节层级精度换性能）。**不是让服务器加内存能解决的。**

**服务端变卡了**

先看是不是**大量玩家开 DH 把区块预生成跑满了**。这种情况需要限制，或者在低配时段观察区块加载曲线。

**和 BlueMap / squareMap 冲突吗**

一般不直接冲突（三者用途不同：DH 是视觉远景，BlueMap/squareMap 是俯视地图），但**都吃性能**。同时开三个地图类插件的服要注意预算。

### 6. 谁该装，谁不该装

| 服类型 | 建议 |
|--------|------|
| 建筑/景观向、有展示需求 | ✅ 值得，玩家会主动要求装 |
| 服务器机器配置不错 | ✅ 撑得住 |
| 玩家愿意自己装模组（技术向社区） | ✅ 覆盖率会高 |
| 玩家技术参差不齐（大量手机/低配玩家） | ⚠️ 覆盖率会很低，因为装不动 |
| 低配机器开的服 | ❌ 服务端和玩家双端都吃力 |
| 基岩玩家为主的服 | ❌ **基岩版没有 Fabric/Forge 模组体系，装不了** |

**最后一条很重要。** 如果你的服靠 Geyser 引入大量基岩玩家，这个插件对他们**完全无效**（见 [Geyser 与基岩版](#/guide/geyser-bedrock)）。这时候为它付出的服务端成本是纯亏。

### 7. 关于汉化

**本站未核实到 DistantHorizonsSupport 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/` 下的对应目录，**搜文件名**找 `lang`、`locale`、`messages`、`zh`
2. 打开配置，**搜关键词** `message`、`locale`、`lang`
3. **注意区分文本的来源**——这个插件尤其容易误判：

| 文本 | 真正归谁管 |
|------|-----------|
| DH 模组自己的界面文字 | **Distant Horizons 模组自己的资源包**，不是这个插件 |
| 模组的配置提示 | 同上 |
| 服务端插件发的消息（连接提示、错误） | 才可能在这个插件的语言文件里 |

> **这是排查重点。** 很多人去改这个插件的配置想汉化 DH 模组的界面文字——**改不到，那部分归模组管**。

4. 如果模组界面要汉化，去查 **Distant Horizons 模组自己的语言设置**，和这个插件是两件事

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 8. 什么时候别用它

- **基岩玩家为主** —— 装不了，收益为零
- **机器配置吃紧** —— 服务端要背成本
- **玩家技术栈不一致** —— 大部分人装不了，覆盖率低
- **玩家只想好好玩原版** —— 为少数人牺牲所有人的服务端性能
