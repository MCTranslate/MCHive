## 先把定位说清楚

**Denizen 不是玩法插件。** 这一点必须先讲，否则你会用完全错误的心智模型去装它。

| 它是 | 它不是 |
|------|--------|
| 一个脚本引擎 / 开发工具 | 一个「装完就能玩」的功能插件 |
| 让你写出别人做不到的定制玩法 | 一个现成的玩法包 |
| 需要你写代码的东西 | 一个点点鼠标就配好的 GUI |

**如果你不打算写脚本，Denizen 对你毫无价值。** 装上去只会多一个吃内存、可能在崩服时跟着炸的依赖。

**反过来说，如果你愿意写脚本**，Denizen 能做到的事比「玩法插件 + 一堆兼容补丁」的组合干净得多。它是 2011 年就在跑的成熟项目（DenizenScript 团队维护），基础扎实。

## 学习成本：这是你要先算清的账

**Denizen 的门槛是真实的，而且不低。**

它有自己的脚本语言（dScript），你得学：

| 要学的东西 | 难度 |
|-----------|------|
| 脚本基本结构 | 低 —— 和 YAML 有点像 |
| 变量与标签（tag）系统 | 中 —— 标签语法比较独特，要适应 |
| 事件系统（event） | 中 —— 什么条件触发什么脚本 |
| 上下文（context） | 中高 —— 这是 Denizen 里最容易把人绕晕的部分 |
| 调试 | 高 —— 出了问题不好定位 |

再加上 Minecraft 本身的机制（权限、插件间交互、NPC AI），**完整的上手周期以「周」为单位，不是「小时」**。

**诚实的判断标准**：

- 你写过 Java / Python / JS 之类的脚本，且愿意查文档 → 可以试
- 你只玩过 Minecraft，没碰过程序 → 先想清楚值不值
- 你想「有个能自定义任务的插件」→ 去看任务系统类插件，那才是你要的

## 它能做什么

**一、事件监听与响应。**
玩家做了某件事（挖了某种方块、说了某句话、进入某个区域）→ 触发一段脚本。这是 Denizen 最核心的能力。

**二、自定义命令。**
写一个 `/sethome2` 这样的命令，背后是任意逻辑：检查条件、发奖励、写数据库、广播消息。

**三、NPC 驱动。**
配合 Citizens 做能对话、能触发任务的 NPC。**注意 Citizens 是另外装的，Denizen 本身不给你 NPC。**

**四、把多插件串成流程。**
比如「完成 A 任务 → 检查 B 插件的等级 → 发放 C 插件的奖励 → 广播」。这种跨插件流程用脚本写比用命令组干净得多。

## 安装

官方仓库：<https://github.com/DenizenScript/Denizen>

1. 下载对应版本的 jar（**1.16 - 1.20.4**，超出这个范围不保证）
2. 丢进 `plugins/`
3. 重启，生成脚本目录

启动后先在控制台或游戏里确认它加载成功，然后**先跑通一个最简单的脚本**再上手复杂的。这一步能省掉后面很多困惑。

**建议的起步顺序**：

1. 写一个最简单的 echo 脚本，确认能输出
2. 写一个最简单的命令，确认能执行
3. 加事件触发
4. 最后才碰 NPC 和复杂上下文

**跳过前三步直接写第四步的脚本，是 Denizen 新手最常见的失败模式。**

## 版本范围要看清

**支持 1.16 - 1.20.4。** 1.20.5+ 及更高版本**不在声明支持范围内**。

这一点在现在的 MC 版本节奏下不是小问题——**如果你想玩的是 1.21+ 的服，Denizen 这条路暂时走不通。** 不是说一定不能用，是官方没声明支持，出了问题也没有依据去排查。

选版本前先确认你的服务端版本在这个区间内。

## 常见坑

**脚本没反应**
十有八九是事件没触发，或者触发条件写错。**Denizen 的调试主要靠脚本内的输出语句和控制台日志**，不熟悉这个链路的话排查会很痛苦。

**和 Citizens / 其他脚本插件冲突**
同类的东西只能有一个。**Denizen、Skript 这类脚本引擎同时装会互相干扰**，因为都要挂事件监听器。

**内存占用高**
它是一个完整的脚本运行时。**脚本写得越复杂，占用越大。** 写完记得清掉测试脚本，别把废弃脚本留在目录里。

**写了复杂脚本后崩服**
脚本有 bug 会连带崩服，这是脚本引擎的通病。**任何复杂脚本上线前都要在测试服跑够时间。**

**玩家能用脚本命令做不该做的事**
权限给宽了。脚本里调用的指令受执行者权限约束，**在脚本里执行命令时要明确以谁的身份执行**——这是权限设计的核心点，不是 Denizen 特有的问题，但在这里特别容易踩。

## 和 Skript 怎么选

两者都是脚本引擎，都面向服主。

| | Denizen | [Skript](#/plugin/skript) |
|---|---------|---------------------|
| 上手难度 | 更高 | 相对低 |
| 文档 | 深，但阅读门槛高 | 更适合新手 |
| 能力上限 | 高（上下文系统很强） | 中 |
| 适合 | 复杂流程、深度定制 | 简单触发、小功能 |

**如果你是第一次接触脚本引擎**，Skript 的学习曲线友好得多。**如果你已经在写脚本并且愿意啃文档**，Denizen 的上限更高。

**别两个都装。**

## 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

**但对 Denizen 来说，汉化基本不是「切换语言文件」的问题。**

原因很直接：**Denizen 面向的是服主和脚本作者，不是终端玩家。** 玩家看到的文字几乎全部来自你自己写的脚本内容——那本来就是中文，你直接写中文。

真正需要汉化的只有报错和调试输出，而那些是给写脚本的人看的，通常不需要汉化。

排查方式（如果你还是想确认）：

1. 启动一次服务器，看它在插件数据目录里生成了什么
2. 在生成的文件里搜 `lang`、`locale`、`message`、`translat`
3. 看有没有 `_zh_CN` 之类的中文变体结构

**没有语言文件是合理的结果，不是问题。**

Denizen 的官方文档（Scripting Hub）是主要学习资源，中文资料相对少。**官方仓库的 README 和 Wiki 是权威信息源**，比二手教程可靠。
