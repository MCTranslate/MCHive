## ⚠️ 服主先看：你大概不需要这个

**nightcore 是库插件（library plugin）。它不是一个「装了能让服务器变好的功能插件」。**

如果你打开这个页面是想找「让服务器更好用」的东西——**关掉这个页面，去看别的。**

| 你想解决的 | 库插件能干吗 |
|-----------|------------|
| 服务器卡顿 | ❌ 不能 |
| PvP 平衡 | ❌ 不能 |
| 汉化 | ❌ 不能 |
| 经济、领地、菜单 | ❌ 不能 |
| 缺少某个功能 | ❌ 不能 |

**库插件是给写插件的人用的。** 它把自己打包成 jar 发出来，别的插件在 `plugin.yml` 里声明依赖它，然后就能 import 它的类来用。它的价值全部体现在**别的插件**上。

### 1. 什么时候你（服主）才需要装它

只有一种情况：

> **你装的某个插件明确要求 nightcore 作为依赖。**

这时候你**必须**装，不装那个插件起不来。你会在控制台看到类似「缺少依赖」的报错。

**判断流程：**

```
某个插件加载失败
    ↓
控制台报错里提到 nightcore（或某个库）
    ↓
装上 nightcore，重启
    ↓
失败消失
```

**如果你没有遇到这种报错，就不要装。** 装了不会报错、不会变快、不会有新功能——**它就是一个沉默的 jar 在 `plugins/` 里躺着。**

> ⚠️ 本站未核实到 nightcore 的官方源码仓库。若某个插件要求它作为依赖，按那个插件的说明给的地址下载，别从不明来源下 jar。

### 2. 库插件的基本概念（给开发者）

如果你在写插件，需要理解库插件的几个特征：

| 特征 | 说明 |
|------|------|
| **没有功能给玩家** | 它自己没有任何命令、权限、GUI |
| **通过 API 提供能力** | 别的插件 `depend` 或 `softdepend` 它，然后调用它的类 |
| **版本必须匹配** | 库有 API 版本，插件针对某个 API 版本编译。**库版本不对会 `NoSuchMethodError` / `NoClassDefFoundError`** |
| **要声明依赖** | 在你自己的 `plugin.yml` 里写 `depend: [nightcore]` |

**最常见的翻车：API 版本不匹配。**

```
插件作者针对 nightcore 2.x 编译
    ↓
你装的是 nightcore 1.x
    ↓
启动时或运行时炸：NoSuchMethodError
    ↓
控制台一大坨堆栈，看着像插件坏了，其实是版本问题
```

**排查方向：先看堆栈里有没有 `NoSuchMethodError` / `NoClassDefFoundError`，有的话优先怀疑库版本，而不是插件本身。**

### 3. 为什么要用库，而不是各写各的

这是库插件存在的理由，也是你（服主）间接受益的方式：

| 方式 | 结果 |
|------|------|
| 每个插件自己写配置读取 | 每个插件的 YAML 风格不一样，你想改一个配置要查五个文档 |
| 每个插件自己写工具类 | 大量重复代码，不同实现还有细微行为差异 |
| **用共享库** | 统一约定，插件之间行为一致，冲突少 |

**所以库插件的质量直接影响到你服上插件之间的兼容性。** 库作者更新频繁 → 依赖它的插件集体炸。你间接承担了这个风险。

### 4. ⚠️ 库插件的固有风险：一次崩，全崩

这是你作为服主需要知道的部分：

```
插件 A 依赖 nightcore
    ↓
nightcore 有个 bug / 版本不兼容
    ↓
插件 A 起不来
    ↓
如果你有 5 个插件依赖它 → 5 个一起没了
```

**库插件的爆炸半径比普通插件大。** 一个普通插件挂了只是它自己挂；一个底层库挂了，**依赖它的所有插件一起挂**。

应对：

- 装库插件前，**看它最近更新时间和 issue 状态** —— 一年没更新的库慎重
- **控制台日志盯一下** 库有没有报错
- 出问题时**先查库，再查业务插件** —— 这个排查顺序能省你半小时

### 5. 什么时候你会遇到库插件

| 场景 | 说明 |
|------|------|
| 装的插件报错缺依赖 | 最常见，**装上** |
| 报错 `NoSuchMethodError` | **版本不匹配**，换库版本 |
| 你自己写插件 | 需要声明依赖 |
| 排查启动崩溃 | 堆栈里有 `NoClassDefFoundError` → 查库 |
| 纯粹想优化服务器 | ❌ 库插件帮不上 |

### 6. 装与不装的实际成本

| | 装 | 不装 |
|---|------|------|
| 磁盘 | 一个 jar | 0 |
| 内存 | 有一点占用 | 0 |
| 性能 | 极小（它自己不做事） | 0 |
| 风险 | 极小（不主动做事） | **依赖它的插件起不来** |

**所以结论很直接：有依赖需求就装，没有就别装。** 不存在「装了也没坏处但也没好处」的中间状态值得纠结。

### 7. 关于汉化

**本站未核实到 nightcore 的官方中文语言文件机制。** 但这基本不重要——**库插件一般不产生玩家可见文本**，它没有命令提示、GUI 标题这类东西。

引导式排查方法（如果你确实需要查）：

1. 进 `plugins/` 下 nightcore 的目录，看有没有语言相关文件
2. 搜配置文件里有没有 `message`、`locale`、`lang` 段落
3. **如果你确实看到了可汉化的文本**，那说明这个版本开始提供面向玩家的输出了——值得留意，但**不要预设它一定存在**
4. 如果你要汉化的是**依赖它的那些插件的提示**，那要去那些插件自己的目录里改，不是 nightcore 的锅

**这一节对本插件的现实意义有限。** 库插件的汉化是它下游插件的问题，不是它自己的问题。

> 通用排查方法见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 8. 什么时候别用它

基本上是：**任何不是「被别的插件要求」的理由。**

- ❌ 想优化服务器性能 —— 它不做事
- ❌ 想加功能 —— 它不提供
- ❌ 想汉化 —— 它没什么可汉化的
- ❌ 「别的服装了」 —— 库不是功能插件，没有攀比价值
