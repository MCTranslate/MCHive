## 它解决的具体问题

玩家在普通世界里正常下界传送门，右键进下界——**但进不去**，或者进去了位置不对，或者在原地反复循环。

**原因不在配置，在 Multiverse 的世界结构。**

用 Multiverse-Core 管理的世界，「主世界」和「它的下界」是两个**独立加载的世界**。原版传送门逻辑只认「玩家所在世界的下界维度」，而 Multiverse 的下界是一个单独的世界文件夹（`_nether` 后缀），不在这套默认映射里。结果就是——**传送门找不到对应的下界世界**。

Multiverse-NetherPortals 就是补上这层映射：

| 场景 | 没有这个插件 | 装上之后 |
|------|--------------|---------|
| 在主世界进下界 | 失败 / 进虚空 / 卡在原地 | 正常进对应下界 |
| 在下界回主世界 | 同上 | 正常返回 |
| 末地 | 同样问题 | 同样修复 |
| 玩家自建的独立世界 | 传送门基本不可用 | 正常工作 |

> 理解这一点很重要：**它不是一个「功能增强」插件，它是在修一个 Multiverse 带来的结构性问题。** 不用不知道，一用就离不开了。

## 硬依赖：Multiverse-Core，且主版本要一致

**没装 Multiverse-Core 的话，这个插件没有意义。** 它的整个作用对象就是 Multiverse 管理的那批世界。

| 要求 | 说明 |
|------|------|
| **Multiverse-Core** | **必装**，且主版本号必须和本插件一致 |
| 服务端 | Paper / Spigot 系（1.13 起） |
| 其他 Multiverse 附属 | 装了更好，不装不影响本插件工作 |

**主版本一致**是硬要求。Multiverse 生态的附属插件靠主插件提供的 API 工作，跨大版本调用 API 会直接崩在初始化阶段。

```
plugins/
├── Multiverse-Core.jar            # 必装，先装
└── Multiverse-NetherPortals.jar   # 本插件
```

启动顺序无所谓，两个都在 `plugins/` 里就会自动关联。

官方仓库：<https://github.com/Multiverse/Multiverse-NetherPortals>

> 下载时注意选对应**主版本**的发行版，不要拿最新版往老核心上丢。

## 安装

1. 先确认 `Multiverse-Core` 已经在正常运行
2. 把 NetherPortals 的 jar 丢进 `plugins/`
3. 重启服务器

启动后控制台应该会出现它关联到 Multiverse-Core 的日志。**如果没出现，99% 是版本号不匹配。**

## 还要做什么：确认下界世界存在

**插件装好不等于传送门立刻能用。** 还得满足前置条件：

| 条件 | 说明 |
|------|------|
| 下界世界已创建 | 那个世界是通过 Multiverse 创建的，有 `_nether` 对应世界 |
| 末地世界已创建 | 同理，需要 `_the_end` |
| 传送门在正确位置 | 传送门要建在有效地形上（不是虚空、不是空气墙） |

**最常见的坑：世界是手动复制文件夹建出来的，不是用 Multiverse 命令创建的。** 手动复制的世界没有正确的世界注册信息，插件找不到它，传送门照样不工作。**验证办法：用 Multiverse 的世界列表命令看这个世界在不在列表里。**

## 使用什么命令

Multiverse 生态的命令由主插件统一提供，NetherPortals 挂在其下。**具体命令形式以你版本的命令列表为准**——进游戏敲 Multiverse 的帮助命令，看当前版本实际提供了什么，比翻旧教程靠谱。

需要做的两件事：

1. **创建/确认对应的下界与末地世界**（如果还没有）
2. **检查并修正世界之间的传送门链接关系**

第二点是重点。链接不对的表现是：门能用，但进错世界（比如从 A 世界的门进到了 B 世界的下界）。**这种问题在实际游玩前很难发现，一定要逐个世界测试一遍。**

## 常见坑

**传送门把人丢进虚空**
传送门在自定义地形里，而对应下界世界的对应坐标是空的。**这不是插件的问题，是世界生成层面的问题。** 解决方向是在建世界时处理好地形对应关系，或者接受下界是虚空型世界（那就要另配传送方式）。

**玩家反复进出卡在原地**
世界链接关系错了，或者下界世界没被 Multiverse 正常注册。检查世界是否在 Multiverse 的世界列表中。

**启动时插件加载失败**
Multiverse-Core 版本不匹配。**这是九成原因。**

**控制台刷红但游戏能玩**
附属插件的告警日志不影响传送门工作。**看具体报错内容，不要看到红字就慌。**

**在某些世界用不了**
那些世界不是 Multiverse 管理的（默认主世界之外手动加的、或者别的插件管的）。**这个插件只对 Multiverse 体系内的世界生效。**

## 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

**好消息是这类插件几乎没有需要汉化的文案。** 它的界面输出基本是命令反馈（英文或原版风格），玩家实际看到的是原版传送门的交互——那本来就是中文。

排查方式：

1. 启动一次服务器，看插件数据目录里生成了什么文件
2. 在生成的文件里搜 `lang`、`locale`、`message`、`translat`
3. 看有没有 `_zh_CN` 之类的中文变体结构

找不到语言文件，就是没有语言层，不用再花时间。**想改玩家看到的文本，改命令提示的话应该去看 Multiverse-Core 那边**——本插件自己基本不输出文案。

Multiverse 生态的通用排查思路见 [多世界搭建](#/guide/multi-world-setup)。
