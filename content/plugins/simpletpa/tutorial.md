## SimpleTPA 安装教程

### 1. 它做什么

```
你 → /tpa Steve          「我想传送到你那里」
Steve → /tpaccept you    「同意」
你 → 出现在 Steve 身边
```

**这五个动作是服务器的通用语言。** 几乎每个 Minecraft 服务器都有这套流程，因为它是「互相帮忙」的基础动作：

- 队友在地里挖矿，你送一箱食物过去
- 朋友在远处盖房子，你去看
- 队友在打 boss，你在旁边打药

**没这套东西的话，玩家只能用坐标 + 走路，或者用 `/tp` 直接飞过去**——后者会破坏「家在哪个世界」的意义。

### 2. ⚠️ 首要问题：你的服是不是已经有 TPA 了

**在装之前先确认这件事。** 这是本页最需要提醒的一点。

很多基础插件包（EssentialsX、部分服务器整合包、某些一键安装的插件合集）**自带 TPA**。装两个的结果：

| 症状 | 原因 |
|------|------|
| `/tpa` 提示未知命令 | **另一个插件抢占了命令**（或反过来，你的没加载） |
| `/tpaccept` 有两个，行为不同 | 两套逻辑并存 |
| 传送后多一条消息 | 两个插件都在播报 |
| 传送后物品/背包异常 | 两套逻辑都在处理事件 |

**TPA 命令冲突是服务器运营里非常常见的现象**，而且排查起来很烦（因为要一个个插件试着禁用）。

**排查方法：** 逐个禁用怀疑的插件，重启，看 `/tpa` 恢复没有。

### 3. 版本要求

**支持 MC 1.21.4 - 26.3。**

- **1.21.4 是比较新的下限** —— 这是个只面向新版 MC 的插件。如果你的服在 1.20.x 或更早，**它用不了**
- 需要 Spigot / Paper 系

**装之前先看你的 MC 版本。** 这是本页最硬的一个前置条件。

### 4. 它「简单」在哪，以及简单意味着什么

插件名字叫 SimpleTPA，那它就真的是个「 uncomplicated 」的小插件——只做传送请求这一件事。

**「简单」的代价：**

| 它不做的事 | 你需要另找的方案 |
|-----------|----------------|
| 传送冷却 | 冷却类插件，或自己写 |
| 传送费用 | 经济插件 + 传送相关配置 |
| 跨世界权限限制 | 领地/世界管理插件 |
| 传送后的保护期 | PvP 管理类插件 |
| 传送前的安全确认 | — |
| 黑名单 / 不接受请求的开关 | 某些实现有基础开关，**以你的版本为准** |

**这不是缺点，是取舍。** 小插件把一件事做干净、没一堆要配的选项，很多服反而更省心。**但你得知道缺什么。**

**尤其是传送后的保护期** —— 传送到队友身边然后被 PvP 秒杀，这是 TPA 类插件被诟病最多的场景。**SimpleTPA 大概率不处理这个**（本页不替它承诺）。**如果你的服 PvP 活跃，这件事要单独想办法。**

### 5. 安装

1. 下载 jar 放进 `plugins/`，重启
2. 生成 `plugins/SimpleTPA/`
3. 权限分配

**没有前置依赖。** 这是它适合当底层组件的原因。

### 6. 常用命令

| 命令 | 说明 |
|------|------|
| `/tpa <玩家>` | 发起传送请求 |
| `/tpaccept [玩家]` | 同意 |
| `/tpdeny` 或 `/tpdeny <玩家>` | 拒绝 |
| `/tpcancel` | 取消自己发出的请求 |
| `/tps` 或 `/tps <玩家>` | 切换传送开关（部分实现有） |

> ⚠️ **具体命令和参数写法以你版本的帮助输出为准。** 极简插件的命令通常就是这几个，但**「拒绝」和「取消」的实现差异很大**（有些是一个命令带参数，有些是分开的）。不写死。

**`/tps`（传送开关）这个功能值得确认一下。** 有的实现支持玩家自己「现在不接受任何传送请求」——这个功能在**不想被打扰的时候很有用**，很多服主会开。

### 7. 权限

**TPA 的权限设计有个需要你自己决定的问题。**

| 方案 | 效果 |
|------|------|
| 只控制「能不能用 TPA」 | 简单，但新玩家和 VIP 权限一样 |
| 分别控制「发起」「接受」「强制」 | 灵活 |
| **「强制传送」（不经过对方同意）** | ⚠️ **危险** |

**「强制传送」要小心。** 如果给权限的节点太大，等于开了后门：

```
管理员 / 某些组可以强制传送任何人
  → 玩家被强制拉走
  → 在 PvP 里等于被打
  → 或者在别人建了一半的房子里被打断
```

**建议：强制传送只给 OP / 管理员。** 这个权限不是用来做日常功能的，是用来处理「玩家卡在某处出不来了」这种紧急情况的。

### 8. 常见坑

**和别的插件命令冲突**
见第 2 节。**TPA 命令冲突非常常见**，先排查基础插件包。

**被队友卖到敌人面前**
```
你 /tpa 队友
队友 /tpaccept
你 出现在队友身边
队友的敌人已经在那里等着了
```

**这是 TPA 机制的固有问题，不是插件的 bug。** 除非 SimpleTPA 带了「传送后短暂无敌」，否则任何 TPA 插件都有这个风险。

**解决方向：** 传送后保护期（需要别的插件）、或者队伍协议（现实约束）。

**传送后被 PvP 秒杀**
同上。**如果你的服 PvP 活跃，这是个必须解决的问题**，而 SimpleTPA 大概率不解决。

**玩家抱怨「不接受别人的 TPA」**
用 `/tps` 之类功能关掉它（见第 6 节）。

**传送到很远的坐标，服务器卡一下**
跨世界/远距离传送会加载区块。**瞬间加载大量区块会掉 TPS。** 这是正常现象，不是 bug。

**和 EssentialXChat / 领地插件的消息重复**
传送成功/拒绝的消息**可能和别的插件的消息重复发**。表现为同一件事播报两遍。

**「未知命令」**
两种可能：1. 插件没加载（看控制台）；2. 被其他插件抢了命令（见第 2 节）。

### 9. 关于汉化

**本站未核实到 SimpleTPA 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/SimpleTPA/`，看有没有语言文件目录
2. 搜配置文件里有没有 `message`、`language`、`locale` 段落
3. **需要汉化的内容通常很少**：TPA 的消息量本来就小（几个提示而已）
4. **如果只有几条消息，用其他插件的消息接管/自定义功能可能比汉化它更省事** —— 有些服的错误提示根本不值得改

**一个务实的判断：** 极简插件的中文支持通常不是刚需。**玩家看到英文提示，几秒钟就明白了。** 除非你非常在意社区体验，否则这一项可以先放着。

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **已经有 TPA 了** —— 见第 2 节，冲突是主要风险
- **MC 1.20.x 或更早** —— 声明区间从 1.21.4 起
- **服务器已有 EssentialsX** —— EssentialsX 自带 TPA 相关功能，**先确认它是否已经覆盖你的需求**
- **纯战斗服，禁止传送** —— 有些服务器设计上就不该有 TPA

### 11. 传送安全：SimpleTPA 不管的部分

**这一节值得单独说，因为它是 TPA 类插件的通病。**

即使 TPA 本身没问题，**组合起来可能有漏洞**：

| 组合 | 问题 |
|------|------|
| TPA + PvP | 传送落地被秒 |
| TPA + 队伍系统 | 队友可能被卖 |
| TPA + 经济 | 无冷却时被用来刷经济（如果某个操作顺便触发） |
| TPA + 战斗日志 | 被击杀后要不要返回？**各服不同，这是个需要你决定的问题** |

**三个值得你在服里实测的场景：**

1. **在 PvP 区用 TPA 落地被秒** —— 会发生吗？玩家会怎么想？
2. **战斗中被击杀后，是送回死亡点还是原地？** 这个规则要跟你的服务器设定一致
3. **跨世界 TPA 有没有限制？** 有些服不允许跨维度 TPA（防止传到下界被烧死）

**这些不是 SimpleTPA 的 bug，是你的服需要定的规则。** 先测一遍，比上线后被玩家发现好。
