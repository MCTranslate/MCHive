## ⚠️ 先看这里：LiveKit 需要一套独立的媒体服务器

**这是 LiveKit 最大的部署门槛，也是最容易被低估的部分。**

LiveKit 插件**不是自包含的**。它的工作方式是：

```
Minecraft 客户端（拿麦克风）
    ↓ 加密音频流
LiveKit 插件（服务端，转发）
    ↓ WebSocket 协商 + 音频流
LiveKit 媒体服务器（SFU，独立的 Go 进程）    ← ⚠️ 必须自己另外部署
    ↓
其他玩家的客户端（收到声音）
```

**中间的「LiveKit 媒体服务器」是一个独立运行的服务，和 Minecraft 服务端不是一回事。** 插件本身不做编解码和转发，它只是把客户端接到那套媒体服务上。

不部署媒体服务器 = 插件装了、命令能敲、但**没人听得到任何人说话**。

| 你以为的 | 实际的 |
|---------|-------|
| 装个 jar 就有语音 | 需要 jar + 一套 LiveKit 服务（可以是云服务） |
| 语音走 Minecraft 流量 | 音频是独立连接，**和游戏流量分开** |
| 端口开一个就行 | 需要放行媒体服务对应的端口（UDP 为主） |
| 免费的 | 媒体服务本身有成本——自建要服务器，云用要钱 |

**这也是为什么 LiveKit 的 MC 支持上限停在 1.21.8**——它把精力投在语音架构上，不是 MC 版本追逐上。

## LiveKit 安装教程

### 1. 它能做什么

| 功能 | 说明 |
|------|------|
| 语音频道 | 玩家加入/退出频道，类似 Discord |
| 按距离衰减 | 越远声音越小，可配 |
| 私密频道 | 密码保护的私密语音房 |
| 队伍语音 | 和队伍系统联动，队友单独一个频道 |
| 静音 / 屏蔽 | 屏蔽单个玩家 |
| 说话状态 | 谁在说话有界面提示（需要资源包） |

**核心价值是社交。** 文字聊天刷屏的时候，一嗓子能解决的事不用打 200 字。这在社区服、生存服、长跑团式玩法里是刚需。

### 2. 版本要求

**支持 MC 1.16 - 1.21.8。**

- **1.16 是下限**（更老的版本客户端音频能力不够）
- **1.21.8 是上限**——⚠️ 你的服如果在 1.21.9+ 或 26.x，**LiveKit 的声明区间不覆盖**

### 3. 部署 LiveKit 媒体服务

**这一步是必须的，而且有两条路：**

| 路线 | 做法 | 适合 |
|------|------|------|
| **用 LiveKit 云服务** | 注册 LiveKit Cloud，拿它的 URL 和 API key | 不想运维、规模不大 |
| **自建 media server** | 跑 LiveKit 的开源媒体服务（Docker 一条命令） | 想省钱、能自己维护 |

**两种路线的关键区别：**

- **云**：省事，但要**按用量付费**。玩家多、时长长就是真金白银
- **自建**：不要服务费，但服务器要额外扛音频流量，**而且这服务器要放在离玩家网络近的地方**（延迟直接等于语音延迟）

> ⚠️ 具体的部署命令、配置文件位置、密钥获取方式，**请以 LiveKit 官方文档为准**。本页不抄部署步骤——抄错了是音频不通的连锁排查，很浪费时间。

**必须拿到的三样东西**（后面填进插件配置）：

1. **服务 URL**（wss:// 开头的地址）
2. **API key / secret**
3. 你的媒体服务对应的**端口放行清单**

### 4. 端口

**这一步不做，100% 不通。**

| 流量 | 协议 | 说明 |
|------|------|------|
| 协商信令 | WebSocket（WSS） | 客户端和媒体服务之间的握手 |
| 音频 | **UDP 为主** | 实时音频，UDP 是必须的 |

**UDP 端口是最容易漏的。** 很多机房只放行了 TCP，症状是：连接成功、能进频道、**听不到声音**。

具体端口号以你的 LiveKit 部署配置为准（**站点标题不要臆造端口——以你的实际配置和 LiveKit 文档为准**）。

### 5. 安装插件

1. 下载 jar 放进 `plugins/`，重启
2. 生成 `plugins/LiveKit/`
3. **填入服务 URL 和 API key**（配置键名以你版本的配置文件注释为准）
4. 确认端口放行
5. 重启后测试

**建议找个没人在线的时间做第一次联调。** 语音不通的排查链条长（服务端配置 → 媒体服务 → 防火墙 → 客户端权限 → 麦克风设备），有其他玩家在线时你没法专心排。

### 6. 客户端前置

**语音功能对客户端有要求：**

| 要求 | 说明 |
|------|------|
| 麦克风设备 | 玩家的硬件，插件管不了 |
| 客户端音频能力 | 1.16+ 才稳定 |
| **可能需要资源包** | 说话状态提示、UI 元素这类**是客户端渲染的**，没有资源包就没有提示 |

**资源包这件事要提前跟玩家说。** 和 GSit 一样的道理——服务端说"这个玩家在说话"，界面怎么显示是客户端的事。

> ⚠️ 资源包是不是必需、能不能关，**以你版本的配置注释为准**。不同版本对「无资源包时的降级行为」处理不一样。

### 7. 常用命令

| 命令 | 说明 |
|------|------|
| `/voice` 或类似主命令 | 加入/离开语音（**具体名字以你版本的帮助为准**） |
| 相关子命令 | 静音、屏蔽、私密频道等 |

> ⚠️ **LiveKit 系的命令在不同版本间改过多次**（有的版本是 `/voice`，有的是别的形式）。**本页不写具体命令名——写错了你敲了没反应，还以为是配置问题。装完直接看 `/voice` 或插件主命令的帮助输出。**

### 8. 常见坑

**能进频道，但听不到声音**
九成是 **UDP 没放行**。其次是媒体服务地址填错、或者 API key 无效。**这是最典型的一个症状**——说明信令通了但媒体流不通。

**自己听得到别人，别人听不到自己**
单向音频问题，通常是**麦克风权限**或者客户端音频设置。**先在自己机器上开系统权限测试。**

**所有人都听不到**
媒体服务根本不通。检查服务端配置里的 URL、检查媒体服务是不是真的在跑、检查防火墙。

**延迟很大 / 卡顿**
- 自建媒体服务器**离玩家太远**——语音延迟就是网络延迟
- 服务器带宽不够，音频流和游戏流量抢带宽
- 服务器在跨洲，玩家分布太散

**MC 1.21.9+ / 26.x 装不了或出问题**
见第 2 节。**声明区间到 1.21.8。**

**和其他语音/聊天插件冲突**
两个语音插件会抢麦克风、抢音频通道。**同时只留一个语音方案。**

**玩家嫌吵**
语音和文字并行的典型副作用。社区服需要**频道规则**（比如不许在主频道一直开麦），光靠技术手段管不住。

**云服务账单超预期**
语音时长 × 人数 × 时长。**这是个真实成本，不是白嫖的。** 大服自建更划算，但要有运维能力。

### 9. 关于汉化

**本站未核实到 LiveKit 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/LiveKit/`，看有没有语言文件目录
2. 搜配置文件里有没有 `language`、`locale`、`message` 段落
3. **注意区分三个界面**：
   - **游戏内的提示消息** —— 服务端发出，可能走语言文件
   - **语音 UI 界面**（频道列表、说话指示）—— **这些往往是客户端渲染的资源包内容**，改服务端配置不生效
   - **媒体服务自己的界面**（如果用 LiveKit 自带的开发/调试界面）—— 那是另一套东西
4. 客户端 UI 的汉化路径是**替换资源包**，比改语言文件麻烦得多

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。

### 10. 什么时候别用它

- **1.15 及以下的老服** —— 不支持
- **1.21.9+ 的服** —— 声明区间不覆盖
- **没有额外的服务器 / 不愿意付云服务费用** —— 媒体服务是硬门槛
- **服务器玩家都是单机自玩** —— 没人一起说话
- **网络延迟本身就很高（跨洲玩家）** —— 自建媒体服务解决不了物理延迟

### 11. 如果只是想「能说话」

**先确认你真的需要语音系统。**

语音是一个**显著增加运维复杂度**的方案：

| 你的需求 | 建议 |
|---------|------|
| 队伍之间少量沟通 | Discord / QQ 语音 + 游戏内队伍频道 |
| 就在电脑前和朋友连机 | 语音软件直接开，游戏里少打字 |
| 真的想要「在游戏里说话」 | 那 LiveKit 值得部署 |
| 服务器是纯 PvP 竞技 | 基本不需要 |

**很多服装了语音插件，活跃度提升有限，但网络配置和答疑成本翻倍。** 先用外部语音软件试一段时间，确认真的需要，再上这套。
