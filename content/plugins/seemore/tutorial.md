## SeeMore 安装教程

### 1. 它解决的到底是什么问题

**这是一个很多服主想不到的浪费。**

情况是这样的：你的 `server.properties` 里设了 `view-distance=16`。这意味着**服务端会给每个玩家加载 16 格内的区块**，不管他自己的客户端渲染距离设了多少。

```
玩家 A 客户端设「渲染距离 8 格」（为了流畅，用的是 4G 显存的手机）
     ↓
服务端仍然给他加载 16 格
     ↓
他永远看不到 9-16 格（客户端自己丢弃了）
     ↓
但那 8 格的区块数据已经传给他了，也已经在服务端内存里了
```

**这就是纯粹的浪费。** 一半的数据传过去被丢弃，一半的内存占着没人看。

SeeMore 的做法极简：

```
读玩家客户端的渲染距离设置 → 把服务端的视距设成同一个值
```

**它的效果**：客户端设 8 的人不再浪费服务端一半的视距开销。**配置零改动，纯粹白拿的优化。**

### 2. 为什么大多数服不需要它

说实话，这个优化对**大多数服是无感的**，因为：

- 玩家里用手机、低配电脑的人本来就少
- 大家默认开满视距
- 你就算省下来了，那部分开销本来就该给别的玩家用

**什么情况下它值得装：**

| 场景 | 为什么值得 |
|------|-----------|
| **玩家设备参差很大**的服 | 有人 4G 内存手机开 4 格，你给他拉 16 格毫无意义 |
| **多人同时探索的大世界服** | 视距是区块压力的主要来源，逐玩家收紧收益明显 |
| **玩家抱怨加载卡顿** | 视距高 → 加载区块多 → 客户端卡 |
| **你有性能余量问题** | 便宜的优化，先做了再说 |

**如果你服的玩家都是电脑、都开满视距，装它没有任何区别。**

## 3. 配置

配置文件 `plugins/SeeMore/config.yml`，**这是本文档核实过的真实内容**（该插件的配置很小，全文如下）：

```yaml
# SeeMore 的配置
# 请勿修改！
version: 2

# 玩家改动客户端设置后，延迟多少刻再降低其视距
# * 这是为了防止玩家反复改视距来压垮服务器
update-delay: 600

# 是否在控制台记录视距变更
log-changes: true

# 以下设置可以按世界分别指定
# * 注意：未在此列出或缺少设置的世界，会使用 default 段下的设置
world-settings:
  default:
    # 该世界玩家的最大视距
    # 设为 -1 则使用服务器配置的视距
    maximum-view-distance: -1
```

### 逐项说明

| 配置项 | 说明 |
|--------|------|
| **`version: 2`** | 配置结构版本，**注释明确写了「请勿修改」** |
| **`update-delay: 600`** | 600 tick = **30 秒**。玩家改完客户端视距后，**等 30 秒才生效** |
| **`log-changes: true`** | 视距变化记到控制台。调试有用，生产环境可以关掉减少刷屏 |
| **`maximum-view-distance: -1`** | **-1 = 用服务器配置的视距**（也就是不做限制） |

### `update-delay` 为什么是 30 秒

注释写得很清楚：

> This stops players overloading the server by constantly changing their view distance.

**如果不延迟，玩家反复改客户端视距 → 服务端反复重算重载区块。** 这是可以被恶意利用的：一个玩家循环改视距，就能让服务端不停干重活。

30 秒的延迟让「改设置」这个行为变得没意义。**这一项是安全设计，不要试图调到 0。**

## 4. 按世界配置

`world-settings` 下可以按世界单独设：

```yaml
world-settings:
  default:
    maximum-view-distance: -1   # 不限制
  world:
    maximum-view-distance: 8   # 主世界限 8 格
  world_nether:
    maximum-view-distance: 4   # 下界限 4 格
```

**两个行为要注意：**

| 情况 | 结果 |
|------|------|
| 世界没在 `world-settings` 里列出 | 用 `default` 段的设置 |
| 世界列出了但某项设置缺失 | **也用 `default` 段的设置** |

**未列出的世界不会被自动限制。** 如果你的服有很多世界，要逐个写清楚。

## 5. 命令

| 命令 | 说明 |
|------|------|
| `/seemore reload` | 重载配置 |
| `/seemore average` | **查看每个世界的实际平均视距** |
| `/seemore players` | 查看所有在线玩家的服务端视距 |

全部需要 `seemore.command` 权限。

> ✅ **`/seemore average` 是验证有没有效果的关键命令。** 装完跑一下，如果各世界平均视距和你的 `view-distance` 一样，说明玩家都开着满视距（那这个插件对你没用）。如果明显低于设定值，说明有玩家在用低视距，插件生效了。

## 6. 命令解读

| 命令 | 告诉你什么 | 怎么用 |
|------|-----------|------|
| `/seemore average` | **各世界实际生效的平均视距** | 判断插件有没有起作用 |
| `/seemore players` | **每个玩家的服务端视距** | 找出谁在用低视距、谁的设置没生效 |

**排查思路**：如果某个玩家明明设了 8 格视距，但 `/seemore players` 显示他 16 格，那就是他的客户端设置没被正确读取，或者他改设置还没到 30 秒。

## 7. 前置条件

| 要求 | 说明 |
|------|------|
| 服务端 | **Paper / Purpur / Folia** |
| MC | 1.19 - 1.21.x |
| 硬依赖 | **无** |

**注意它需要 Paper 系**（要 Paper API 提供的玩家视距设置接口），不是纯 Spigot。

## 8. 常见坑

**装了但没效果**

按顺序查：

1. `/seemore average` —— 看实际平均视距
2. 你的 `maximum-view-distance` 是不是设成了 `-1`（**-1 就是不限制，等于没装**）
3. 玩家是不是都开着满视距（那就是真没效果，不是故障）

**改了配置没生效**

`/seemore reload`。

**玩家改视距要等很久才生效**

**这是设计如此**——`update-delay: 600` 就是 30 秒延迟，防刷的。

**某个世界没被限制**

检查 `world-settings` 里有没有列这个世界，以及那一项是不是漏了。**没列 = 用 default = 如果 default 是 -1 就是不限制。**

**和 `view-distance` 冲突吗**

不冲突。它的 `maximum-view-distance` 是**在服务器配置之上再加一层上限**：

```
最终视距 = min(客户端设置, world-settings 的最大值, 服务器 view-distance)
```

## 9. 缺点

| 缺点 | 说明 |
|------|------|
| **只支持到 1.21.x** | 新版 MC 要等更新 |
| **需要 Paper 系** | 纯 Spigot 用不了 |
| **只在玩家主动降视距时有效** | 大多数情况收益为零 |
| **配置极简，功能单一** | 就做这一件事，没有统计、没有报告、没有可视化 |
| **默认 `log-changes: true` 会刷屏** | 视距变化频繁的服建议关掉 |
| **有 30 秒延迟** | 对刚改完设置就期待生效的玩家体验不好 |

**它是一个「便宜、窄、但白拿」的优化。** 别指望它解决性能问题——它的作用是在玩家已经主动降视距的情况下，帮你把省下来的资源用好。

## 10. 关于汉化

> ⚠️ **本站未核实到 SeeMore 的官方中文语言文件机制。**

**这个插件很可能根本没有需要翻译的东西**——它只有 4 个命令（reload / average / players + 主命令），输出的是数字和世界名。

想加中文提示，用 PlaceholderAPI 或别的插件间接做。`config.yml` 里没有任何面向玩家的文案可改（见上面贴出的完整配置）。
