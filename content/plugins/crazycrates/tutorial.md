### 1. 它在做什么

**把一个箱子变成抽奖机。** 玩家付出代价（通常是货币，或拉杆次数），获得随机奖励。

```
玩家右键箱子 / 拉杆
        ↓
按权重抽一次
        ↓
从奖励池里按权重命中一项
        ↓
物品进背包 + 播放动画 + 播报
```

**它在你服务器经济里的位置：**

```
玩家  ──→ 货币/货币点  ──→  玩家
            ↑                    ↑
         抽奖消耗              随机产出
            │                    │
            └──── 货币回收 + 物品再分配 ────┘
```

所以它其实是个**货币回收泵**：把玩家手上的货币重新洗回物品和战利品，同时给「开出好东西」这个瞬间一个情绪高点。**很多服装它不是因为好玩，是因为它能有效销毁过剩货币。**

### 2. 核心概念：权重

抽奖的核心是**权重（weight）**，理解了这一个概念就够了：

| 概念 | 含义 | 影响 |
|------|------|------|
| 权重 | 一个奖励被抽中的相对概率 | 权重 10 的比权重 1 的常见 10 倍 |
| 保底 | 抽够 N 次必出某项 | 控制「非酋体验」的下限 |
| 冷却 | 一段时间内不能开 | **防刷**，最重要的一环 |

**权重设计不当是这个插件最常见的翻车原因。** 几种典型事故：

| 事故 | 后果 |
|------|------|
| 权重总和算错 | 概率不是预期的那个比例 |
| 极品奖励权重给太高 | 经济通胀，单件饰品刷爆 |
| 奖池里混进不该有的东西 | 有人开出 TieToMe / 内部物品 |
| 成本远低于期望产出 | **无限刷钱** —— 见下方警告 |

### 3. ⚠️ 必看：经济系统里最危险的插件

**抽奖箱是「玩家花钱 → 随机出货」，这个结构天然容易被利用成刷钱机器。**

**必须同时具备的三道闸：**

| 闸 | 做什么 | 不做的后果 |
|----|--------|-----------|
| 成本 > 期望产出 | 定价时算过期望值 | **无限刷钱**，经济崩盘 |
| 冷却 | 单位时间内最多开几次 | 脚本/宏刷箱 |
| 防重复领取 | 同一次抽奖记号 | 断线重连重复领奖 |

**期望值怎么算（这是唯一需要你动手算的一步）：**

假设一个箱子成本 `C` 币，奖池里：

| 奖励 | 概率 | 折算价值 |
|------|------|---------|
| 普通石头 ×64 | 70% | 10 币 |
| 铁锭 ×16 | 25% | 60 币 |
| 钻石 ×1 | 5% | 300 币 |

**期望产出** = 0.7×10 + 0.25×60 + 0.05×300 = 7 + 15 + 15 = **37 币**

定价必须满足：**C 明显大于 37**。定 40 币的话只有 3 币利润，磨损和资金效率太紧；定 100 币，利润率 63%，玩家才有动力。

> **反过来也要检查：如果 C 定得太低（比如成本 5 币），玩家能稳定套利，一晚上就能把全服经济打崩。** 上线前拿实际奖池算一遍，别凭感觉。

**再补一句：如果你的服开了玩家间交易（ChestShop 之类），抽奖箱就是洗钱的合法通道。** 玩家可以从别人手里低价买箱子、开出高价值物品再卖回去。**抽奖箱子是否允许被交易，是你要单独做决定的。**

### 4. 安装

1. 确认来源可信（见上方警告），下载 jar
2. 丢进 `plugins/`
3. 启动服务器，看控制台有没有依赖缺失或加载失败
4. 检查生成的配置目录，确认文件在（**这一步也是核实有没有真实配置机制的机会**）
5. **开一个测试服账，先小额跑一遍抽奖，验证概率和冷却生效，再上生产**

### 5. 配奖池的原则

不要一上来配 50 个箱子。按这个顺序来：

| 阶段 | 做什么 |
|------|--------|
| 起步 | 只上 1-2 个箱子，10 来个奖励项，**先跑通** |
| 观察 | 看一个月真实数据：开箱人数、日均开箱量、实际收益分布 |
| 调整 | 按数据调权重和成本，而不是按「感觉玩家会不会太兴奋」 |
| 扩展 | 跑顺了再加快捷方式 / 菜单分类 |

**奖池里该放什么：** ✅ 和玩法强相关的东西（材料、半成品、稀有过渡装备）；✅ 有回收价值、能卖回经济系统的；❌ **不可再生的顶级物品**（刷一件少一件）；❌ 内部/管理物品（有些服不小心把管理员物品放进奖池）。

### 6. 常见坑

**开箱没反应 / 权限不够**

抽奖箱的交互本质是物品交互事件。常见原因：箱子所在区域被其他领地/保护插件的交互保护挡了、玩家没有对应权限节点。**看控制台有没有被别的插件 cancel 掉的记录。**

**和领地保护打架**

开箱要**打开界面** + **从容器里取物品** + **放奖励进背包**，三个动作都会触发不同插件的检查。保护插件挡掉其中一个，现象就是「能开但拿不到东西」。

**和 Vault / 经济插件的依赖**

抽奖箱通常要扣货币。装完**确认你的经济插件（EssentialsX Economy 等）是否在位**。经济系统不在位时的表现往往是「不扣钱也不给东西」或者直接报错。

**玩家用宏刷箱**

**冷却不是可选项，是必需品。** 上线前确认冷却真的生效了——开一个测试号，用加速器测间隔。如果插件版本没提供冷却能力，**你需要靠别的方式限制**（比如只在菜单 GUI 里开、限制每人每日次数）。

### 7. 什么时候别用它

- **新服 / 还没跑通经济** —— 玩家手里没货币可抽，先把经济做起来（见 [经济系统配置](#/guide/economy-setup)）
- **纯PvP 或小模式服** —— 抽奖和战斗节奏没关系
- **已经有活跃的玩家交易** —— 洗钱通道的风险要先评估
- **服主接受不了随机付费** —— 玩家抽到垃圾会积累怨气，哪怕概率是公平的

### 8. 关于汉化

**本站未核实到 CrazyCrates 的官方中文语言文件机制。** 若要汉化需自行确认。

引导式排查方法：

1. 进 `plugins/` 下的 CrazyCrates 目录，**搜文件名**找 `lang`、`locale`、`messages`、`zh`、`translations` 之类的
2. 打开配置文件，**搜关键词** `message`、`locale`、`lang`、`name`、`display-name`
3. 分清这三类文本，**它们走的是完全不同的路径**：

| 文本类型 | 典型例子 | 能否靠改文件汉化 |
|---------|---------|----------------|
| 界面提示 | 「恭喜你获得！」 | 大概率在语言文件里 |
| 奖励物品名 | 奖池里那个物品叫什么 | **通常来自 Minecraft 本体的物品名**，不是插件管 |
| 箱子方块名 | 你把箱子自定义成「神秘宝箱」 | 可能在配置里，也可能是物品改名/头名 |

> 第 2 行是最容易误判的：**奖池里「钻石」显示成「钻石」是 Minecraft 自己的语言文件在起作用，不是插件的锅。** 改错了地方会白折腾。想改物品显示名要去改物品的自定义名（比如用改名插件），不是改这个插件的配置。

4. 如果全都没搜到语言相关文件，**说明消息很可能是硬编码在 jar 里**，那就没法靠配置汉化了

想看全站各插件的汉化情况，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
