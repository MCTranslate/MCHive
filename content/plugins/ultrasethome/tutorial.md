## ⚠️ 先看这里：版本已经滞后

**注册表记录的 MC 上限是 1.20.1。** 这个数字不是随便来的——它反映的是**插件实际更新的位置，不是当前 MC 版本**。

| 时间点 | 情况 |
|--------|------|
| 最后一次更新 | 2024 年 3 月 |
| 覆盖到的 MC | 1.20.2 一档 |
| 之后的 MC 版本 | **未适配** |

**这意味着什么：**

- 你在 1.21+ 上装它 → **能不能跑起来完全没保证**
- 就算装上，可能出现的是「进服正常、传送正常、某些场景静默失效」这类难查的问题，而不是干脆报错的清爽失败
- MC 的物品、数据版本、世界格式一直在动，**「没报错」不等于「没问题」**

**如果你要长期运营一个服**，这个插件需要谨慎评估：

- MC 版本正好在 1.16 - 1.20.1 → 可以用
- 需要 1.21+ → **先在测试服验证，别直接上生产**
- 追求长期可维护 → 看看有没有更新的替代，或做好未来要换的心理准备

**装之前必做：在目标 MC 版本上完整测一遍。** 测的不是一个「能不能进服」，是：设家 → GUI 打开 → 传送 → 跨世界传送 → 权限限制生效 → 数据库写入。这六步都过了才算能用。

## UltraSetHome 安装教程

### 1. 它做什么

传送点插件，但重点不在「有几个家」，而在**家能被当成一个可管理的东西**：

| 功能 | 说明 |
|------|------|
| 多家园 | 每个家独立命名 |
| GUI 面板 | 打开界面看所有家，左键传送、右键进设置 |
| **独立图标** | 每个家可以设一个物品做图标，视觉上一眼分清哪个是哪个 |
| 主家园 | 指定一个家，`/home` 不带参数就回这里 |
| GUI 里改 | 改位置、设主家、删除、换图标，都能在界面里点出来 |
| 命令可配 | 命令名可以改 |
| 数量上限可配 | 基础上限 + 按权限加额度 |
| 传送反馈 | 音效 + 粒子 |
| 传送延迟 / 冷却 | 冷却可被权限绕过 |
| 导入 Essentials | 一键导入 EssentialsX 的家 |

**「独立图标」是它和普通传送点插件的差别。** 普通插件给你一个列表，它给你一排图标——玩家记的是「煤矿那个家」「农场那个家」，不是「第三个家」。这个设计在多家园场景里差别很大。

### 2. 安装

- SpigotMC 资源页搜 `Ultra SetHome`（作者 Cerexus）
- 丢进 `plugins/`，重启，生成配置目录

**⚠️ 重要：需要 UUID 模式的服务器。** 插件明确写了**不适合离线模式 / 破解服**。它按 UUID 存数据，玩家改名或重进就对不上。**如果你在开盗版服，别用。**

### 3. 权限系统

它的权限设计是**可堆叠的家园额度**——不是简单的「有 / 没有」：

| 节点 | 效果 |
|------|------|
| `ultrasethome.use` | 允许用这些命令（**基础节点，所有人要有**） |
| `ultrasethome.limit.5` | 允许创建 5 个家 |
| `ultrasethome.limit.*` | 允许配置里定义的家园数量（默认上限） |
| `ultrasethome.cooldown.bypass` | 绕过传送冷却 |

**注意这里有个坑：开了权限系统之后，玩家「不能使用任何命令，直到你给他加了 `use`」。** 而且**光有 `use` 不够，还得给 limit 节点**——这意味着新玩家进来是没有任何家额度的，得手动给。

> **给所有玩家一个基础额度**（比如 `limit.3`），VIP 给更高的，管理员给 `limit.*`。别让新玩家进来一个家都建不了。

配置里可以**选择是否启用权限系统**。如果你想简单粗暴，可以关掉，纯靠配置文件里的全局上限。**但关掉就没法做差异化了**——这是两回事。

### 4. 常用命令

| 命令 | 说明 |
|------|------|
| `/sethome [名称]` | 在当前位置设家 |
| `/home [名称]` | 传送，不带名称回主家园 |
| `/removehome <名称>` | 删掉指定家 |
| `/homes` | 打开 GUI |
| `/homes [玩家]` | 管理员：看某玩家的家 |
| `/homes add/remove/set` | 管理员：给玩家加 / 减 / 设额度 |
| `/homes info` | 查额度用了多少、还能加多少 |
| `/ultrasethomereload` | 重载配置，不用重启 |
| `/importhomes essentials` | 从 EssentialsX 导入家园数据 |

`/ultrasethomereload` 不重启，这个很实用——改 GUI 文案、数量上限不用停服。

> 导入 EssentialsX 家园这条路存在，但**导入前先备份**。跨插件迁移的数据格式兼容不保证，尤其是 EssentialsX 那边有重名家的时候。

### 5. GUI 操作

打开 `/homes` 之后：

| 操作 | 结果 |
|------|------|
| 左键一个家 | 传送过去 |
| 右键一个家 | 打开设置界面 |

设置界面里能：改家的位置、设为主家、删除家、换图标。

**「换图标」是这个插件的特色功能**——给每个家配一个不同的物品，GUI 里一眼认出哪个是哪个，不用背名字。

### 6. 数据库

| 场景 | 用什么 |
|------|--------|
| 单服 | **SQLite**（默认，比 JSON / YAML 快） |
| 多服 | **MySQL** |

**⚠️ 群组服的关键操作：把配置里的 SQLite 关掉、MySQL 打开。** 不改的话各服数据不通，玩家在 A 服设的家在 B 服看不见。

**⚠️ 别把这个插件放进 BungeeCord 的插件目录。** 原文写得很直白：不要这么做。它是后端插件，放代理端没有意义。

**多服也别用 MySQL 在单服上。** 单服开 MySQL 只是白白多一个外部依赖，单机 SQLite 完全够。

### 7. WorldGuard 联动

它提供了两个 WorldGuard 旗标：

| 旗标 | 效果 |
|------|------|
| `ush-commands` | 玩家不能用这些命令 |
| `ush-create-homes` | 玩家不能建家、不能改家的位置 |

适合用在** spawn 点、战争区、匹配区域**——这些地方不该能建家，也不该能传送出去。

**注意 `ush-commands` 的杀伤力**：它拦的是**所有**家园命令，包括 `/home`（回家）。在战斗区域用这个，等于玩家在里面完全没法用这个插件。`ush-create-homes` 温和得多，通常你要的是这个。

### 8. 常见问题

**新玩家一个家都建不了**
权限系统开着，但只给了 `use` 没给 limit 节点。**两个都要给。**

**装了之后玩家说数据丢了**
检查是不是离线模式。**这插件要 UUID**，盗版服上数据本来就不可靠。

**多服之间家不同步**
SQLite 没换 MySQL。

**GUI 里的家名字改了不显示**
改完 `/ultrasethomereload`。

**图标乱了 / 认不出哪个家**
图标存在家园数据里。跨 EssentialsX 导入的家可能没有图标数据。

**在 1.21+ 上出问题**
见开头。**这是版本适配问题，不是你配错了。**

### 9. 关于汉化

**没有核实到官方中文语言文件机制。**

引导式排查：

1. 解压 jar 看 `resources/` 下有无语言资源目录
2. 启动后看 `plugins/UltraSetHome/` 下生成的文件，找语言相关文件
3. **它的「消息」和「GUI 信息」是分开的两套**，都标了可配置，翻配置目录时注意区分
4. 它的配置强调「所有消息和 GUI 信息可自定义、命令名可配置」——**所以即使没有语言文件机制，界面文本也是能改的**，只是要你自己写

> 这类以 GUI 为主的插件，文本通常分散在配置各处（消息一份、GUI 一份），**没有统一的语言文件**是很常见的情况。以你手上那份配置的注释为准。
