## ⚠️ 前置：Machines 是 Nova 的附属，不能单独装

**Machines 不装 Nova 就完全没有意义。** 它不是一个独立的机器插件，是 Nova 框架下的一个 addon。

```
Nova（框架，负责物品/方块/能量/资源包）
  └── Machines（机器内容：挖矿机、粉碎机、发电机……）
```

**安装顺序不能反：**

1. 先装 **Nova**，重启一次，让它生成配置
2. 再装 **Machines**，再重启

装了 Machines 没装 Nova 的表现是：**Machines 加载失败或者完全不出现任何机器方块。**

想了解 Nova 本身怎么装（尤其是资源包那部分），先看 [Nova 安装教程](#/plugin/nova)。

## 1. 它提供什么

Machines 提供的是**自动化设备**，核心是让玩家从「手动挖矿」升级到「机器生产」：

| 类别 | 例子 | 作用 |
|------|------|------|
| **采集** | 挖矿机、收割机 | 自动挖掘方块、收集掉落 |
| **加工** | 粉碎机、熔炉类 | 矿石 → 原料 |
| **发电** | 太阳能板、发电机 | 产生能量 |
| **储能** | 充电器、电池类 | 存电、给设备供电 |
| **传输** | 电缆、网络 | 把机器连成电网 |
| **农场** | 自动农场类 | 自动化种植收获 |

**核心机制是能量。** 机器不是免费的：

```
光源（太阳能/发电机）→ 电缆 → 机器
```

能量不够，机器就停机。这让 Nova 的玩法从「放个箱子就完事」变成「要规划产能」。

## 2. 通用上手流程

典型场景（三步）：

**Step 1 — 造电源**

太阳能在白天发电（晚上停，但可以提前存）。有 addon 也可能提供其他发电方式。

**Step 2 — 用电缆把电送到设备**

电缆是能量传输的唯一方式。**没连上 = 机器完全不工作**，这是最常见的「装了没反应」原因。

**Step 3 — 放机器，填材料**

机器 GUI 里通常有输入槽和输出槽。**放错槽位它就是不工作。**

**石头生成器这类流体机器**：需要水 + 岩浆，GUI 里能看到输入和输出状态。

## 3. 常用命令

Machines 的大部分功能通过 Nova 的命令访问：

| 命令 | 说明 |
|------|------|
| `/nova items` | **列出 Nova 和所有 addon 的全部物品 —— 想知道 Machines 提供了什么就跑这个** |
| `/nova give <物品>` | 给自己发机器 |
| `/nova addons` | 确认 Machines 是否被 Nova 识别为已加载 |
| `/nova reload` | 重载 |
| `/nvrecipe` | 查看手上机器的配方 |
| `/nvusage` | 查看手上机器的用途 |

> **`/nova addons` 是排错第一步。** Machines 装了但列表里没有它，就是没被识别。

## 4. 调试顺序：机器不工作

按这个顺序查，能覆盖绝大多数情况：

| 步骤 | 检查什么 |
|------|---------|
| 1 | `/nova addons` 里有 Machines 吗？**没有 = 没被识别** |
| 2 | 玩家下载资源包了吗？**没下载 = 紫黑块，放下去也不工作** |
| 3 | **能量够吗？** 有电源和电缆连到这台机器吗 |
| 4 | GUI 里的输入槽有正确材料吗 |
| 5 | 机器朝向对不对（有些机器有正面/输入面） |
| 6 | 机器所在区块是否加载（离太远可能不 tick） |

**第 3 条是绝大多数情况的答案。** 「机器完全不动」九成是没通电。

## 5. 常见坑

**Machines 装了但没有任何机器**

Nova 没装，或者安装顺序错了。回到文头的顺序重来。

**`/nova items` 里看不到 Machines 的东西**

Machines 没被 Nova 加载。看控制台有没有 Machines 的加载报错——通常是 Nova 版本和 Machines 版本不匹配。

**机器是紫黑块**

**资源包问题。** Nova 的资源包没配好或者玩家没下载。见 [Nova 安装教程](#/plugin/nova) 的资源包部分。

**机器放下去了但不工作**

按上面第 4 节的顺序查。**先查能量。**

**机器 GUI 里东西放进去消失了**

输出槽满了 / 满了之后不再接收输入。这是设计行为，不是 bug——把输出取走。

**性能下降明显**

Nova 机器本身是 TileEntity，**大量机器 + 大量掉落物 = 压力**。用真空箱和存储单元自动收集，减少地面掉落物堆积。见 [性能调优](#/guide/performance-tuning)。

## 6. 缺点和取舍

| 缺点 | 说明 |
|------|------|
| **必须有 Nova** | 没有独立可用的路径 |
| **必须有资源包** | 玩家不下载就是紫黑块，比纯服务端插件更容易「看起来坏了」 |
| **要规划能量** | 机器多了要算产能，配错就是一堆停机的机器 |
| **版本耦合紧** | Nova 升级、Machines addon 升级要配套做 |
| **性能开销真实存在** | 大量 TileEntity 和自动化的掉落物处理是实打实的 tick 开销 |
| **单机化严重** | 多人服务器里机器区容易被抢、被拆，需要保护插件 |

**它的取舍很清楚：给玩家工业化的爽感，代价是一整套能量、资源包和性能管理的复杂度。**

## 7. 关于汉化

> ⚠️ **Machines 作为独立 addon，本站未核实到它自己的官方中文语言文件机制。**

但好消息是：**Nova 本体的汉化非常完整**（118 个语言文件，含简繁中文），**Machines 作为官方 addon 通常跟随 Nova 的语言**。装好后简体中文玩家看到的界面文案大多已经是中文。

机器的显示名、GUI 标题这类内容一般在 Nova 或 addon 的配置文件里，**不是通过 `.json` 语言文件**。想改：

1. 打开 `plugins/` 下 Nova 和 Machines 的目录
2. 搜配置文件里带 `name` / `display` / `title` 的条目
3. **具体键名以你手上版本的官方配置注释为准**

**不要照抄网上随便找的「Nova 汉化包」** —— 语言文件的键名跨版本会变，用错版本可能导致加载失败。详见 [Nova 汉化机制](#/plugin/nova/lang.md)。
