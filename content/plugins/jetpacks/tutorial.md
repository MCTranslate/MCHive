## 先装 Nova，这是硬前置

**Jetpacks 是 Nova 的附属插件，自己不完整。** 不装 Nova 直接丢 Jetpacks 的 jar，服务器会拒绝加载它。

正确顺序：

1. 装 [Nova](#/plugin/nova)（主框架）
2. 装 Jetpacks
3. 重启服务器

> 安装顺序无所谓，但**两个都必须在**。Nova 会负责加载它的附属插件。

**为什么这么设计**：Nova 本身是「物品 / 方块 / 能量 / 机器」这套科技框架的底座，喷气背包只是它上面的一类物品实现。脱离框架单独装，这个物品没有数据驱动、没有能量系统、没有机器体系，等于废的。

## 它给什么

**8 种喷气背包。** 每一种的定位不同——有的偏续航（飞得久），有的偏动力（飞得快），有的干脆是一次性冲刺。

它们共享同一套底层逻辑：**能量（燃料）→ 推进 → 空中机动**。所以 Jetpacks 的核心玩法不是「拿到一个背包就起飞」，而是**给它喂燃料、升级、改造**。8 种背包的差异主要体现在能量容量、推力、耗能速率这些数值维度上——具体每种背包的名称、参数和配方以官方配置文件和 Wiki 为准，本站不列具体键名。

飞行的手感是三个数共同决定的：

| 维度 | 影响 |
|------|------|
| 推力 | 起步和加速能力 |
| 耗能速率 | 同样的燃料能飞多久 |
| 能量上限 | 单次装多少燃料 |

调平衡时这三个要一起看。**只调推力不调耗能，玩家会觉得「飞一下就没油」，体验很差。**

## 适合什么样的服

| 服类型 | 建议 |
|--------|------|
| 科技/工业服 | **强烈推荐**，Nova 体系里喷气背包是最经典的入门科技树 |
| 探索/生存服 | 合适，能让跑图变快，但要注意别让玩家懒得走路 |
| 小型朋友服 | 先看看 Nova 那整套东西你装不装得起，Jetpacks 只是它的一小块 |
| 纯 PVP 服 | 谨慎。飞行能力会改变战斗平衡 |

**它不是独立玩法，是 Nova 玩法的一部分。** 如果你只想要「玩家能飞」，装 EssentialsX 的 `/fly` 权限就够了，犯不着拉 Nova 一整套进来。反过来，如果你已经决定要玩 Nova 科技树，Jetpacks 基本是必装的。

## 安装

官方仓库：<https://github.com/xenondevs/Jetpacks>

- 主框架 Nova 另装，仓库在 `xenondevs` 组织下
- 两个 jar 从对应版本的 Release 页拿
- 丢进 `plugins/`，重启

启动后控制台会输出 Nova 加载附属的日志。**没看到 Jetpacks 相关的行，就说明它没被加载**——先去查 Nova 是否在运行。

## 配置要点

配置的具体文件位置、每个背包的键名、能量/配方设置，**都以你版本的官方配置文件注释为准**。这个插件的配置跟着 Nova 的版本走，Nova 一升级 Jetpacks 的配置结构也可能跟着变。

能明确说的只有一件事：**它依赖 Nova 的能量（燃料）系统。** 也就是说 Jetpacks 能用的一切，前提是 Nova 那边有可用的燃料和能量方块/机器。Nova 的机器不装，喷气背包就是个大号的摆设。

## 常见坑

**Jetpacks 不加载**
九成是 Nova 没装或没先启动。确认 Nova 正常加载，重启服务器而不是 `/reload`。

**能飞但飞两下就没能量**
能量系统没接上，或者背包本身能量上限太低。前者查 Nova 的机器配置，后者查 Jetpacks 的背包参数。

**爆炸/卡顿**
这是 Forge 系（Nova 是平台）的典型表现。检查服务端核心类型和 Java 版本是否匹配——**Nova 这类科技插件对 Java 版本和服务端核心的要求比普通插件严格得多**。

**和其他飞行插件打架**
装了 EssentialsX `/fly`、或者别的飞行权限插件，叠加之后玩家能飞到不该飞的高度。**规则只能有一个来源**，这个必须自己规划，插件不管。

**升级 Nova 后 Jetpacks 炸了**
附属插件跟着主框架走。**Nova 升级前先备份整个 Jetpacks 配置目录**，这个习惯适用于所有 Nova 生态的插件。

## 关于汉化

**本站未核实到该插件的官方中文语言文件机制。** 若要汉化需自行确认。

Jetpacks 属于 Nova 生态的一部分，**它的文案大概率跟随 Nova 的语言机制**——如果 Nova 提供了语言文件，附属插件往往复用同一套。

排查顺序：

1. 先看 Nova 的配置目录里有没有语言文件（**Nova 部分是站内已有插件，可以先查 Nova 的说明**）
2. 再看 Jetpacks 自己的目录里生成了什么
3. 在生成的文件里搜 `lang`、`locale`、`message`、`translat`
4. 看有没有 `_zh_CN` 之类的中文变体

**物品名称和 GUI 标签往往直接写在配置文件里**，不是从语言文件读的——汉化时这两类要分开处理。键名以官方配置注释为准。

想搭一套覆盖全服插件的汉化方案，见 [插件汉化与本地化完全指南](#/guide/plugin-localization)。
