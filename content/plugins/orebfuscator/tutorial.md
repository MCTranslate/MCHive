## ⚠️ 先读这一段：这是个明确的取舍

Orebfuscator 做的事是：**给每个玩家单独生成一份「他看不见的方块被替换掉」的区块数据**。

这意味着：

- ✅ 玩家真的**看不到**矿脉，不是客户端插件那种「视觉上骗一下」
- ❌ **每个玩家的区块数据都不一样** —— 内存占用和带宽消耗成倍增加
- ❌ CPU 消耗明显，社区里有「资源翻倍」的实测反馈

**装之前先想清楚你的服是什么定位。**

| 服类型 | 建议 |
|--------|------|
| 生存服、公开注册、有付费玩家 | ✅ 值得装，矿脉被透视 = 直接影响付费体验 |
| 小朋友玩、朋友联机 | ❌ 没必要，X-Ray 客户端本来就少 |
| 建筑/创造服 | ❌ 装了反而碍事，玩家要看到方块 |
| 高配机器 + 玩家少 | ✅ 装得起，收益明显 |
| 低端小鸡 / 2G 内存机 | ❌ 别装，会拖垮 |

## 1. 它是怎么工作的

原理值得说清楚，因为**它决定了这个插件的能力上限**：

```
玩家请求区块
    │
    ├─ 对这个玩家来说：这些方块不可见（被墙体挡住、在视锥外、超过距离）
    │   → 保持原样发出去
    │
    └─ 对这个玩家来说：这些方块可见（如果他开了 X-Ray）
        → 替换成石头/空气等假方块再发
```

**它不改世界存档**，只改发给某个玩家的那一份网络数据。所以客户端拿到的区块包是「假」的，服务端存的还是真数据，换个玩家视角矿还在。

这一点比客户端 X-Ray 模组强的地方在于：**没有客户端要装任何东西**，普通玩家完全无感。

### 两种隐藏模式

| 模式 | 做什么 | 特点 |
|------|--------|------|
| **World obfuscation** | 隐藏所有目标方块（矿石、箱子等） | 简单有效，但**目标方块在客户端全都不存在** |
| **Proximity hider** | 按距离动态决定显示哪些 | 玩家靠近时矿会「出现」，看起来自然，但**吃更多 CPU 和包体积** |

**World obfuscation 优先级更高。** 两个都开时 world 设置优先——因为你不想让「靠近了矿还是隐形」这种玩法出现。

Proximity 的好处是**视觉上自然**：玩家走近时矿脉逐渐显现，不会觉得「这服务器矿脉是隐形的」。代价是每一步都要算距离。

## 2. 硬依赖：ProtocolLib

```
Java 17+
Spigot / Paper / Folia 或其分支（1.16+，1.9.4+ 用 legacy 版）
ProtocolLib 5.2.0 或更高
```

Orebfuscator 的工作完全建立在拦截区块发包上，**没有 ProtocolLib 它什么都做不了**。

- [ProtocolLib](https://www.spigotmc.org/resources/protocollib.1997/)

**顺序**：ProtocolLib 先装 → 重启 → Orebfuscator → 重启。

> ⚠️ **ProtocolLib 版本不匹配是最常见的翻车原因。** 新版 MC 上老 ProtocolLib 会报不兼容。装之前确认 ProtocolLib 支持你的 MC 版本。

## 3. 安装

- SpigotMC：<https://www.spigotmc.org/resources/orebfuscator.82710/>
- 源码：<https://github.com/Imprex-Development/Orebfuscator>

步骤：装 ProtocolLib → 重启 → 装 Orebfuscator → 重启 → 改配置 → 再重启（配置只能在停服时改）。

## 4. 配置怎么改

配置文件是 `plugins/Orebfuscator/config.yml`。**停服状态下改，改完再启。**

主要就两块——**世界设置**和**隐藏方块清单**。典型形态（**以你版本的配置注释为准**）：

```yaml
worlds:
  world:
    world:
      # 隐藏目标方块
      hidden-blocks:
        - DIAMOND_ORE
        - GOLD_ORE
        - IRON_ORE
      # 替代成什么
      replacement-blocks:
        - STONE
    proximity:
      # 玩家靠近时显示的距离
      hidden-block-distance: 8
      replace-blocks:
        - STONE
```

**关键在于 `hidden-blocks` 清单要和你服的实际产出对齐。** 这是最容易漏的地方：

| 症状 | 原因 |
|------|------|
| 装了还是能透视钻石 | 你的自定义矿（GoldFactory 之类）没加进 `hidden-blocks` |
| 箱子透视 | 箱子属于 **Block Entity**，要单独配，清单和方块不同 |
| 刷怪笼被透视 | 同上，Block Entity |
| 活塞/掉落物透视 | **这个插件管不了**，见下面的能力边界 |

## 5. 能力边界（重要）

**Orebfuscator 只隐藏静态方块。它藏不住这些东西：**

| 藏不住 | 说明 |
|--------|------|
| 玩家和其他生物 | 实体不走区块包，是单独的实体包 |
| 掉落物物品 | 同上 |
| 盔甲架、画、物品框、矿车、船 | 实体 |
| 流动的岩浆/水 | 服务端持续更新的方块状态包 |

**结论：它不是「防作弊」，只防 X-Ray 静态透视。** 想要更全面的隐藏（比如射线式隐藏实体），那是另一类插件（Raytrace 类），且**两者不是同一个东西，别指望叠加**。

### 会被现代客户端绕过一部分

X-Ray 客户端不是静态的。它们会：

- **逐步挖掘** —— 每次挖一小块，像真人一样靠近
- **长距离追踪矿脉走向** —— 因为世界生成是确定性的，从已知矿脉可以推算远处有没有
- **混合采集** —— 混入大量无意义的方块，稀释观察

Orebfuscator 的 proximity 模式能缓解第一类，第二三类**解决不了**——它们是游戏生成机制层面的信息，不是区块隐藏能覆盖的。

**所以：Orebfuscator 是提高透视门槛，不是杜绝透视。** 期望值放对。

## 6. 性能到底吃掉多少

这必须说实话，因为它是最主要的缺点：

| 因素 | 影响 |
|------|------|
| 每玩家独立区块数据 | **内存占用随在线人数线性增长** |
| proximity 模式每 tick 算距离 | **CPU 开销明显**，是最贵的一项 |
| 替换方块后的区块包更大 | 带宽上升 |
| 缓存 | 它有两级缓存，能省很多重复计算 |

**省资源的三个方向**：

1. **关掉 proximity** —— 省下大部分 CPU，代价是玩家会觉得矿脉隐形不自然
2. **缩小 `hidden-blocks` 清单** —— 只藏真正值钱的（钻石矿、绿宝石），不藏煤炭铁矿
3. **限制隐藏方块的距离** —— 不用给每个玩家算整张地图

社区里有实测反馈说「资源翻倍」，也有作者和付费配置的优化方案说「minimal overhead」。**差距来自你的配置粒度**——全藏 + proximity 确实是最贵的组合。

> **判断标准**：装之前记一下 `/mspt`，装满员之后再看一次。有差就是有差，别自我安慰。

## 7. 为什么不用 Paper 自带的 anti-xray

Paper 有内置的反透视（`anti-xray.enabled`），很多人会问为什么还要装这个。

| | Paper 内置 | Orebfuscator |
|---|-----------|-------------|
| 配置粒度 | 几个开关 | 每个世界、每种方块、两种模式都能调 |
| 缓存 | 无 | 两级缓存，重复区块不重算 |
| Proximity hider | 无 | 有 |
| Block Entity 隐藏 | 有限 | 能正确处理箱子/熔炉而不留在区块包里 |
| 运维复杂度 | 一个开关 | 一份大配置 |

**结论：只有矿石防透视需求的话，Paper 内置的够用。** Orebfuscator 的价值在于你要精细控制——比如「只藏钻石，别的照常显示，但箱子必须藏」。

**别两个都开。** 两套机制同时改区块包，会互相干扰到难以排查。

## 8. 常见坑

| 症状 | 处理 |
|------|------|
| **装了不加载** | ProtocolLib 没装或版本不兼容。看控制台最上面的异常 |
| **1.21.x 上不工作** | **ProtocolLib 版本不兼容**——最新版 Paper 上最常见的问题，先更新 ProtocolLib |
| **配置改了没生效** | **配置只能在服务器停止时改。** 必须完整停服 → 改 → 启动 |
| **玩家说矿看不见了** | proximity 距离设太远，或 `hidden-blocks` 里放了玩家本来该能看见的方块 |
| **和 WorldGuard / FAWE 出问题** | 做过世界编辑的区域，区块里可能残留不一致数据。换新版本会跳过 remapping，必要时重建那部分区块 |
| **内存飙升 / 服变卡** | 查 proximity 开了没、`hidden-blocks` 清单多长、在线人数多少。**先关 proximity 测** |

## 9. 版本支持策略（要知道）

作者明确说明这是**滚动支持窗口**：从 MC 27.x 开始只支持最近两个大版本，新大版本发布后最老的那个会在未来某个版本里被移除。**老版本可能还能跑，但不保证修 bug。**

**这意味着**：如果你卡在很老的 MC 版本上，未来会失去官方支持。跨大版本升级时优先更新 Orebfuscator。

另外 1.17 / 1.18 / 1.19 **不在常规测试矩阵里**（1.16.5 和 1.20+ 才测），出问题要自己排查。

## 10. 关于汉化

> ⚠️ **本站未核实到 Orebfuscator 的官方中文语言文件机制。**

Orebfuscator 几乎没有玩家可见的文案——它是纯服务端包处理插件，不发消息给玩家。**如果你看到玩家收到某个提示，那多半来自其他插件。**

想改东西的话直接编辑 `plugins/Orebfuscator/config.yml`（停服状态），里面是方块名和距离数值，没有需要翻译的文案。**具体可改的键名以你手上版本的配置注释为准。**
