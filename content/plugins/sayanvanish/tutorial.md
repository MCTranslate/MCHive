## SayanVanish 安装教程

### 1. 隐身不只是「看不见」

朴素实现的隐身只做一件事：不把玩家的实体包发给其他人。**问题是这样漏洞很大**：

| 泄漏途径 | 朴素实现 |
|---------|---------|
| Tab 列表 | 名字还在，别人看得到 |
| 玩家列表 / 服务器列表 | 人数统计还在，别人数得出来少了谁 |
| 命令参数 | `/tell Steve hi` 会漏给别人听 |
| 皮肤 | Tab 列表里的头还在 |

**SayanVanish 的思路是「模块化地逐项处理」**——每个模块负责抹掉一种泄漏途径。

**它的能力范围**：

| 能力 | 说明 |
|------|------|
| 实体隐身 | 别人看不到你的实体 |
| Tab 隐藏 | 从 Tab 列表移除 |
| **假消息**（fake_message） | 假装你还在线——发你的消息不会显示「XX 隐身中」，而是正常显示 |
| 跨服同步 | 多服环境下保持一致 |

> **「假消息」这个设计是它和普通隐身插件最大的区别。** 隐身的人发的聊天，在别人眼里就是他人在说话。这让抓作弊时更难被发现。

### 2. 支持的平台

| 平台 | 支持 |
|------|------|
| Bukkit / Spigot / Paper / Folia | ✅ |
| **Velocity** | ✅ |
| **BungeeCord / Waterfall** | ✅ |

**代理端支持是它的强项。** 群里服用 Velocity 或 Bungee 时，代理端装一份、后端各装一份，是标准做法。

### 3. 架构：api / bukkit / proxy 三层

源码分三个模块，这个结构说明它的设计意图：

| 模块 | 作用 |
|------|------|
| `sayanvanish-api` | 跨平台通用 API |
| `sayanvanish-bukkit` | Bukkit 侧实现 |
| `sayanvanish-proxy` | 代理端（Velocity / Bungee）实现 |

**API 模块是通用的**，写插件要集成的话用 `sayanvanish-api`。平台特定的 artifact ID 是 `sayanvanish-bukkit`、`sayanvanish-proxy-velocity` 这类。

### 4. 数据库：多服同步靠它

SayanVanish 的数据库层负责**多服务器之间同步隐身状态**。

支持的方式（从源码的数据库接口设计看）：

| 方式 | 说明 |
|------|------|
| **SQL** | MySQL 等 |
| **Redis** | 群组服常见 |

**只有单服的话不用配这些。** 多服环境下才需要统一数据库，否则一个玩家在 A 服隐身、切到 B 服还是显形。

**具体数据库配置项和键名以你手上版本的配置文件注释为准。**

## 5. 安装

**下载页（作者推荐 Hangar）**：

- Hangar：`hangar.papermc.io/syrent/sayanvanish` ← **推荐**
- Modrinth：搜 `sayanvanish`
- SpigotMC：<https://www.spigotmc.org/resources/sayanvanish-1-8-1-21-7.105992/>
- 文档：<https://docs.sayandev.org/sayanvanish>
- 源码：<https://github.com/Syrent/SayanVanish>

**代理端架构的装法**：

| 位置 | 装什么 |
|------|-------|
| Velocity / Bungee 代理端 | SayanVanish（proxy 版） |
| 每个后端服务器 | SayanVanish（bukkit 版） |

**版本要一致。** proxy 版和 bukkit 版混用不同版本，通信协议可能对不上。

## 6. 命令

| 命令 | 说明 |
|------|------|
| `/vanish` | 切换隐身状态（**常见别名：`/v`、`/vs`**） |

> ⚠️ **具体命令和权限节点以你版本的文档为准。** SayanVanish 的功能开关大量通过配置而不是命令，命令表本身很简短。

## 7. 功能开关：配置才是主战场

SayanVanish 的功能主要通过**功能（Feature）**配置启用。官方的 Feature 编写规则有两条限制，说明了它的设计约束：

| 规则 | 含义 |
|------|------|
| 所有参数必须有默认值 | 缺参数时不会崩 |
| 参数必须是基础类型（String / Integer / Boolean 等） | 复杂对象不好序列化 |

**这两条规则决定了功能配置的形态**：一个功能就是一串扁平的基础类型开关。

**具体有哪些功能项、每项的键名，请以你手上版本的配置文件注释为准。** 本站不写死键名——这类多模块插件的配置结构会随版本变化。

### 值得知道的两项

| 功能方向 | 说明 |
|---------|------|
| **fake_message** | 让别人以为你没隐身（更新日志提到它支持 legacy 格式） |
| **canSee 的一个坑** | 源码里有一个修复：「对未隐身用户永远返回 true」。这个细节说明 API 在隐身/可见性判断上绕过一个逻辑 |

> 那个 `canSee` 修复值得留意——它修的是「非隐身玩家被错误判定为看不见某玩家」的情况。如果你遇到「有人明明在线但别人看不到」的诡异 bug，升级到包含此修复的版本。

## 8. 怎么用它抓作弊

这是它的实际用途，也是它为什么值得装：

```
staff 隐身 → 潜行观察 → 看到有人开飞 / 透视 → 记下 → 直接叫 Security 封
```

**关键价值：被观察的玩家不知道自己被看着。** 这是所有反作弊插件都做不到的——反作弊是自动检测，但「现场抓获」只有隐身能做。

### 使用纪律

| 该做 | 不该做 |
|------|--------|
| 隐身抓完**立刻恢复** | 长时间隐身，Tab 人数对不上会引起怀疑 |
| 抓到了**立刻叫 Security** | 一个人蹲那看半天不走 |
| 隐身状态下**别用 /tell 交流** | 可能暴露 |
| 记得**关掉假消息**（如果不想让人以为你还在） | 保持伪装到不必要的时候 |

## 9. 常见坑

**装了之后自己也被隐身了**

`/vanish` 是切换不是单向开关。再敲一次恢复。

**代理端隐身了，后端还是显形**

| 检查 | 说明 |
|------|------|
| 代理端装了吗 | proxy 版要装在代理上 |
| 版本一致吗 | proxy 和 bukkit 版版本要对得上 |
| 数据库配了吗 | 多服必须共享数据库，否则状态不同步 |

**Tab 里还看得到名字**

对应功能没开。去看功能配置里 Tab 隐藏那项。

**别人发 /tell 给我，我的消息被别人听到了**

假消息 / 命令参数过滤没开，或者对方没开对应的「互相不可见」选项。

**Velocity 上用了之后 mobs 不攻击你了**

这是社区反馈过的一个老问题（VelocityVanish 相关）。**版本较老时可能出现**，升级到最新版；如果还在，就是它把实体交互也屏蔽了。

**升级后 API 不兼容**

源码里可见几次 API 调整（比如 Bukkit 事件里的用户和选项结构）。**依赖 SayanVanish API 的第三方插件需要跟着升级。**

## 10. 缺点和取舍

| 缺点 | 说明 |
|------|------|
| **配置体系复杂** | 功能模块多，配置项多，第一次配容易懵 |
| **功能主要靠配置而非命令** | 没有「一键隐身全开」的开关，全靠配置文件 |
| **多服要配数据库** | 单服简单，群组服是额外工作 |
| **API 还在演进** | 事件结构和参数有过调整，依赖它的插件要跟着适配 |
| **隐身状态下的边界问题** | mobs 攻击、载具、容器交互这些细节容易出意外 |
| **Tab 人数对不上会引起怀疑** | 用它需要纪律，不是装上就完 |

## 11. 关于汉化

> ⚠️ **本站未核实到 SayanVanish 的官方中文语言文件机制。**

它的玩家可见文本主要是命令反馈和隐身提示。想改：

1. 打开 `plugins/SayanVanish/` 的配置文件
2. 搜带 `message` 的段落（各功能模块的配置文件里可能有各自的提示文案）

**具体键名以你手上版本的官方配置文件注释为准。**
