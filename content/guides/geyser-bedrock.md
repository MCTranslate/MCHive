## 一、先想清楚：它解决什么，又带来什么

Java 版和基岩版是**两个不同的程序**——协议不同、存档格式不同、部分规则不同。基岩版客户端本来就进不了 Java 服务器，**Geyser 做的就是在中间做协议翻译**：对玩家说基岩协议，对服务器说 Java 协议，玩家端什么都不用装（手机、主机、Windows 版直接连）。

**但翻译只解决「连进来」，没解决「你是谁」**：基岩版没有 Java 账号，服务器没法用正版验证认他。所以还需要 **Floodgate**——它让基岩玩家用微软/Xbox 账号完成身份认证，无需 Java 账号。

| 插件 | 作用 | 缺了它会怎样 |
|------|------|--------------|
| **Geyser** | 协议翻译：让基岩客户端能连上 Java 服务端 | 基岩玩家根本连不上 |
| **Floodgate** | 给基岩玩家一套身份认证（免 Java 账号） | 基岩玩家连上后会被当成「没有 Java 账号的人」踢掉 |

> **最常见的误解**：「装了 Geyser 就能让手机玩家进服」——**不对**。只装 Geyser，基岩玩家在登录阶段就会被要求 Java 账号验证。**两个都要装。**

## 二、装之前先想清楚：代价是什么

跨平台互通不是白来的，这些差异要提前告知玩家：

| 差异 | 具体表现 |
|------|----------|
| **红石机制不同** | 基岩版红石规则与 Java 不同，依赖精确时序或半连接性的 Java 机器，基岩玩家看到的行为可能不一致甚至失效 |
| **战斗无攻击冷却** | 基岩版没有 Java 的攻击冷却条，PvP 服的平衡会被打破 |
| **Java 资源包不直接生效** | 基岩客户端需要转换过的 `.mcpack` 资源包，直接发 Java 的包没用 |
| **部分新内容表现不一致** | 新方块/实体在基岩端的显示与交互可能受限 |
| **反作弊可能误判** | 基岩玩家的移动与交互方式与 Java 不同，反作弊容易误踢 |

**建议装的场景**：朋友里有手机/主机玩家；公益服想扩大玩家面。
**不建议装的场景**：生电/技术服（机制差异会毁掉机器）；纯 Java 正版服（没有基岩玩家就没必要）。

## 四、手把手安装（单服：装在 Paper 上）

**第 1 步：装 Geyser + Floodgate**

两个 jar 都放进 `plugins/`，然后**重启服务器**（不是 reload）。首次启动会生成各自的配置目录。

**第 2 步：放行基岩版端口（UDP！）**

基岩版用的是 **UDP**，与 Java 版的 TCP 是两回事——这是新手最大的坑：

```bash
# Linux
sudo ufw allow 19132/udp
# Windows：在防火墙入站规则里放行 UDP 19132
```

> **最常见的失败原因就是这个**：基岩端口被当成 TCP 放行，或者只开了 25565 的 TCP 没开 19132 的 UDP。**两个端口、两种协议，都要开**：
> - `25565/TCP` —— Java 玩家
> - `19132/UDP` —— 基岩玩家

**第 3 步：改 Geyser 配置**

`plugins/Geyser/config.yml`（文件名随平台可能不同，以实际生成的为准）：

```yaml
bedrock:
  address: 0.0.0.0        # 监听地址，一般不动
  port: 19132             # 基岩玩家连接用的端口（官方默认值）

remote:
  address: auto           # auto = 自动指向本机的 Java 服务端
  port: auto              # auto = 自动读取 server.properties 的端口
  auth-type: floodgate    # 默认 online；用了 Floodgate 就改成 floodgate
```

**第 4 步：验证**

基岩版客户端 → 游戏 → 服务器 → 添加服务器：

- 地址：你的**公网 IP**（与 Java 玩家连的同一个）
- 端口：`19132`

能进世界 = 通了。控制台可以用 `/geyser connectiontest` 检查外网连通性。

## 五、与账号 / 权限 / 经济的配合

基岩玩家进来后的**名字默认带一个点前缀**（如 `Steve` 变成 `.Steve`），这是 Floodgate 故意的——防止基岩玩家占用 Java 玩家的名字。这条前缀可以在 `plugins/floodgate/config.yml` 的 `username-prefix` 里改，但**不建议删掉**：删掉后可能出现重名，权限与白名单都会乱。

| 事项 | 说明 |
|------|------|
| 权限 | LuckPerms 里给基岩玩家分组时，**名字要带点**（如 `.Steve`），或按「是否基岩玩家」用前缀判断 |
| 白名单 | `/whitelist add .Steve` 才能加上基岩玩家（注意那个点） |
| 经济 | 余额跟随玩家身份，与 Java 玩家同库；注意 `.` 前缀的名字 |
| 群组服 | Geyser 与 Floodgate 装在**代理（Velocity）**上；每个后端也要装 floodgate 并**共享同一个 key.pem**（代理生成后拷贝过去，否则登录会被拒） |

## 六、常见坑速查

| 症状 | 原因 |
|------|------|
| 基岩玩家连不上 | **UDP 19132 没放行**（最常见），或填成了 TCP |
| 能连上但立刻被踢 | `auth-type` 没改成 `floodgate`，或 Floodgate 没装 |
| 基岩玩家被要求 Java 账号 | 同上，Floodgate 没装或不工作 |
| 基岩玩家名字前有个点 | 这是 Floodgate 的默认前缀，**别删**（删了会与 Java 玩家重名） |
| 皮肤不显示 | Geyser 的皮肤服务有限流，等一会儿或重启 |
| 主机玩家（Xbox/PS/Switch）连不上 | 主机端需要 BedrockConnect 或 MCXboxBroadcast 一类方案才能加自定义服务器 |
| 基岩玩家移动被反作弊踢 | 反作弊未适配基岩版，按插件文档放行基岩玩家 |
| 启动时 Geyser 没加载 | 服务端版本不在 Geyser 支持范围内（当前官方支持表到 26.2） |

## 七、Java 玩家那边要不要做什么

**什么都不用做**：Java 玩家照常用 `IP:25565` 连接，与基岩玩家在同一个世界里玩。这是 Geyser 方案最大的好处——玩家端零成本。
