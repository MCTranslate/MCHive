## 一、先定位：到底卡在哪一层

「朋友连不上」有四层原因，从外往里逐层排查，不要瞎试：

| 层级 | 现象 | 怎么确认 |
|------|------|----------|
| ① 服务端没起来 | 自己用 `localhost` 也连不上 | 控制台有没有出现 `Done (x.xxxs)! For help, type "help"` |
| ② 端口/监听不对 | 自己 `localhost` 能连，局域网 IP 连不上 | `server.properties` 里 `server-ip` 与 `server-port` 的值 |
| ③ 防火墙拦了 | 局域网能连，外网连不上 | 路由器「端口映射」有没有配、系统防火墙有没有放行 |
| ④ 压根没有公网 IP | 映射配了也没用 | 路由器 WAN 口 IP 是不是运营商大内网地址（见第二节） |

> 判断顺序很重要：**先确认自己 `localhost` 能进**。服务端本身没起来的话，后面全都白折腾。

## 二、你有没有公网 IP？

这决定了你该走哪条路，两分钟就能判断：

1. 打开 <https://ip.sb> 或搜索「我的 IP」，记下**公网 IP**
2. 登录路由器管理页（通常是 `192.168.1.1` 或 `192.168.0.1`），看 WAN 口/外网口的 IP
3. 对比两个 IP：

| 情况 | 结论 | 走哪条路 |
|------|------|----------|
| 两个 IP **一致** | 你有公网 IP | 第三节：端口映射 |
| 两个 IP **不一致** | 运营商级 NAT（大内网） | 第四节：内网穿透 |
| 路由器 WAN 口是 `100.64.x.x` / `10.x.x.x` / `172.16~31.x.x` | 同上，运营商大内网 | 第四节：内网穿透 |

> 也可以直接打运营商客服问「能不能给公网 IP」，很多家宽服务报个理由就能开（部分需要光猫改桥接 + 路由器拨号）。

## 三、方案 A：有公网 IP —— 端口映射 + 放行防火墙

**第 1 步：固定服务器的局域网 IP**

在服务器所在机器上设一个静态内网 IP（如 `192.168.1.100`），否则重启后 IP 变了映射就失效。家用路由器里一般叫「DHCP 静态分配」或「IP/MAC 绑定」。

**第 2 步：在路由器上做端口映射**

各品牌叫法不同：**端口映射 / 端口转发 / 虚拟服务器 / NAT 转发**，参数填：

| 项目 | 填什么 |
|------|--------|
| 外部端口 | `25565`（= Minecraft Java 版默认端口） |
| 内部 IP | 服务器的局域网 IP（如 `192.168.1.100`） |
| 内部端口 | `25565` |
| 协议 | **TCP**（Java 版只走 TCP；基岩版另说） |

**第 3 步：放行系统防火墙**

```bash
# Linux（Ubuntu / Debian 系，用 ufw）
sudo ufw allow 25565/tcp

# Linux（CentOS / RHEL 系，用 firewalld）
sudo firewall-cmd --permanent --add-port=25565/tcp
sudo firewall-cmd --reload
```

Windows：控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP → `25565` → 允许连接。

> **云服务器（阿里云/腾讯云/AWS 等）还有一层「安全组」**，必须单独去控制台放行 25565/TCP。这是买云主机最常见的「防火墙都关了还是连不上」的原因。

**第 4 步：验证**

让外网的朋友（不是同一个 WiFi 的）用「你的公网IP:25565」直连试试。如果你自己在家，用手机流量开热点测也能模拟外网。

## 四、方案 B：没有公网 IP —— 内网穿透（frp）

内网穿透的思路是：租一台有公网 IP 的小服务器当「中转站」，把内网服务器的 25565 端口借它的端口露出去。

**当前版本：frp v0.71.0**（2026-08-14 发布），开源免费，下载页 <https://github.com/fatedier/frp/releases>。

> ⚠ **时效性提醒**：frp 新版**已经完全不使用 ini 配置文件**（官方仓库里 `frpc.ini` / `frps.ini` 都已移除），改为 **TOML**。网上大量教程还在教 `frpc.ini`，照抄会直接启动失败。下面给的是当前的真实写法。

**中转机（有公网 IP 的那台）上跑 `frps`**：

```toml
# frps.toml
bindAddr = "0.0.0.0"
bindPort = 7000

# 鉴权：两边 token 必须一致。千万不要留默认值或弱口令
auth.method = "token"
auth.token = "换成你自己的长随机字符串"

# 可选：强制 TLS 加密（生产环境建议开）
# transport.tls.force = true
```

**本地服务器上跑 `frpc`**：

```toml
# frpc.toml
serverAddr = "你的中转机公网IP"
serverPort = 7000

# 与 frps 完全一致
auth.method = "token"
auth.token = "换成你自己的长随机字符串"

[[proxies]]
name = "minecraft"
type = "tcp"
localIP = "127.0.0.1"
localPort = 25565
remotePort = 25565      # 玩家将来连「中转机IP:25565」
```

启动顺序：先在中转机起 `frps`，再在本地起 `frpc`。玩家连接「**中转机公网IP:25565**」。

**中转机防火墙同样要放行**（`7000` 给 frpc 连、`25565` 给玩家连）：

```bash
sudo ufw allow 7000/tcp
sudo ufw allow 25565/tcp
```

> **安全建议**：token 写进配置文件有泄露风险，frp 支持从文件读取——把 token 单独存一个文件（权限设 600），两份配置里改成 `auth.tokenSource.type = "file"` + `auth.tokenSource.file.path = "/etc/frp/token"`。

> **延迟提醒**：穿透的流量多绕一跳，延迟必然比直连高。中转机选**离玩家近**的地域，会明显改善手感。

## 五、server.properties 里与网络相关的真实键

迁机、换端口、排查连接问题时最常动这几个（下面是**官方默认值**）：

```properties
server-ip=                              # 留空 = 监听本机所有网卡。只有多网卡需要绑定时才填
server-port=25565                       # Java 版默认端口
enable-status=true                      # false 时服务器在列表里显示为「离线」，但仍能连（不是真正的防护）
network-compression-threshold=256       # 达到该字节数的数据包才压缩；-1 关闭压缩，0 全部压缩
max-players=20                          # 显示的最大人数（服务器列表用）
view-distance=10                        # 服务端视距（区块半径）
simulation-distance=10                  # 实体模拟距离（区块半径）
```

> `max-players` **不是硬性上限**：它只是列表里显示的数字与默认踢人阈值，权限插件或代理层可以绕过。别把它当防挤服手段。

**关于 RCon（远程控制台）**——这是**最容易被当成后门**的端口：

```properties
enable-rcon=false        # 默认关闭，用不到就别开
rcon.port=25575
rcon.password=           # 默认空！开了 RCon 又没设密码，等于把服务器控制台送人
```

> **绝对不要把 25575 暴露到公网**。需要远程执行命令，请走 SSH 隧道或只在本地使用。

## 六、安全底线：把端口暴露出去之前

对外开放之前，请确认这三件事已经做完：

1. **正版验证开着**（`online-mode=true`，默认就是）——否则任何人都能顶着别人的名字进服。如果你的服务器必须离线运行，请务必配白名单与登录插件，见 [账号安全：正版验证、白名单与登录插件](#/guide/account-security)。
2. **管理类端口一律不对公网开放**：RCon（25575）、数据库（3306）、面板端口（如 8080/8443）、SSH（22，建议改端口 + 密钥登录）。
3. **做好备份**：端口一开，世界就暴露在公网了。至少按 [服务器日常运维手册](#/guide/server-maintenance) 里的备份体系配一套，并装上 [CoreProtect](#/plugin/coreprotect) 记录与回滚。

> 顺带说：公网 IP 一旦暴露，就会被扫描器盯上，这是**必然**而不是「运气不好」。所以别指望「没人会找到我的 IP」——要假设它一定会被扫到，然后按上面的清单做准备。

## 七、连不上 / 能连但卡 —— 速查表

| 症状 | 最可能的原因 |
|------|--------------|
| 自己 `localhost` 都连不上 | 服务端没起来 / 端口被别的程序占用（换个 `server-port` 试） |
| 局域网能连，外网不能 | 端口映射没配、映射到了错误的内部 IP、系统防火墙没放行 |
| 映射配了还是不通 | **云服务器没放安全组**；或**没有公网 IP**（运营商大内网） |
| 前几天好好的，突然都不通了 | 服务器内网 IP 变了（DHCP 重新分配）→ 映射失效；或公网 IP 变了（家宽多为动态 IP） |
| 能进服但过一会儿集体掉线 | 带宽被跑满（家宽上行通常很小）；或触发了运营商的封禁策略 |
| 延迟很高、总掉线 | 内网穿透中转机距离太远；或中转机带宽/线路质量差 |
| 报 `You are not whitelisted on this server!` | 白名单开着但玩家不在名单里（附：**Java 版 26.3 起白名单默认开启**） |
| 只有某些玩家进不来 | 他们客户端版本不匹配 → 看 [客户端版本兼容策略](#/guide/version-compat) |
