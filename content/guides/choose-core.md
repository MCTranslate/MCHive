# 核心怎么选：决策树版

> 本教程更新于 2026 年 9 月，适用 Paper 26.x（向下兼容 1.21.x）。

> 核心一句话解释：**核心 = Minecraft 服务端大脑**，决定了服务器能用什么插件、能跑多少玩家、能和哪些版本客户端连通。选错了核心 = 推倒重来。

网上的核心选择教程喜欢把 Paper、Purpur、Pufferfish、Folia、Leaves、Mili 全部列出来讲一遍特性，看完你还是不知道选哪个。**本站换个思路：先说你的需求，直接给答案。**

---

## 10 秒决策版（先定位你自己）

> 想都不想，直接选 **Paper 26.x**。90% 的插件服，Paper 都是最优解。往下看只是为了确认你是不是那特殊的 10%。

如果你需要更多的判断依据，请使用下面的决策树：

```
你的服务器是什么玩法？
│
├─ 原版生存服 / RPG 服务器 / 小游戏（起床、空岛）
│   └─ 选 【Paper 26.x】⬅️ 就这个，不用纠结
│
├─ 超大型服（100+ 玩家同时在线）
│   ├─ 追求极致性能，能接受插件大幅不兼容 → 【Folia】
│   └─ 要性能又要插件兼容 → 【Pufferfish】
│
├─ 生电服 / 红石密集型（飞行器、 TNT 大炮、精密时序）
│   ├─ 必须 100% 原版行为兼容 → 【Leaves】或【Mili】
│   └─ 部分红石可用，更追求性能 → 【Paper】+ `redstone-implementation: ALTERNATE`
│
├─ 需要装 MOD（Forge/Fabric 模组）
│   ├─ 只要 MOD（无插件）→ 【Forge】或【Fabric】
│   ├─ 插件 + Forge MOD → 【Mohist】或【Arclight】
│   └─ 插件 + Fabric MOD → 【Cardboard】（⚠️ 不成熟）
│
└─ 我就是想折腾 / 尝鲜
    ├─ Folia + 兼容插件清单 → 详见下方「Folia」章节
    ├─ Mili（生电优化）
    ├─ Lophine（folia生电分支）
    └─ Arbor（Luminol社区）
```

## 核心逐一介绍（含详细注解）

### Paper — 通用首选 ✅

```
所属系：Bukkit 系列（插件系）
上游关系：Vanilla → CraftBukkit → Spigot → Paper
插件兼容性：★★★★★ 最好
性能表现：★★★★☆ 很好
原版行为：★★★☆☆ 做了部分简化（红石、实体 AI）
维护状态：Mojang 上游同步，更新最快
```

**为什么它是默认推荐：**

- Paper 是 PaperMC 团队维护的开源项目，**每推出稳定版后会极快速同步上游更新**。今天 Minecraft 发布了新版本，Paper 几天内就会出现对应构建。
- 拥有 Bukkit 系列**最大的插件生态**。几乎所有 Bukkit/Spigot 插件都能无障碍运行在 Paper 上。
- 默认配置已经做了大量优化：异步区块加载、实体激活范围控制、漏斗优化等，**新手不需要任何调整就能获得良好性能**。
- 配置文件丰富（`paper-global.yml`、`paper-world-defaults.yml`、`bukkit.yml`、`spigot.yml`），进阶玩家有充足调优空间。

**适用人群：** 90% 的服务器类型，尤其是生存服、RPG 服、小游戏服。

**何时不要选：** 100+ 人超大服、生电/红石极致还原服、MOD 混合服。

**下载地址：** https://papermc.io/downloads

### Pufferfish — Paper 的性能增强版

```
所属系：Bukkit 系列
上游关系：Paper → Pufferfish
插件兼容性：★★★★★ 和 Paper 完全兼容（它是 Paper  fork）
性能表现：★★★★★ 在 Paper 基础上进一步优化
原版行为：★★★☆☆ 同 Paper
维护状态：中等，社区维护
```

**它和 Paper 的关系：** Pufferfish 是 Paper 的一个「分支」（fork），它保留 Paper 的全部功能，并叠加了来自社区的性能补丁。你可以理解为「Paper + 性能增强包」。

**具体的额外优化项：**

| 优化项 | Paper 默认 | Pufferfish 增强 |
|--------|-----------|----------------|
| 区块生成 | 标准异步 | 更激进的异步分发 |
| 实体 AI | 标准优化 | 动态 AI tick rate（空闲实体降频） |
| 漏斗处理 | 标准冷却 | 聚合化漏斗事件 |
| 网络层 | Netty 默认 | 调优 Netty 缓冲区 |

**适用人群：** 50-200 人生存服、需要更高 TPS 但**不能更换核心生态**的情况。

**注意事项：** 某些极大尺度的优化可能会影响原版机制。如果你玩家依赖非常精确的实体行为，先测再决定。

**下载地址：** https://pufferfish.host/downloads

### Folia — 多线程革命的代价

```
所属系：Bukkit 系列（独立分支）
上游关系：Paper → Folia（PaperMC 官方实验性项目）
插件兼容性：★★☆☆☆ ⚠️ 大量插件不兼容
性能表现：★★★★★ 理论上界最高（区域多线程）
原版行为：★★★★☆ 部分机制被改写（区块 tick 模式完全重构）
维护状态：活跃但仍是实验性
```

**它到底是什么：** Folia 把世界划分成多个「区域」（region），每个区域可以在**不同线程**上独立 tick。这与传统服务端「所有世界内容都在一个主线程跑」的架构完全不同 —— 这也是 Paper/Pufferfish 性能上限的根源：**主线程单核无论如何优化都有天花板**。

**「破坏性」的来源：** 很多插件写的时候会假设「所有 tick 事件都在同一线程」，这在 Folia 上会引发**并发 bug**（数据竞争、未同步的状态读取）。因此：

- 读写全局状态的插件需要重写
- 使用 `Bukkit.getScheduler()` 跨服调度的插件可能产生竞态
- 操作非当前区域实体的 NMS 代码完全失效

**2022 年至今的兼容状态：**

| 插件类型 | 兼容情况 | 举例 |
|----------|---------|------|
| 权限插件 | ✅ 基本兼容 | LuckPerms、Vault |
| 经济插件 | ✅ 基本兼容 | EssentialsX Economy |
| 世界保护 | ✅ 基本兼容 | WorldGuard（8.0+ 已适配） |
| 多世界管理 | ⚠️ 部分兼容 | Multiverse 5.x 未适配 ❌ |
| 实体/怪物相关 | ❌ 大量不兼容 | MythicMobs、Boss |
| 跨服传送 | ❌ 基本不兼容 | BungeeCord 传送相关 |
| 地图渲染 | ❌ 不兼容 | Dynmap |
| NMS 相关 | ❌ 不兼容 | ProtocolLib、Citizens |

**何时选择 Folia：**

1. 你的服务器**物理玩家数**长期超过 80-100
2. 你愿意**精简插件列表**，只使用官方兼容的插件
3. 你有一台多核服务器（**Folia 的核心优势在 8 核+ 才能体现**）
4. 你能接受**实验性带来的不稳定性**（偶发 bug、配置反复调优）

**何时不选 Folia：**

- 小型服（30 人以内）→ 使用 Paper + 良好的配置就够了
- 生电红石服 → 区域化 tick 会改时序
- RPG 重度服 → 很多 NPC 插件还没适配

**下载地址：** https://papermc.io/downloads/folia

### Leaves — 原版兼容补丁

```
所属系：Bukkit 系列
上游关系：Paper → Leaves
插件兼容性：★★★★★ 同 Paper
性能表现：★★★★☆ 同 Paper
原版行为：★★★★★ 还原度最高（修复 Paper 红石/实体缺失）
维护状态：活跃，国内生电社区维护
```

**它和 Paper 的关系：** Leaves 的核心目标不是性能，而是**在 Paper 基础上还原更多原版行为**。国内生电玩家多将 Leaves 作为 Paper 的「平替」。

**修复的典型原版行为问题：**

| 原版机制 | Paper 的现状 | Leaves 的修复 |
|----------|-------------|--------------|
| 零刻农场 | 部分失效 | 修复（可选开关） |
| TNT 复制 | 部分失效 | 修复（按原版行为） |
| 飞行器 | 部分失效 | 修复（红石兼容模式） |
| 刷铁机效率 | 因实体 AI 优化而降低 | 修复（村民恐慌机制完整） |
| 珍珠炮时序 | 偶发偏移 | 更稳定的跨区块实体传输 |

**性能影响：** 开启较多原版修复选项后，**整体 TPS 大约会下降 5-15%**。这是生电圈公认的取舍：要么性能、要么机制。

**适用于：** 生电服务器（需要飞行器、珍珠炮、刷铁机、零刻农场）、对原版机械有高还原要求的玩家群体。

**不适用于：** 纯生存服、RPG 服、小游戏服。

**下载地址：** https://leavesmc.org/downloads/leaves

### Mili — 生电专用的性能体化方案 🌟

```
所属系：Bukkit 系列
上游关系：基于 Folia
插件兼容性：★★★☆☆ 专攻生电优化
性能表现：★★★★★ 针对性极致优化
原版行为：★★★★★ 兼容原版 + 性能增强
维护状态：活跃
```

**项目定位：** Mili 是国内生电圈的新兴高性能核心，重点解决「原版机制保真 + 高实体数性能」的矛盾。

**主要特性：**

- **Rust 原生加速**：将服务端中 CPU 密集的部分（如区块生成、NMS 反射）用 Rust 编写，调用效率远超纯 Java 实现
- **Carpet 协议兼容**：支持 Carpet Mod 的部分协议，让原版技术玩家能在服务端运行原版自动化测试
- **红石兼容修复**：完整保留零刻、飞行器、珍珠炮、TNT 复制等，**并保持高性能**

**适用人群：** 生电技术服、需要高 TPS + 完美原版行为的大型服务器。

**与 Folia 的区别：** Folia 是通用多线程方案，Mili 是专攻生电场景的一体化方案。。

**下载地址：** https://github.com/xucy10/Mili/releases

> 📖 想更深入地了解 Mili？参见 Mili 项目官网（如有）或 GitHub 仓库 README。

### Purpur — Paper 的终极可玩性版

```
所属系：Bukkit 系列
上游关系：Paper → Pufferfish → Purpur
插件兼容性：★★★★★ 同 Paper
性能表现：★★★★☆（综合了 Paper + Pufferfish 的优化）
原版行为：★★★★★ 可配置性最强
维护状态：活跃
```

**核心定位：** Purpur = Paper + 所有社区配置项开关。它把大量「要不要开启」的争议机制做成了配置项，让你逐项选择，而非由核心作者决定。

**典型可配置项举例：**

```yaml
# purpur.yml 中的部分开关

# 末影龙行为
world-settings:
  default:
    entities:
      ender-dragon:
        always-drop-full-exp: true        # 击杀龙必掉完整经验
        towers:
          crystals:
            remove: false                 # 是否移除黑曜石柱上的末影水晶
        
      villager:
        breaded-breeding: true            # 村民只需面包就能繁殖
        lobotomize:
          enabled: false                  # 村民高负载时降低 AI（开则更省 CPU）
          wait-until-trade-locked: true   # 完成第一次交易后才启用 lobotomy
        
      player:
        idle-timeout:
          kick-if-idle: true              # 闲置玩家踢出
          kick-after-minutes: 15          # 闲置时长（分钟）
        
      iron-golem:
        spawn-rate: 1                     # 刷铁机率
        player-crafted-golems: true       # 是否允许玩家手搓铁傀儡
        
      turtle:
        breed-cooldown: 6000              # 海龟繁殖冷却（tick）
```

**适用于：** 希望极致可配置服主（不用改源码，只用改配置就能微调大量原版行为）。

**不适用于：** 新手（选项太多反而晕）；性能优先（与 Paper 上限量级相同）。

**下载地址：** https://purpurmc.org/downloads

### 混合 MOD 核心（等你玩腻了再说）

如果你的服务器需要同时运行**插件 + MOD**，你需要用「混合核心」。这类核心本质上是在 Forge/Fabric 之上加载一个 Bukkit API 兼容层。

| 混合核心 | 支持 MOD 类型 | 支持插件类型 | 现状 |
|----------|-------------|-------------|------|
| Mohist | Forge 系 | Bukkit 部分 | 维护中，兼容性因版本而异 |
| Arclight | Forge / NeoForge | Bukkit | 较活跃，推荐新服尝试 |
| Cardboard | Fabric 系 | Bukkit | ⚠️ 非常不成熟，仅限实验 |
| Banner | Forge + Paper | 两者 | 新项目，观望中 |

**⚠️ 强烈不推荐新手使用混合核心**。原因：

> 插件兼容性 + MOD 兼容性 + 核心稳定性 = **三重风险**。任何一个环节出问题都会产生难以排查的诡异 bug（如 MOD 物品栏被打断、插件事件在混合核心里延迟生效、NBT 在不同 API 体系下序列化不一致等）。
>
> **能只用插件就不用混合方案。如果 MOD 是刚需，请先确定 MOD 列表 → 找支持该 MOD 列表的混合核心版本 → 从「单服 + 单插件」开始逐个加入测试。**

## 核心版本怎么挑

### Minecraft 2026 年新版本号规则

```
旧方案（2024-2025）：  1.21 / 1.21.4 / 1.21.7 ... 每个小版本可能是大改动
新方案（2026 起）：    26.1 / 26.2 / 26.3 ...   主版本号 = 年份，次版本号 = 年内序号
```

**具体对照表（2026 年 9 月现状）：**

| 版本 | 代号 | 主题特性 | 主流程度 |
|------|------|----------|----------|
| 26.3 | Wilderness Bound | 新生物群系 | ✅ 最新 |
| 26.2 | — | 性能优化 | ✅ 主流 |
| 26.1 | — | 基线版本 | ⚠️ 可用但已非主流 |
| 1.21.4 | — | 最终旧版号 | ✅ 生态最完整 |
| 1.20.4 | Trails & Tales | 1.20 最终 | ⚠️ 仍广泛使用（尤其 MOD） |

### 版本选择铁律（逐条附解释）

**铁律 1：跟随主流**

> 服务器版本 = 大部分玩家的客户端版本。

判断方法：

- 如果你要开**新服** → 选 26.x 最新版（当前 26.3）→ 玩家用官方启动器更新就能进
- 如果你已经有**老服**且玩家都在 1.21.x → **别急着升 26.x**。先确认你的插件全部兼容 26.x，再升级
- 如果你在做 **怀旧型服务器**（1.20.4 MOD 服）→ 留在 1.20.4，不要追主流版本

**铁律 2：插件适配看核心，不看版本号**

> 插件是否兼容取决于它用什么 API（Bukkit / Spigot / Paper），而不是 MC 版本号。

实例说明：

- **LuckPerms**：同时支持 1.14 ~ 26.x（全部版本），因为 LuckPerms 做了底层兼容层
- **EssentialsX**：1.13 ~ 26.x（非常广泛的兼容性）
- **某个小众插件**：可能只支持到 1.20.6 → 你需要去插件页面看「Supported Versions」

**铁律 3：别追最新**

> 核心和客户端更新当天就升是大忌。

时间线经验值：

| 更新类型 | 建议等待时间 | 原因 |
|----------|-------------|------|
| MC 小游戏补丁（如 26.2 → 26.3） | 1-2 周 | 插件需更新，反作弊需适配 |
| MC 主线版本（如 1.21 → 26.1） | 4-8 周 | 插件大改，配置格式可能变化 |
| 核心大版本重写 | 2-3 月 | 新 bug 多，配置结构可能重构 |

**最佳实践**：落后**一个小版本**最稳定。等前一批「小白鼠」测试完反馈后再跟。

## 下一步

已经选定核心了？→ 去 [15 分钟极速开服](#/guide/quick-start) 开始实际操作。

有多个候选？→ 在 **两个核心都安装测试服**，让朋友进去体验 TPS（`/tps`命令查看），选 TPS 更高且你用着顺手的那个。

**选定后不要频繁换核心**（服务端的核心切换 = 重建）。第一次选对最省时。
